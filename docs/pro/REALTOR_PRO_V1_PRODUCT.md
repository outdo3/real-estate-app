## 1. 한 줄 정의

**E-JIP Realtor Pro = 중개사의 매물관리 + 고객관리 + 자동매칭 + 고객 설명 업무도구.**

- 공개 매물 게시판(마켓플레이스)이 **아니다.** 중개사가 등록한 매물은 기본적으로 **본인만 보는 비공개 노트**다.
- 이집의 제품 흐름 `DATA → INTERPRETATION → COMPARISON → RECOMMENDATION → ACTION` 중, Pro는 중개사가 고객에게 **ACTION**(설명·제안·연락)을 수행하는 도구다. 이집 공공 데이터(단지 master, 실거래, 좌표, 학교)는 "설명 근거"로 쓰인다.
- 경쟁 매물 플랫폼을 복제하지 않는다(AGENTS.md Product identity).

## 2. 대상 사용자

| 단계 | 사용자 | V1 지원 |
|---|---|---|
| V1 | 개업/소속 공인중개사 개인(1인) | 지원 |
| V1 | 소규모 사무소(대표 1인이 사용) | 1인 계정으로 지원 |
| 이후 | 팀/사무소 대표(구성원 계정, 공유 매물·고객) | **보류** — 권한 모델 별도 설계 필요 |

## 3. 해결하려는 문제

| 현재 중개사 업무 | 문제 | Pro 제공 가치 |
|---|---|---|
| 매물을 수첩·엑셀·메신저에 흩어 기록 | 검색 불가, 가격 변경 추적 불가 | 비공개 매물 노트 + 단지 master 연결 |
| 고객 조건을 기억/메모에 의존 | 새 매물이 들어와도 누구에게 맞는지 놓침 | 구조화된 고객 조건 CRM |
| 매물↔고객 연결을 머릿속으로 | 누락·지연 | 결정적(deterministic) 자동매칭 + 이유 설명 |
| 고객 설명 자료를 매번 캡처·편집 | 시간 소모, 근거 부족 | 이집 실거래/입지 데이터가 들어간 브리핑 카드/웹 리포트 |
| 재연락·만기·입주일 관리 누락 | 기회 손실 | "오늘 해야 할 일" 대시보드 |

## 4. V1 우선순위

1. **비공개 매물 노트** (private listing notebook)
2. **고객 CRM** (구조화 조건 + 메모 분리)
3. **고객↔매물 매칭** (hard filter + 가중 soft preference, 이유 설명)
4. **고객 브리핑/공유** (모바일 카드 + 공유 링크 웹 리포트)
5. **Free vs Pro 한도** (가설 기반, 결제는 MVP 이후)

## 5. 핵심 화면: "오늘 해야 할 일" 대시보드 (B3)

허영 지표(총 매물 수, 조회수 그래프)보다 **행동 목록**을 우선한다. 각 카드는 탭 한 번으로 해당 작업 화면으로 이동한다.

| 섹션 | 조건(V1 정의) | 액션 |
|---|---|---|
| 신규 매물 | 최근 7일 내 등록한 본인 매물 | 매칭 고객 보기 |
| 고객과 매칭된 매물 | 최근 매칭 계산에서 `score ≥ 70` & 아직 `SEEN`/`DISMISSED` 아님 | 브리핑 만들기 / 무시 |
| 다시 연락할 고객 | `followup.dueAt ≤ 오늘(KST)` & 미완료 | 전화/문자 링크(`tel:`/`sms:`) · 완료 처리 |
| 가격 변경 매물 | 최근 7일 내 호가 변경 이력이 있는 매물 | 해당 매물을 원했던 고객 재매칭 |
| 계약/입주 일정 | 고객 입주희망일·매물 입주가능일이 14일 이내 | 일정 확인 |
| 만기 임박 | 매물 임차인 계약 만기가 60일 이내 | 소유자 연락 |
| 최근 브리핑 | 최근 7일 발송 브리핑 + 열람 여부 | 재공유 / 만료 |
| 미처리 상담 | 상태 `NEW` 고객 중 3일 이상 조치 없음 | 조건 입력 완료 |

- 날짜 판정은 모두 **KST 달력일**(기존 `src/lib/kst-day.ts` 규칙 재사용).
- 데이터가 없으면 빈 섹션을 숨기지 않고 "해당 없음"을 표시(0과 미조회를 혼동하지 않음).

## 6. 이집 공공 데이터와의 관계 (요약, 상세는 ARCHITECTURE §5)

- 매물은 단지를 **`ApartmentMaster.aptSeq`로 식별**한다. 이름만으로 재식별하지 않는다.
- 면적은 Unit Master `canonicalExclusiveArea`로 선택한다. `전용면적/3.3058`로 평형을 만들지 않는다.
- 지역 공개 상태(`src/lib/region/enablement.ts`)가 닫힌 지역은 공공 데이터 prefill을 제한한다.
- 중개사 비공개 데이터와 공공 데이터는 **다른 테이블·다른 권한**에 둔다. 비공개 데이터가 공개 화면(상세·지도·통계·리포트)에 섞이지 않는다.
- 매칭 점수는 **E-JIP Score V2 / 개인화 점수와 완전히 분리**된 별개 계산이다.

## 7. 비범위(V1에서 하지 않음)

공개 매물 마켓플레이스, 결제 연동(MVP), 팀/사무소 계정, 음성/STT, 생성형 AI 요약·추천, 카카오 API 자동 발송, 회계/정산, 조직 관리, 계약서 작성, 전자서명.

## 8. 성공 판단 (MVP 테스트 5~10명)

| 지표 | 목적 |
|---|---|
| 중개사 1인당 등록 매물/고객 수(7일) | 실제 업무 데이터 입력 여부 |
| 매칭 → 브리핑 생성 전환 | 매칭이 행동으로 이어지는가 |
| 브리핑 링크 열람률 | 고객 설명 도구로서 가치 |
| 대시보드 "할 일" 완료율 | 재방문 동기 |
| 정성 인터뷰: "엑셀/수첩을 대체했는가" | 핵심 가설 검증 |

지표 수집은 기존 1st-party analytics allowlist(`src/lib/analytics/events.ts`)에 이벤트 이름만 추가하는 방식으로 하며, **개인정보(고객명·연락처·매물 호수)는 이벤트에 싣지 않는다.**

## 9. 핵심 리스크

| 리스크 | 대응 |
|---|---|
| 고객·소유자 개인정보 처리 (개인정보보호법) | 데이터 분류·최소 수집·보존기한·감사로그 설계(ARCHITECTURE §7). **법률 검토 필수** |
| 출입 비밀번호 등 민감정보 저장 유혹 | 필드 자체를 두지 않음 + 입력 경고 UI |
| 중개사 자격 사칭 | 수동 검수 기반 인증 상태 모델(ARCHITECTURE §3) |
| 공공 데이터 품질 오해(없음 vs 조회 실패) | 기존 data truth 상태(missing/unavailable/error) 그대로 브리핑에 전달 |
| 가격 가설 오류 | 가격은 가설로만 두고 베타 인터뷰로 검증 |
