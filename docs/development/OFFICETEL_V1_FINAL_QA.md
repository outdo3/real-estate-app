## 4. 발견된 결함과 조치

### P1 — "거래 없음" 오표기 (수정 완료)

다중 동 단지의 상세가 **"매매 거래 없음"**이라고 표시했다. 이안해운대는 그 주소에
1,350건이 실재한다. 귀속 실패를 결측으로 위장하는 것이고, 데이터 진실성 원칙이
금지하는 형태다.

수정: 상태를 둘이 아니라 **셋**으로 가른다.

| 상태 | 화면 |
| --- | --- |
| `ATTRIBUTED` | 거래 목록 |
| `UNATTRIBUTED_AT_ADDRESS` | "이 주소의 거래를 동별로 구분할 수 없어 표시하지 않습니다." + 건수·사유 안내 |
| `NO_TRANSACTIONS` | "매매/전세/월세 거래 없음" (검증된 진짜 0) |

판정은 import 없는 순수 모듈 `src/lib/officetel/attribution.ts`가 하고, 회귀 10개로
고정했다. 추가 쿼리는 **연결 0건인 294개 master만** 낸다 — 거래가 있는 4,762개는
쿼리 수가 그대로다(실측: 109/2가 2243/435와 동일한 지연).

Production 실측:

> 이 지번에는 건물 5개 동이 등록되어 있습니다. 국토교통부 실거래 원천이 동을 구분해
> 제공하지 않아, 어느 동의 거래인지 확정할 수 없는 매매 680건 · 전월세 670건은
> 표시하지 않습니다. 다른 동의 거래를 이 동의 거래처럼 보여주지 않기 위한 조치입니다.

### P2 — 면적 표기 불일치 (수정 완료)

칩은 충돌 해소된 라벨(`전용 31.686㎡`)을, 거래행·요약은 원본 float(`전용 31.6862㎡`)를
찍어 **같은 면적이 두 개로 읽혔다.**

수정: 페이지 전체가 `getUniqueAreaLabels` 기반 **단일 라벨 맵**을 공유한다.
서로 다른 전용면적은 여전히 절대 합쳐지지 않고(43.0498과 43.05는 4자리 유지),
필터링은 원본 exact 값을 그대로 쓴다. 표기만 통일했다.

## 11. 남은 권고 (이번 범위 밖)

1. **다중 동 거래 귀속** — 6,395건을 되살리려면 동 단위 귀속 근거가 필요하다.
   원천에 동 정보가 없으므로 면적·층 조합 등 간접 근거를 써야 하고, 그건 추론이라
   별도 설계·승인이 필요하다. 현재의 "표시하지 않고 이유를 밝힌다"가 안전한 기본값이다.
2. **면적 칩 터치 타겟 36px** — 권고치 44px 미만. 이번 범위(빈 상태·면적 표기)에
   포함되지 않아 손대지 않았다.
3. **부속동 master 6건** — 식별자 변경이라 승인 사항.
4. **좌표 신뢰 티어 미보존** — 런타임 정밀도 라벨을 만들려면 schema 추가가 필요하다.
