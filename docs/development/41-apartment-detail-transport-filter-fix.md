## 1. 교통 데이터 생성 경로 재확인

`NeighborhoodInfoPanel.tsx`의 교통 카드: `<KakaoPlaces categories={['SW8']}
keywords={['KTX', '기차역']} limit={4}/>`. `KakaoPlaces.tsx` 내부에서
`SW8` 카테고리 검색(지하철)과 `'KTX'`/`'기차역'` 키워드 검색(카카오
`keywordSearch`, 이름에 해당 문자열이 "포함"되면 매칭되는 느슨한 검색)을
병렬로 돌려 거리순으로 병합한다. 기존 오탐 필터는
`EXCLUDED_NAME_SUBSTRINGS = ['아파트','빌라','화장실','맨션','타워']`
(장소명 부분일치)뿐이었고, "퀵서비스"/"폐역" 관련 필터는 이번 STEP
이전에는 없었다(재확인).

## 2. 원인 조사(Kakao Local REST API 실측, read-only, DB/코드 변경 없음)

`geocode-apt.ts`와 동일한 인증 헤더로 REST API를 직접 호출해 실제 응답의
`category_name` 필드를 확인했다.

**KTX특송퀵서비스 등 오탐 원인**: `'KTX'` 키워드 검색은 상호명에 "KTX"가
들어가기만 하면 잡히는 문자열 검색이라, 실제로는 철도와 무관한 업체가
다수 섞여 들어온다(부산역 인근 표본에서 확인):

| 결과 | `category_name` |
|---|---|
| KTX특송퀵서비스 | 교통,수송 > **운송 > 퀵서비스** |
| KTX특송 부산역점 | 교통,수송 > **운송** |
| KTX렌트카 | 서비스,산업 > 전문대행 > **렌터카** |
| KTX부동산(명륜아이파크1단지 인근) | 부동산 > 부동산서비스 > **부동산중개업** |
| 부산역(실제 KTX 정차역) | 교통,수송 > 기차,철도 > 기차역 > **KTX,SRT정차역** |

실제 역만 `category_name`에 **"기차,철도 > 기차역"** 경로를 갖고, 오탐은
전부 완전히 다른 분류 경로(운송/렌터카/부동산 등)를 가진다 — 이건 카카오가
매기는 공식 분류값이라 이름 추정이 아니다.

**신선대역/우암역(폐역) 노출 원인**: `'기차역'` 키워드 검색 결과 중 폐역이
된 역은 `category_name` 마지막 세그먼트에 카카오가 **명시적으로 "폐역"을
표기**한다:

| 결과 | `category_name` |
|---|---|
| 신선대역 (폐역) | 교통,수송 > 기차,철도 > 기차역 > **폐역** |
| 우암역 (폐역) | 교통,수송 > 기차,철도 > 기차역 > **폐역** |
| 부산진화물역(정상, 화물역) | 교통,수송 > 기차,철도 > 기차역 (폐역 표기 없음) |

`place_name`에도 "(폐역)"이 붙어 있긴 하지만, `category_name`의 상태값이
카카오의 공식·명시적 신호라 이걸 기준으로 삼았다.

## 3. FIX-1 — KTX 오탐 필터

`src/components/KakaoPlaces.tsx`에 일반 규칙을 추가했다(특정 상호
하드코딩 없음):

```ts
const isRailwayStation = (p: any): boolean =>
  (p.category_name || '').includes('기차,철도 > 기차역');
```

필터 체인에 다음을 추가:

```ts
.filter((p) => !(p.__keyword === 'KTX' || p.__keyword === '기차역') || isRailwayStation(p));
```

`'KTX'`/`'기차역'` 키워드로 찾은 결과에만 적용되고, `SW8` 카테고리
검색(지하철) 결과나 다른 카드(병원/공원/대형마트/편의점/약국/
어린이집·유치원)는 `__keyword`가 이 두 값이 아니므로 이 조건과 무관하게
그대로 통과한다.

## 4. FIX-2 — 폐역 필터

```ts
const isClosedStation = (p: any): boolean => (p.category_name || '').includes('폐역');
```

필터 체인에 `.filter((p) => !isClosedStation(p))`를 **모든 검색 경로
(카테고리+키워드) 공통**으로 추가했다 — `SW8` 카테고리 결과에는 애초에
폐역이 나온 적이 없었지만(실측 5개 단지 전부 정상 역만 반환), 카테고리
검색에서도 이론적으로 나올 가능성을 배제하지 않기 위해 방어적으로
공통 적용했다. 운행 중인 역을 이름만 보고 추정으로 제거하는 로직은
전혀 없다 — 카카오의 명시적 상태 표기(`category_name`에 "폐역")만 근거.
