# STEP 1.5-A — 학군 데이터 신뢰성 정비

작성일: 2026-08-12

## 발견된 문제

STEP 1 정밀진단(`01-current-system-audit.md`, H섹션)에서 `/school` 페이지의 "평균 특목고 진학률"이 학교명 문자열 해시로 만든 임의 수치이며, "(시 평균 상회)"라는 평가 문구까지 함께 실제 통계처럼 노출되고 있다는 문제가 발견됐다.

이번 STEP 1.5-A 작업 중 원인을 추적하는 과정에서, 동일한 방식(학교명 해시 시드)으로 만들어진 훨씬 더 넓은 범위의 가짜 데이터가 `/school` 페이지의 핵심 기능인 "학교 랭킹" 목록 전체에 걸쳐 있다는 사실이 추가로 확인됐다(아래 "추가 발견" 참고). 두 문제 모두 이번 작업에서 함께 수정했다 — 후자는 STEP 1 audit이 특정하지 못했던 사각지대였고, 성격이 완전히 동일한 문제(학교명 해시 → 가짜 통계처럼 표시)였기 때문이다.

## 원인

1. **`src/app/api/school/stats/route.ts`** — `/school` 상단 요약카드용 API. 중학교마다 `SCHUL_NM`(학교명) 문자열의 char code 합을 구해 `nameHash % 50 / 10 + nameHash % 5` 공식으로 "특목고 진학률"을 지어내고, 지역 내 평균을 계산해 `specRate`로 반환하고 있었다.
2. **`src/app/school/school-client.tsx`** — 위 `specRate` 값을 "평균 특목고 진학률 {specRate} (시 평균 상회)"로 그대로 렌더링. "(시 평균 상회)" 문구는 코드 어디에도 "시 평균"과 비교하는 로직이 없이 고정 텍스트로 하드코딩되어 있었다.
3. **`src/app/api/school/route.ts`** — `/school` 학교 랭킹 목록 API. 학교명 해시로 만든 `seed1`/`seed2` 시드값으로 **학생수, 학급당 인원, 졸업생수, 학업성취도, 특목·자사고 진학 인원/비율, 통학시간, 건널목 개수, 4년제 진학률, 주요대·의약계열 진학률**까지 사실상 화면에 보이는 모든 수치를 생성하고 있었다(학교명·학교코드 제외). 랭킹 정렬(`mapped.sort`)도 이 가짜 수치(`specialRatio`, `univRate`) 기준이었다.
4. 같은 파일에서 NEIS API 호출이 완전히 실패하는 경우, 실존 여부가 불확실한 하드코딩 학교 7곳(대신중학교, 경남중학교 등)을 마치 실제 조회 결과처럼 반환하는 fallback도 있었다.

## 수정 전 동작

- `/school` 요약카드: "평균 특목고 진학률 4.8% (시 평균 상회)"처럼 근거 없는 수치+평가문구가 항상 표시됨.
- `/school` 랭킹 패널: "🏆 {지역} {탭} 랭킹" 제목 아래 "특목고 진학률 순"/"과밀학급·선호도 순"/"진학률 순"이라는 부제와 함께, 각 학교마다 학업성취도(%)·특목고 진학 인원/비율·학생수(초등은 학급당 인원·통학시간·건널목 개수, 고등은 4년제 진학률·의약계열 진학률)가 모두 정확한 통계처럼 표시되고, 그 가짜 수치 기준으로 순위(rank)까지 매겨져 있었음.
- NEIS 호출 완전 실패 시: 실제 조회 결과가 아닌 하드코딩된 학교 7곳이 화면에 그대로 노출됨.

## 수정 내용

### `src/app/api/school/stats/route.ts`
- 학교명 해시 기반 `totalSpecRate`/`specRateCount`/`avgSpecRate` 계산 로직을 전부 제거.
- `specRate`는 항상 `null`을 반환하도록 변경(실제 데이터 소스가 없다는 사실을 명시적으로 드러냄). `elemCount`/`midCount`/`highCount`/`totalSchools`(NEIS 실집계)와 `academyCount`/`academyLocation`(카카오 실집계)은 원래부터 실제 데이터였으므로 그대로 유지.

### `src/app/school/school-client.tsx`
- `stats` 상태의 `specRate` 초기값을 `'0.0%'`(0%로 오인될 수 있는 값)에서 `null`로 변경.
- 요약카드: `specRate`가 있을 때만 값을 표시하고, 없으면(현재는 항상 없음) "데이터 준비 중"으로 표시. "(시 평균 상회)" 문구는 완전히 제거(근거 있는 비교 로직이 코드에 없었으므로).
- 랭킹 패널 제목을 "🏆 {지역} {탭} 랭킹" → "🏫 {지역} {탭} 학교 목록"으로 변경, 부제를 "진학률 순" 등 가짜 기준 문구에서 "가나다순"(실제 정렬 기준)으로 변경.
- `renderSchoolItem()`을 재작성해 학생수/학업성취도/특목고 진학률/통학시간/건널목 개수/4년제 진학률/의약계열 진학률 등 근거 없는 수치를 전부 제거하고 "데이터 준비 중"으로 대체. 고등학교의 "유형"(자율고/일반고)만 NEIS 실제 필드(`HS_GNRL_BUSNS_SC_NM`)가 있을 때만 표시하고, 없으면 임의 추측 대신 "정보 없음"으로 표시.
- 학교 목록이 비어 있을 때(예: NEIS 호출 실패) "학교 정보를 불러오지 못했습니다." 안내 문구를 추가(과거에는 이 상황에서 가짜 학교가 채워졌음).

### `src/app/api/school/route.ts`
- 학교명 해시 기반 `seed1`/`seed2`로 만들어지던 모든 필드(students, graduates, classStudents, achievement, specialHigh, sciHigh, foreignHigh, specialRatio, walkTime, crossRoad, univRate, medSeoulRate)를 제거. 응답에는 실제 근거가 있는 필드(`id`, `name`, 고등학교의 `schoolType`)만 남김.
- NEIS 호출이 완전히 실패했을 때 실제 조회 결과처럼 보여주던 하드코딩 학교 7곳(대신중학교 등) fallback 배열을 제거 — 실패 시 빈 목록을 그대로 반환.
- 가짜 수치 기준 정렬(`specialRatio`/`univRate` 내림차순)을 제거하고, 실제 근거가 있는 기준인 학교명 가나다순 정렬로 교체.

### `src/app/school/school.module.css`
- 기존 "데이터 준비 중" 표시 관례(`src/app/school/[id]/school-detail.module.css`의 `.dataPending`)와 동일한 `.dataPending { color: var(--text-muted); }` 클래스를 추가(신규 디자인 아님, 기존 관례 재사용).

### `src/components/SchoolDistrictPanel.tsx`
- 이 컴포넌트는 이미 STEP 1.5-A 이전부터 같은 문제를 인지하고 "특목고 진학률 데이터 준비 중"으로 정직하게 처리하고 있었다(아파트 상세페이지 학군 탭). 다만 주석이 "가짜 수치가 여전히 다른 곳에 남아있다"는 전제로 쓰여 있어, 이번 수정 후 상황(모든 경로에서 동일하게 정비됨)에 맞게 주석만 갱신했다. 동작(로직)은 변경하지 않음.

## 실제 런타임 검증 결과

typecheck/lint/build 확인 이후, 로컬 개발 서버(`npm run dev`, http://localhost:3000)를 직접 띄워 실제 요청/응답을 확인했다.

- `GET /school` → **HTTP 200**. 페이지 HTML에 "평균 특목고 진학률", "학교 목록"(변경된 랭킹 패널 제목), "데이터 준비 중" 문구가 정상적으로 포함되어 렌더링됨을 확인. 과거의 가짜 퍼센트 수치나 "(시 평균 상회)" 문구는 응답 어디에도 나타나지 않음.
- `GET /api/school?region=부산광역시 서구&type=중등` → **HTTP 200**. 응답 예:
  ```json
  {"success":true,"data":[{"id":"7171011","name":"경남중학교","rank":1},{"id":"7171035","name":"대신여자중학교","rank":2}, ...]}
  ```
  실제 NEIS 학교명·학교코드(`SD_SCHUL_CODE`)만 포함되고, 과거의 `students`/`achievement`/`specialHigh`/`specialRatio` 등 가짜 필드는 응답에 존재하지 않음.
- `GET /api/school/stats?region=부산광역시 서구` → **HTTP 200**. 응답:
  ```json
  {"success":true,"data":{"totalSchools":23,"elemCount":11,"midCount":7,"highCount":5,"specRate":null,"academyLocation":"토성동5가","academyCount":45}}
  ```
  `specRate: null`로 정상 반환됨을 확인(과거 학교명 해시 기반 가짜 퍼센트가 더 이상 계산되지 않음). 학교 수(초/중/고), 학원가 밀집 위치·개수는 실제 값 그대로 반환됨.
- dev 서버 실행 및 위 요청 처리 중 콘솔/터미널에 에러 로그 없음.

## 남아 있는 학군 데이터 문제

- **`/school` 페이지의 "학원가" 탭 필터링 로직 이상(가짜 데이터 아님, 별도 버그)**: `api/school/route.ts`의 `kindMap`은 `'초등'/'중등'/'고등'`만 처리하고 `'전체'`/`'학원가'` 탭은 필터링되지 않아, 이 두 탭에서는 모든 학교급(초+중+고)이 뒤섞여 반환된다. 특히 "학원가" 탭은 이름상 학원 목록을 보여줘야 할 것 같지만 실제로는 학교 목록이 그대로 노출된다. 이는 데이터 조작(가짜 수치 생성)이 아니라 탭-필터 매핑 누락에 가까운 별도 이슈이며, 무엇을 보여줘야 하는지에 대한 기능 설계 판단이 필요해 이번 "데이터 신뢰성" 정비 범위에서는 제외했다.
- **학생수/학급당인원/진학률 등에 대한 실제 공식 데이터 소스가 여전히 없음**: 이번 작업은 가짜 수치를 제거하고 "데이터 준비 중"으로 정직하게 표시하는 데 그쳤을 뿐, 실제 데이터를 새로 확보한 것은 아니다. 아래 "향후 공식 데이터 연동 후보" 참고.
- **`/school/[id]` 상세페이지의 "학년별 학생 수 추이"·"특목고 진학률" 섹션**: 이미 "데이터 준비 중"으로 정직하게 처리되어 있었으나, 이 역시 실제 데이터로 채워지지는 않은 상태로 남아 있음(이번 STEP 범위 밖).

## 향후 공식 데이터 연동 후보

주의: 아래는 현재 코드/문서에서 실제로 참조되고 있는 API만 기록한 것이며, 확실하지 않은 신규 외부 API를 임의로 조사하거나 채택하지 않았다.

- 이 코드베이스가 이미 사용 중인 **NEIS Open API**(`https://open.neis.go.kr/hub/...`, `NEIS_API_KEY`)에는 현재 `schoolInfo`(학교 기본정보) 엔드포인트만 연동되어 있다. NEIS는 이 외에도 학급수/학생수 관련 공개 엔드포인트를 제공하는 것으로 알려져 있으나, 이번 조사에서는 이 코드베이스 안에 해당 엔드포인트를 실제로 호출/검증한 코드가 없어 구체적인 엔드포인트명을 확정 기재하지 않는다 — 실제 채택 전 별도 조사·검증이 필요하다.
- 특목고/자사고 진학률, 4년제 대학 진학률과 같은 데이터는 이번 조사 범위 내 코드/문서 어디에서도 실제 공공 API 연동 근거를 찾지 못했다 — 현재로서는 확정 가능한 후보가 없다.
