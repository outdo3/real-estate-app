# REPORT TEMPLATE REDESIGN V1 — 인포그래픽 한장 리포트

> **표현 레이어만 바꿨다.** 데이터 로직·trust 의미·DB/schema는 건드리지 않았다.
> 템플릿은 계속 envelope만 읽는다(Prisma 접근 0, 재계산 0).

## 1. 무엇이 문제였나

REPORT ENGINE V1은 기능적으로 완성돼 있었지만, 출력물은 **폭 520px짜리 세로로 긴
모바일 카드 더미**였다. 저장하거나 카카오톡으로 보냈을 때 "리포트"가 아니라
"앱 스크린샷"으로 보였다.

## 2. 설계 방향

화면이 아니라 **문서**를 기준으로 폭·여백·위계를 다시 잡았다.

| | 이전 | 이후 |
|---|---|---|
| 캔버스 폭 | 520px 고정 | **데스크톱 1000px** / 모바일 자동 재배열 |
| 구조 | 카드 세로 나열 | 헤더 → KPI 스트립 → **2단 본문** → 해석 → 신뢰 푸터 |
| 헤더 | 텍스트 3줄 | 브랜드 그라디언트 밴드 + 태그 + 신뢰 칩 + 기준일 |
| 점수 | 막대만 | **도넛 다이얼 + 항목별 막대** |
| 푸터 | 작은 각주 | 신뢰 칩 · 기준일 · 기간 · 출처 · 브랜드 서명 |

## 3. 디자인 시스템

`src/components/report/ReportSheet.module.css` — 토큰(색/여백/라운드/타이포)과
프리미티브를 한 곳에 모았다. 6개 리포트가 **같은 파일**을 쓰므로 스타일이 갈라질 수 없다.

`src/components/report/ReportPrimitives.tsx` — `ReportHeader` / `SectionHead` /
`KpiCard` / `DefinitionList` / `ScoreDial` / `TrustChip` / `TrustFooter`.
전부 envelope 값을 **배치만** 한다.

## 4. 적용 범위

| 리포트 | 상태 |
|---|---|
| 단지 (`/report/apt/[aptSeq]`) | **전면 개편** (PHASE A) |
| 비교 (`/report/compare`) | **전면 개편** (PHASE B) |
| 지역 city/district/dong | **전면 개편** (PHASE C) |
| 일별 (`/report/daily/[date]`) | **전면 개편** (PHASE D) |

최소 PASS 기준(단지+비교)을 넘어 4종 전부 같은 시각 언어로 정리했다 — 두 종만 바꾸면
나머지가 옛 카드 스타일로 남아 오히려 제품이 어긋나 보인다.

## 5. 데이터 진실성 (바뀌지 않은 것)

- MISSING은 그대로 MISSING(흐린 '정보 없음'), 0으로 채우지 않는다.
- LIMITED/UNVERIFIED는 칩으로 계속 보인다. SAFE에는 칩을 붙이지 않는다(모든 줄에
  배지가 붙으면 의미가 사라진다).
- 점수가 없으면 다이얼을 그리지 않고 "준비 중"만 — 0점처럼 보이면 안 된다.
  항목 점수가 없으면 막대를 0%로 두고 "정보 없음"이라고 쓴다.
- "역대 신고가" 금지 유지 — 하이라이트에 기간 문구(`최근 2년`)를 항상 함께 그린다.
- 평 라벨 없음, ㎡ 유지.
- 비교 리포트: 종합 승자 없음. 우열(▲)은 리포트 기준 SAFE 항목에서만 조용히.
- 일별 리포트: 보류/준비 중이면 **상태 박스가 주인공**이고 숫자 영역 자체가 렌더되지
  않는다(envelope이 이미 숫자를 만들지 않았다).

### 고친 표시 버그 하나

비교 리포트가 준공연도를 `toLocaleString`으로 찍어 **"2,014년"**으로 보였다.
연도 전용 포맷터(`fmtYear`)를 만들어 `2014년`으로 고쳤다. 값 자체는 그대로이고
표기만 바로잡은 것이다.

## 6. export / print

### 6.1 캡처가 깨졌다가 고쳐진 지점

새 디자인을 처음 내보냈을 때 **점수 도넛과 항목별 막대가 통째로 사라졌다.**

원인은 REPORT-6에서 내린 결정이었다. 캡처는 텍스트가 다시 접힐 때 박스가 따라 커지도록
`width`/`height`를 복사하지 않는데(그 규칙이 헤더 글자 잘림을 고쳤다), 도넛과 막대처럼
**크기 자체가 그림**인 요소는 그 규칙 때문에 0으로 찌그러졌다.

기존 `data-export-*` 계약과 같은 방식으로 예외를 열었다:

```
data-export-fixed-size   ← 이 요소만 width/height를 함께 복사한다
```

글자가 없거나 크기가 고정된 도형에만 붙인다(도넛, 도넛 내부 원, 막대 트랙/필).
붙인 뒤 캡처본에서 링과 막대가 정상 렌더되는 것을 확인했다.

### 6.2 결과

- PNG 1080px 폭 고정, 비율 유지. 액션바는 캡처에 들어가지 않는다
  (구조적으로 `data-export-root` 바깥 + `data-export-exclude`).
- 인쇄(PDF)는 같은 문서를 A4로 흘려보낸다. 실측: 시트가 전폭으로 펴지고
  액션바 `display:none`, PDF 생성 성공(60~62KB).
- 화면과 export의 구조 차이가 없다 — 버튼만 빠진다.

## 8. 남은 한계

- **단지 사진(hero visual)은 넣지 않았다.** 항상 있는 자산이 아니라서, 없을 때
  레이아웃이 무너지지 않는 쪽을 택했다. 신뢰 가능한 이미지 소스가 생기면 헤더 우측에
  optional 썸네일로 넣을 수 있는 구조다.
- **긴 리포트는 A4 2장이 될 수 있다.** 글자를 줄여 억지로 1장에 넣지 않았다
  (읽히지 않는 1장보다 읽히는 2장이 낫다). `break-inside: avoid`로 섹션이 페이지
  경계에서 반으로 갈리지는 않게 막았다.
- `RegionReportSheet.module.css`는 아직 남아 있다 — `ReportActions`(액션바/버튼)와
  `InvalidScope`가 계속 쓴다. 리포트 본문 스타일은 전부 새 모듈로 옮겨갔다.
- 비교 리포트 해석 문장에 "대신롯데캐슬는"처럼 조사가 어긋나는 경우가 있다.
  문장 생성은 데이터 레이어(compare-report.ts) 소관이라 이번 범위에서 건드리지 않았다.
