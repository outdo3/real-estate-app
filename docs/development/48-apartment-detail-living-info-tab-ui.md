# STEP 48 — 단지 주변 생활정보 탭 UI 개선

상태: **구현 완료 / commit·push 완료 / production 반영 확인**

성격: 기능 추가/API 변경 없이, 상세페이지 3구역(실거주 환경·교통·학군)
탭의 시각적 존재감과 선택 상태 가독성만 개선한 UI 전용 STEP.

## 목적

모바일 실기기 기준으로 탭 글자가 작고 선택 상태가 약해 사용자가 탭
자체를 인지하지 못할 수 있다는 지적. 기능/데이터는 그대로 두고
"어떤 탭이 선택되어 있는지 한눈에 보이는 수준"으로 UI만 개선한다.

## 기존 문제

- 탭이 텍스트+밑줄 형태라 존재감이 약함
- 선택 상태가 초록 텍스트+밑줄 정도로 미약함
- 섹션 제목("실거주 환경 & 학군 인프라")보다 탭이 시각적으로 약함

## 변경 전 UI

```
[실거주 환경] [교통·편의시설] [학군]     ← 텍스트 + 하단 밑줄, flex 배치
```

선택 상태: 초록 텍스트 + 초록 밑줄만.

## 변경 후 UI

```
┌─────────┐ ┌─────────┐ ┌─────────┐
│   🏡    │ │   🚇    │ │   🏫    │
│ 주거환경 │ │ 교통·편의 │ │  학군   │
└─────────┘ └─────────┘ └─────────┘
```

3열 고정 그리드(`grid-template-columns: repeat(3, minmax(0, 1fr))`),
아이콘(위)+라벨(아래) 카드형 버튼. `minmax(0, 1fr)`을 쓴 이유는 `1fr`
단독이면 그리드 트랙이 콘텐츠 min-content 폭 밑으로 줄어들지 않아
좁은 화면에서 그리드 자체가 넘칠 수 있기 때문이다 — 0을 하한으로 줘
항상 3등분을 강제한다. 버튼(grid item)에도 `min-width: 0`을 명시해야
트랙이 실제로 줄어든다(grid item 기본값이 `min-width: auto`라
지정하지 않으면 콘텐츠 폭 이하로 줄지 않는다).

## 제목 변경

"실거주 환경 & 학군 인프라" → "단지 주변 생활정보"

코드 영향 범위를 먼저 조사(`grep`으로 해당 문자열의 참조처 확인)했고,
`apt-client.tsx` 한 곳에서만 쓰이는 순수 표시 텍스트임을 확인한 뒤
변경했다 — 다른 컴포넌트/분석 로그/테스트가 이 문자열에 의존하지
않는다.

## 탭 구조

라벨 변경: 실거주 환경 → 주거환경, 교통·편의시설 → 교통·편의, 학군
(유지). `infraTab` state(`'환경' | '교통' | '학군'`)와 탭 전환 로직,
각 탭이 렌더링하는 컴포넌트(`LivingEnvironmentPanel`/
`NeighborhoodInfoPanel`/`SchoolDistrictPanel`)는 전혀 건드리지 않았다
— 라벨과 마크업(아이콘/라벨 span 분리)만 바꿨다.

## 선택 상태 디자인

- 배경: 연한 그린(`#e6f9ee`, `--primary-color`(`#03c75a`)의 옅은 톤)
- 테두리: 그린(`var(--primary-color)`), 2px
- 라벨: `font-weight: 700`(비선택은 600)
- 기존 "초록 텍스트+밑줄"보다 훨씬 명확하게 구분됨

## 모바일 360/375/390 검증 결과

STEP47에서 이미 확인한 대로 이 환경의 claude-in-chrome `resize_window`가
실제 `window.innerWidth`를 바꾸지 못해(재확인 완료), 실제 뷰포트
리사이즈로는 검증할 수 없었다. 대신 **동일한 CSS/마크업을 그대로 담은
독립 `iframe`(자체 뷰포트를 가짐, `@media` 쿼리가 iframe 자신의 폭
기준으로 정확히 평가됨)을 360px/375px/390px 폭으로 생성**해 실측했다:

| 폭 | 3개 버튼 한 줄 여부 | 라벨 잘림 | horizontal overflow |
|---|---|---|---|
| 360px | 예 (`allSameRow: true`) | 없음 | 없음 |
| 375px | 예 | 없음 | 없음 |
| 390px | 예 | 없음 | 없음 |

세 폭 모두 `document.documentElement.scrollWidth`가 iframe 폭을
넘지 않음을 스크립트로 직접 측정해 확인했고, 스크린샷으로도 3개 카드가
한 줄에 나란히 렌더링됨을 시각 확인했다.

**단, 이 iframe 검증은 실제 브라우저 창 크기 변경을 통한 검증이
아니다** — CSS 구조(고정 3열 그리드 + `minmax(0,1fr)` + 라벨
`overflow: hidden; text-overflow: ellipsis`)가 이론적으로도 줄바꿈이
불가능하고 잘림 시에도 폭을 넘지 않도록 만들어져 있다는 것까지 함께
확인한 결과이며, **실제 모바일 실기기 검수를 대체하지는 않는다.**
