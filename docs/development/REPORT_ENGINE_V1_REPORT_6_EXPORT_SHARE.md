# E-JIP REPORT ENGINE — REPORT-6 (이미지 / PDF / 공유)

> **Production write 없음 / schema 변경 없음 / migration 없음 / 신규 의존성 없음.**
> 대상: city / district / dong / apt / compare / daily 6개 리포트 전부.

## 1. 새 의존성을 **하나도 추가하지 않았다**

`html2canvas` / `dom-to-image` / `jspdf` / `puppeteer` 계열은 이 저장소에 설치돼 있지
않다(감사 결과 0건). 추가하려면 `package.json`과 `package-lock.json`을 고쳐야 하는데
**두 파일 모두 사용자의 작업 중 파일**이라 이 STEP이 손댈 수 없다(AGENTS.md worktree
보존). STEP §4/§7도 "무거운 의존성을 가볍게 추가하지 말 것", "서버 Chromium은 정말
필요할 때만"을 우선순위로 지시한다.

그래서 두 경로 모두 **브라우저 네이티브**로 구현했다:

| 기능 | 방식 | 추가 의존성 |
|---|---|---|
| 이미지 | DOM → SVG `<foreignObject>` → canvas → PNG | 없음 |
| PDF | 인쇄 스타일시트 + `window.print()` | 없음 |

## 2. 이미지 아키텍처 (`src/lib/report/dom-to-png.ts`)

리포트 시트는 캡처하기에 이상적인 모양이라는 걸 먼저 확인했다:

- `<img>` / `background: url()` **없음** → 외부 리소스 인라인 단계가 통째로 불필요
- `@font-face` **없음** → `Pretendard`는 이름만 지정돼 있고 실제로는 시스템 폰트로
  렌더된다. `foreignObject`도 같은 시스템 폰트를 쓰므로 **한글 글리프가 바뀌지 않는다**
  (폰트 임베딩 단계가 필요 없다는 뜻이기도 하다)
- `::before/::after` content **없음** → 캡처가 놓치는 시각 요소가 없다

흐름:

```
article[data-export-root]
  → 복제 + computed style 인라인 고정
  → SVG foreignObject에 담아 Image로 로드
  → canvas에 그린 뒤 알파 경계로 잘라내기
  → PNG Blob
```

### 2.1 구현하며 실제로 깨졌던 것 세 가지

문서로 남기는 이유: 이 세 가지가 캡처 품질의 전부였다.

**(1) `width`/`height`를 통째로 복사하면 글자가 잘린다.**
computed 값을 그대로 박으면 캡처 안에서 텍스트가 한 줄 더 접힐 때 박스가 따라 커지지
못한다. 실측: 부제 "취소 거래 제외"의 "외"가 헤더 밖으로 삐져나가고, 푸터의
`검증 중 / 데이터 기준 / 관찰일`이 아래 문단과 겹쳤다.
→ `width`/`height`/`max-height`는 복사하지 않고 자연 높이로 둔다.
`min-height`는 유지한다(박스를 키우기만 하므로 글자를 자르지 않는다).

**(2) 컴포넌트가 직접 준 인라인 스타일이 사라진다.**
분포 막대는 `style={{ width: '43%' }}`처럼 인라인으로 폭을 받는다. computed 복사본으로
`style` 속성을 통째로 덮으면 그 값이 날아간다.
→ 원본 인라인 스타일을 **맨 뒤에 다시 붙여** 우선권을 준다.

**(3) 높이를 "측정"해서 쓰면 마지막 줄이 잘린다.**
DOM 안의 복제본은 `body`의 상속 스타일 위에서 렌더되지만 `foreignObject` 안은 그렇지
않아, 같은 인라인 스타일이라도 줄바꿈이 미세하게 달라진다. 실측: daily 시트에서 측정값
512px에 맞춰 그렸더니 푸터 출처 문구 한 줄이 잘렸다(실제 필요 549px).
→ **넉넉하게 그린 뒤 알파 채널로 실제 내용 경계를 찾아 잘라낸다.**
`foreignObject`는 내용이 없는 곳을 투명하게 남기므로 이 경계가 정확하다. 측정값은
"얼마나 넉넉히 그릴지"를 정하는 힌트로만 쓴다.

### 2.2 해상도 (§5)

가로 **1080px** 고정(공유 친화적), 세로는 비율 유지. 시트 실제 폭(366px @390 뷰포트)에서
배율을 유도하되 `MAX_SCALE = 3`으로 상한을 둬 저해상도를 억지로 늘리지 않는다.
총 픽셀이 16MP를 넘으면 배율을 낮춰 과도하게 큰 파일을 만들지 않는다.

투명 배경이 카카오톡에서 검게 보이지 않도록 합성 시 흰 바탕을 깐다.

## 3. PDF 아키텍처 (§6/§7)

서버 렌더러를 추가하지 않고 **브라우저 인쇄 파이프라인**을 쓴다.
같은 리포트 HTML을 `@media print`로만 재배치하므로:

- 본문이 **벡터 텍스트**로 남는다 → 한글이 선명하고 선택/검색이 된다
- 링크가 살아 있다
- 사용자는 인쇄 대화상자에서 "PDF로 저장"을 고른다

`@page { size: A4 portrait; margin: 12mm }`. 억지로 한 장에 욱여넣어 글자를 줄이지
않는다(§6) — 길면 여러 장으로 나가고, `break-inside: avoid`로 섹션/거래 카드/푸터가
페이지 경계에서 반으로 갈리지 않게만 막는다.

## 4. 내보내기 안전 모드 (§12)

셀렉터를 템플릿마다 복제하지 않고 **속성 두 개**로만 계약한다:

| 속성 | 뜻 |
|---|---|
| `data-export-root` | 캡처/인쇄 대상(각 시트의 `<article>`) |
| `data-export-exclude` | 캡처·인쇄에서 제외(액션바 등) |

액션바는 구조적으로 `<article>` **바깥**에 있어 이미지 캡처에서는 애초에 들어가지
않고, 인쇄에서는 `data-export-exclude`가 숨긴다. 비교 리포트는 예전에 자체 액션바를
따로 그렸는데 이번에 공용 `ReportActions`로 합쳤다(§1 "중복 템플릿 금지").

## 5. 공유 (§8/§9/§10)

- Web Share API 우선, 없으면 **링크 복사** 폴백.
- 파일 공유가 가능한 환경(주로 Android Chrome)에서는 캡처 PNG를 **함께** 싣는다.
  단 **URL/text는 항상 포함**한다 — 이미지는 클릭할 수 없으므로(§8) 링크가 없으면
  수신자가 리포트로 돌아올 방법이 사라진다.
- iOS Safari는 `files`와 `url`을 같이 넘기면 `canShare`가 false를 주는 경우가 있어
  그때는 조용히 URL 공유로 내려간다(거짓 실패 표시 없음).
- 파일 공유 가능 여부를 **먼저 확인한 뒤에만** 캡처한다 — 불가능한 환경에서 쓸데없이
  1~2초를 쓰지 않기 위해.

Kakao SDK는 쓰지 않는다(§9). 수신자 맥락은 공유 문구가 담당한다:
`{제목} · {기간 라벨} · 이집 E-JIP`.

### 5.1 canonical URL (§10)

`export-identity.ts`가 envelope의 `reportType + scope + period`에서만 경로를
재구성한다. **표시 이름을 쓰지 않는다.**

| 리포트 | 경로 |
|---|---|
| city | `/report/city/busan` |
| district | `/report/district/{lawdCd}` |
| dong | `/report/dong/{lawdCd}/{dong}` |
| apt | `/report/apt/{aptSeq}` |
| compare | `/report/compare?a={a}&b={b}` (순서 보존 — 뒤집으면 다른 리포트) |
| daily | `/report/daily/{관찰일}` |

identity가 불완전하면 경로를 **지어내지 않고 null**을 돌려주며, 그때는 현재 주소를
그대로 쓴다.

## 6. 파일명 (§15)

결정적이고 사람이 읽을 수 있으며, 고유성은 항상 canonical id가 만든다(표시 이름 아님).

```
e-jip-busan-2026-09-09.png
e-jip-district-26350-2026-09-09.png
e-jip-dong-26140-서대신동3가-2026-09-09.pdf
e-jip-apt-26140-1164.png
e-jip-compare-26140-1164-26140-1356.pdf
e-jip-daily-2026-08-29.png
```

한글은 유지하고(최신 OS/카카오톡 모두 UTF-8 파일명 처리), 경로 구분자·예약문자·
제어문자만 제거한 뒤 60자로 자른다.

## 7. 신뢰가 파일과 함께 나간다 (§13/§14)

캡처 대상이 시트 전체이므로 다음이 **자동으로** 포함된다:

- 리포트 제목 / 기간 / E-JIP 브랜드
- `데이터 기준(dataAsOf)`
- 완전성 칩(`검증 완료` / `일부 제한` / `검증 중`)
- `trust.notes` 전체
- 출처 문구(`국토교통부 실거래가 · 취소 거래 제외 · …`)
- 일별 리포트의 "새로 확인된" 표현과 관찰일≠계약일 안내

일별 리포트 5개 상태가 이미지에서도 그대로 유지되는 것을 확인했다(§14):

| 상태 | 이미지에 나타난 문구 |
|---|---|
| READY_ZERO | 새로 확인된 실거래가 없습니다 |
| PREPARING | 데이터 확인 중 |
| WITHHELD_BACKFILL | 이 날짜는 집계를 제공하지 않습니다 |
| OUTSIDE_SUPPORTED_RANGE | 집계 제공 기간이 아닙니다 |

보류 상태에서 **숫자 이미지를 만들지 않는다** — envelope이 이미 숫자를 만들지 않았고
캡처는 그 화면을 그대로 굽기 때문에 구조적으로 불가능하다.

## 8. 번들 영향 (§22)

- **신규 의존성 0** → 의존성 무게 증가 없음.
- 캡처 코드는 버튼을 누를 때 `import()`로 지연 로드된다. 빌드 산출물에서 별도 청크
  (**3.2 KB**)로 분리된 것을 확인했고, QA에서 리포트를 열기만 했을 때는 로드되지
  않고 **탭한 뒤에야** 청크 요청이 발생하는 것을 실측했다.
- 즉 리포트를 읽기만 하는 사용자는 내보내기 코드를 내려받지 않는다.

## 9. iOS / Android 차이 (§17)

| | Android Chrome | iOS Safari |
|---|---|---|
| Web Share | 지원 | 지원 |
| 파일 공유(`canShare({files})`) | 대체로 지원 → 이미지+링크 | 조합에 따라 false → 링크만 |
| `<a download>` 저장 | 파일로 저장 | 새 탭/미리보기로 열리는 경우가 있어 사용자가 직접 저장 |
| PDF | 인쇄 → PDF로 저장 | 공유 시트 → 파일에 저장 |

어느 경로든 **실패를 성공으로 표시하지 않는다**. 캡처가 실패하면
"이미지를 만들지 못했습니다"라고 말한다.

## 11. 알려진 한계

- **PDF는 브라우저 인쇄 대화상자를 거친다.** 원탭 저장이 아니라 "인쇄 → PDF로 저장"
  단계가 있다. 원탭 PDF를 원하면 PDF 라이브러리나 서버 렌더러가 필요한데, 그건
  의존성 추가라 이 STEP의 범위를 벗어난다.
- **`foreignObject` 래스터화는 브라우저 구현에 의존한다.** Chrome에서 실측 검증했고,
  Safari는 구조적으로 같은 경로를 지원하지만 이번 QA 환경에서는 검증하지 못했다
  (§12 참고). 실패 시 조용히 실패하지 않고 사용자에게 알린다.
- **그림자/그라디언트 같은 일부 시각 효과는 복사 목록에 없다.** 리포트 시트가 실제로
  쓰는 속성만 복사하므로 현재 화면과 차이는 확인되지 않았지만, 시트에 새 CSS 효과를
  추가하면 `COPIED_PROPS`에도 추가해야 한다.
- 차트(SVG)를 쓰는 리포트가 향후 생기면 별도 검증이 필요하다. 현재 리포트의 시각화는
  전부 CSS 막대라 캡처에 그대로 담긴다.
