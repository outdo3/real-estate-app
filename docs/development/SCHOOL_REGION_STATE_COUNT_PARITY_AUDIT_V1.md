## 1~3. 스크린샷 해명 — **state desync가 아니라 "지우지 않은 이전 목록"이다**

### 먼저: 표시값과 요청값은 어긋날 수 없다

둘 다 **같은 객체**에서 파생된다(`src/app/school/school-client.tsx:50`).

```tsx
const regionName = `${region.sido} ${region.sigungu}`;  // 요청에 쓰는 값
<span>📍 {regionLabel}</span>                            // 화면에 쓰는 값 (= regionName.trim())
fetch(`/api/school?region=${encodeURIComponent(regionName)}&type=...`)
```

**어느 한 시점을 잘라 보면 표시 sigungu == 요청 sigungu가 항상 참이다.** 값 차원의 desync는 없다.
어긋남은 **값이 아니라 시간**에서 생긴다.

### 진짜 원인: 목록이 지역 변경 때 초기화되지 않는다

```tsx
const [schools, setSchools] = useState<any[]>([]);
useEffect(() => {
  const fetchSchools = async () => {
    setLoading(true);
    try {
      const res = await fetch(`/api/school?region=${...}`);
      const json = await res.json();
      if (json.success) setSchools(json.data);   // ← 성공했을 때만 갱신
    } catch { … } finally { setLoading(false); }
  };
  fetchSchools();
}, [regionName, activeTab]);
```

확인한 사실(코드 전수):

| 사실 | 근거 |
|---|---|
| `setSchools`는 **성공 시 한 곳에서만** 호출된다 | `school-client.tsx:87` — 파일 전체에서 유일한 호출 |
| 지역이 바뀔 때 **`setSchools([])`를 하지 않는다** | 초기화 호출 자체가 없음 |
| 목록 `<ul>`은 **`loading`과 무관하게 항상 렌더**된다 | 빈 상태 문구만 `!loading`으로 가려짐 |
| **요청 취소·stale 응답 가드가 없다** | `AbortController`/`signal`/cleanup 전부 **없음** |
| `stats`도 동일 | `setStats`는 성공 시 1곳(`:106`), 초기화 없음 |

→ **지역이 바뀐 순간 제목은 즉시 새 지역으로 바뀌지만, 목록은 새 응답이 도착할 때까지 이전 것이 그대로 남는다.**

### 그래서 스크린샷이 성립한다

1. 진입 → `region = FALLBACK_REGION`(**`sigungu: ''`**, 표시 "부산광역시 전체")
2. 학교 목록 요청이 `region="부산광역시 "`로 나감 → **수정 전 코드에서는 부산 671곳 중 663곳**이 돌아옴
   (명지3고=부산진구 주소, 명지3·4중·6초=북구 주소가 **한 응답 안에** 들어 있다)
3. `setSchools(663)` → 화면에 명지 학교들이 그려짐
4. **GPS 역지오코딩**(`RegionContext`) 또는 **URL `?sido=&sigungu=` 복원**(`RegionUrlSync`)이
   **비동기로 늦게** 끝나며 `setRegion({ sigungu: '서구' … })`
5. 제목은 그 즉시 **"부산광역시 서구"** 로 바뀜 (동기 렌더)
6. 새 요청이 나가지만 **그 응답이 오기 전까지 3번의 663행 목록이 그대로 표시**

→ **"부산광역시 서구" 제목 + 명지 학교 목록.** 운이 필요한 race가 아니라 **구조적으로 반드시 생기는 창**이다.

### "서구 wrong-district 0"과 스크린샷이 동시에 성립하는 이유

**화면에 있던 목록은 서구 응답이 아니었다.** 서구 필터는 그때도 정확히 24곳(명지 0)을 반환했다.
사용자가 본 것은 **`sigungu=''`로 나간 이전 요청의 응답**이다. 두 사실은 모순이 아니다.

### FALLBACK_REGION이 쓰이는 시점 (§2)

| 경로 | 확인 |
|---|---|
| 초기 state | `useState(FALLBACK_REGION)` — **`sigungu: ''`** |
| **영속화 없음** | `localStorage`/`sessionStorage` 복원 **없음** → **새로고침·뒤로가기마다 항상 "전체"에서 다시 시작** |
| GPS 복원 | `navigator.geolocation` → 카카오 역지오코딩 → `setRegion` (**비동기**) |
| URL 복원 | `RegionUrlSync` → `resolveLawdCdByNames(...).then(...)` (**비동기**, 최초 1회) |
| 사용자 선택 | `RegionSelectModal` — "부산광역시 전체" 선택 시에도 `sigungu: ''` |

**stale closure·router 경합은 없었다.** 원인은 위 하나다.

### 지금은 얼마나 남아 있나

수정(`0d7dfe0`) 이후 `sigungu=''` 응답이 **663 → 0건**이 됐으므로 **이 경로로 다른 구 학교가 뜨는 일은 사라졌다.**
그러나 **"이전 목록이 남는" 구조 자체는 그대로**다. 여전히 가능한 오표시:

- 동래구(52곳) 보다가 서구로 전환 → **제목 서구 + 동래구 52곳**이 잠시 표시
- 창 길이 = 새 요청 왕복 시간. 실측(운영, 서버 캐시 10분): **cold 0.35~0.43초 · warm 0.12~0.14초**

짧지만 **다른 구 데이터를 그 지역인 것처럼 보여주는 상태**이므로 남겨 두지 않는 편이 맞다. → **PATCH_REQUIRED**

## 9. PATCH 권고 (이번 STEP 구현 안 함)

### P0 — 지역 바뀔 때 이전 목록을 지운다

사용자가 본 현상의 직접 원인이고, 지금도 "제목 A + 목록 B"를 만든다.

1. `regionName`이 바뀌면 **`setSchools([])` / `setStats(초기값)`** 를 먼저 한다.
2. `useEffect`에 **stale 응답 가드**를 둔다(`AbortController` 또는 `let cancelled = false` cleanup).
   현재는 둘 다 없어, 느린 이전 응답이 새 응답을 덮어쓸 수도 있다.
3. 목록 `<ul>`을 **`!loading`일 때만** 렌더하거나 로딩 중 스켈레톤으로 대체한다.

### P1 — "전체" 탭과 요약 카드의 계약을 하나로

둘 중 하나를 고르는 **제품 결정**이 필요하다(코드만으로 정할 수 없다):

- **(A) 초·중·고로 통일** — 요약과 목록이 같은 23이 된다. 특수학교·외국인학교 등 40곳이 목록에서 사라진다.
- **(B) 모든 유형으로 통일** — 목록 24를 유지하고 **요약 카드도 24**로 센다. 다만 "초/중/고" 개별 카드와
  총합이 어긋나므로 "기타 1" 같은 칸이 필요하다.

**(B)를 권한다** — 특수학교·외국인학교는 실재하는 학교이고, 지역 학교 목록에서 지우는 것은 정보 손실이다.
어느 쪽이든 **두 곳이 같은 기준을 쓰게** 하는 것이 핵심이다.

### P2 — 지역 선택 영속화 검토

지금은 새로고침·뒤로가기마다 **항상 "부산광역시 전체"로 되돌아간다**(영속화 없음).
그래서 §1의 "전체 → 구" 전환이 **매 진입마다** 일어난다. 선택을 기억하면 그 창 자체가 줄어든다.
다만 GPS 정책·지도 기본 위치와 얽혀 있어 별도 STEP이 맞다.
