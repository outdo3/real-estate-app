## 1. 이전 UX

아파트 상세 하단에 버튼 두 개가 있었다:

```
[ 지도 ]  [ 로드뷰 ]     ← 각각 모달을 연다
```

- 위치를 보려면 **항상 한 번 더 눌러야** 했다.
- 지도와 로드뷰가 **서로 다른 모달**이라, 둘 사이를 오가려면 닫았다 다시 열어야 했다.
- 모달 안에는 "📍 **단지명**의 위치입니다." 같은 안내 문장이 지도 위 공간을 차지했다.

## 2. 최종 UX

```
위치                          [ 지도 | 로드뷰 ]
┌──────────────────────────────────────────┐
│                                          │
│            지도 또는 로드뷰               │   ← 같은 컨테이너
│                                          │
└──────────────────────────────────────────┘
주소
```

버튼 게이트 없음. 라우트 이동 없음. 모달 없음. 지도↔로드뷰는 **같은 컨테이너 안에서** 바뀐다.

## 4. 배치

```
가격/실거래 요약 → 거래 타임라인 → 단지 상세 제원
→ ★ 위치(지도+로드뷰) ★
→ 단지 주변 생활정보 → 커뮤니티 → 제휴 CTA
```

**"단지 주변 생활정보" 바로 앞.** 사용자가 단지 자체(가격·거래·제원)를 다 훑은 직후 자연스럽게 "그래서 여기가 어디인가"로 넘어가는 지점이고, 그 답이 곧 아래 생활정보(학교·교통·편의)의 전제가 된다.

일부러 피한 자리: 가격 요약 **앞**(핵심 정보를 밀어낸다), 페이지 **맨 아래**(거의 안 본다), 점수 카드 **안**(객관 지표와 섞인다), 떠 있는 오버레이.

## 5. 좌표 — canonical만 쓴다

서버(`/api/apt/[name]?withCoordinate=1`)가 canonical identity로 해석해 준 좌표만 쓴다. 클라이언트에서 **다시 추측하지 않는다**.

- `mode="coordinate"` → `planMapEmbed`가 `USE_STORED_COORDINATE`를 내고, `KakaoMapEmbed`는 Geocoder/Places 객체를 **생성조차 하지 않는다**. 런타임 지오코딩이 구조적으로 불가능하다.
- 좌표가 이상하면(0,0 널섬, 범위 밖, NaN) 주소 모드로 **떨어지지 않는다** — 떨어지면 이름 검색이 다른 장소를 집을 수 있다.
- 마커는 **현재 단지 하나**. 지역 마커 데이터셋이나 주변 단지 목록을 가져오지 않는다.

### 없음 상태 — "확인 중"과 "없음"을 구분한다

| 상황 | 표시 |
|---|---|
| 좌표 해석 진행 중(`locationReady=false`) | `위치 정보를 확인하고 있습니다…` |
| 해석 끝났고 좌표 없음 | `위치 정보를 확인할 수 없습니다.` + 안내 |

확인 중인 것을 "없다"고 말하면, 잠시 뒤 지도가 뜨는 순간 방금 한 말이 거짓이 된다. 어느 경우에도 **가짜 마커를 찍지 않는다**.

## 6. 로딩 전략

"지도가 바로 열린다"는 **버튼 게이트가 없다**는 뜻이지, 상세 초기 렌더를 Kakao SDK에 묶는다는 뜻이 아니다.

```
상세 본문 렌더  →  위치 카드 자리(400px) 이미 확보  →  카드가 화면에 다가오면 SDK 로드
```

- `useLazyInView` — IntersectionObserver **단독으로는 안 된다**. IO 콜백은 렌더 파이프라인에 실려 오기 때문에 요소가 이미 화면 안에 있어도 콜백이 영영 오지 않는 경우가 있다(오피스텔 QA에서 실제 재현). 그래서 **동기 판정 + IO + scroll/resize 보조**를 함께 쓰고 먼저 도착하는 쪽이 이긴다.
- 컨테이너 높이를 CSS에서 고정해 SDK 전후로 **레이아웃 시프트가 없다**.
- 한 번 켜지면 다시 꺼지지 않는다 — 껐다 켜면 SDK 재초기화 비용이 든다.

**실측**: 상세 페이지 초기 HTML에 `dapi.kakao.com/v2/maps/sdk` 태그가 **없다**. SDK는 크리티컬 패스에 없다.

## 7. 지도 ↔ 로드뷰

`mode = 'map' | 'roadview'` **단일 상태**(§11). `isMap`/`showRoadview` 같은 불리언을 따로 두지 않아 모순 상태가 생길 수 없다.

- 두 컨테이너가 **계속 살아 있고** `visibility`만 바뀐다(`display:none`이면 Kakao가 크기를 0으로 읽어 다시 보일 때 깨진다).
- 돌아올 때 `relayout()`만 호출 — 중심/줌은 사용자가 둔 그대로다.
- 인스턴스를 재생성하지 않으므로 반복 전환해도 **SDK 재초기화도, 캔버스 누적도 없다**.
- 단지 데이터는 전혀 다시 불러오지 않는다.

### 로드뷰가 없을 때

`RoadviewClient.getNearestPanoId(coords, 200m)`가 비면 같은 카드 안에 사실대로 표시한다:

> 이 위치는 로드뷰를 제공하지 않습니다.

지도 모드는 그대로 살아 있고, 상단 `[지도]`를 누르면 즉시 돌아온다. 검은 빈 화면을 남기지 않는다. **로드뷰 카메라 위치가 단지 출입구라고 주장하지 않는다** — 가장 가까운 지원 지점일 뿐이다.

## 8. 옛 진입점 정리

| 항목 | 결정 |
|---|---|
| `[지도]` 모달 버튼 | **제거** |
| `[로드뷰]` 모달 버튼 | **제거** |
| `'지도'` / `'로드뷰'` 모달 케이스 | **제거** |
| apt-client의 `KakaoMapEmbed` dynamic import | **제거**(호출부가 사라져 죽은 코드. 같은 컴포넌트로 가는 지연 로딩 진입점이 두 곳이면 청크가 갈라진다) |
| 다음 행동의 `/map` 이동 | **유지하되 라벨 변경**: `지도에서 위치 보기` → `지도에서 주변 단지와 보기` |

마지막 항목이 §12의 핵심이다. 상세 안 카드가 **이 단지의 위치**를 보여주므로, `/map`이 주는 값은 이제 "주변 단지와 함께 보기"다. 라벨이 그 차이를 말하지 않으면 사용자는 어느 쪽이 "진짜" 지도인지 고민하게 된다. 기능은 없애지 않았다.

외부 카카오맵 링크는 이 화면에 원래 없었다.

- GA4 `page_view` 동작 무변경.

## 11. 모바일 QA — **STRUCTURAL QA ONLY**

**브라우저 렌더링이 아니다.** 이 세션에서 브라우저 확장이 승인되지 않았고 헤드리스 브라우저는 `package.json`을 건드려야 해서 설치하지 않았다. 렌더 PASS를 주장하지 않는다.

구조 근거:

- `.mapFrame`은 `width:100%` + 고정 높이 400px. 고정 픽셀 폭이나 `min-width`가 없어 **가로 오버플로가 생길 수 없다**.
- 높이를 모바일에서 낮추지 않은 이유: `KakaoMapEmbed` 내부가 `min-height:400px`을 쓰므로 프레임만 낮추면 지도가 `overflow:hidden` 밖으로 잘린다. 그 공용 컴포넌트를 고치는 건 오피스텔까지 건드리는 변경이라 범위 밖이다.
- 전환 버튼: `min-height 36px` + 좌우 여백. `.switch`는 `flex-shrink:0`이라 제목이 길어도 줄어들지 않고, 380px 이하에서는 **제목 글자만** 줄인다.
- 하단 탭 겹침: 카드는 일반 흐름 안이고 상세 `.main`이 이미 `padding-bottom: calc(60px + 4rem)`을 확보한다.
- 스크롤: 카카오 지도 기본 제스처를 그대로 둔다 — 공격적인 터치 차단을 추가하지 않았다.

**권장**: 실제 기기 360px에서 지도·로드뷰 전환을 한 번 눈으로 확인.

## 12. 오피스텔 재사용 (§18) — **REUSED NOW (부분)**

- **공용 훅은 재사용됐다.** 중복되던 in-view 판정을 `useLazyInView`로 옮기고 `OfficetelLocationCard`가 그것을 쓰도록 바꿨다. 동작 동일, 약 50줄 중복 제거. IO 단독으로는 안 되는 미묘한 로직이라 두 벌로 두면 한쪽만 고쳐진다.
- **카드 컴포넌트는 합치지 않았다.** 두 화면의 CSS/레이아웃 언어가 다르고(오피스텔은 지도 위 플로팅 토글, 아파트는 헤더 세그먼트), 합치려면 동작하는 화면을 건드려야 한다. §18의 "아파트 릴리스 품질을 위협하면서까지 오피스텔을 바꾸지 말 것"에 따라 하지 않았다.

## 13. 알려진 한계

1. 모바일 QA가 렌더링 기반이 아니다(§11).
2. 지도/로드뷰 **초기화 타이밍(ms)을 측정하지 못했다** — 브라우저 계측이 필요하다. SDK가 크리티컬 패스에 없다는 것은 초기 HTML로 확인했다.
3. 지도 높이가 모든 폭에서 400px이다 — `KakaoMapEmbed`의 `min-height` 때문이며, 낮추려면 공용 컴포넌트를 함께 고쳐야 한다.
4. 로드뷰 탐색 반경은 기존 200m 그대로다(`KakaoMapEmbed` 상수). 이 STEP에서 바꾸지 않았다.
5. 위치 카드 컴포넌트가 아파트/오피스텔 두 벌이다(§12).
