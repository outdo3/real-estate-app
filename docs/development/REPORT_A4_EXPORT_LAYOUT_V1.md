# REPORT A4 EXPORT LAYOUT V1

단지 리포트 PDF가 2페이지로 나뉘고 1페이지 아래 절반이 비던 문제,
공유 PNG가 "긴 웹 스크롤 캡처"로 나오던 문제를 잡는다.

**레이아웃/내보내기 전용 STEP이다.** DB · schema · migration · 리포트 계산 ·
trust 의미 · Score 공식은 건드리지 않았다. 리포트 envelope도 그대로다.

- 대상: `/report/apt/[aptSeq]`, `/report/compare`, `/report/city|district|dong`, `/report/daily/[date]`
- 실측 기준 단지: `26140-1164` (대신롯데캐슬)

---

## 1. 목적

리포트는 화면에서 읽히기도 하지만, 결국 **저장되고 공유되는 한 장**이다.
그런데 지금까지는 웹 화면 하나로 세 가지 일을 다 하려 했다.

| 의도 | 요구 | 이전 상태 |
| --- | --- | --- |
| WEB VIEW | 반응형, 세로 스크롤 허용, 읽기 최적화 | 정상 |
| SHARE IMAGE | 고정 구성, A4 세로비, 한 장 | 화면 폭 그대로 캡처 → 374×2429px |
| PDF | A4 세로, 단지 리포트는 한 장 | 2페이지 + 1페이지 하단 공백 |

이 STEP은 **웹은 그대로 두고 문서(PDF/PNG)만 분리**한다.

## 2. 웹 / 내보내기 렌더링 계약

세 가지 의도를 하나의 마크업으로 처리한다. **별도 템플릿을 만들지 않는다** —
템플릿을 복제하면 곧 두 벌이 서로 다른 사실을 말하기 시작한다.

```
같은 envelope → 같은 컴포넌트 → 같은 DOM
                                  │
        ┌─────────────────────────┼──────────────────────────┐
        │                         │                          │
   (기본 CSS)              @media print          [data-export-mode='a4']
     웹 화면                  PDF                    공유 PNG
   반응형/스크롤            A4 한 장               A4 한 장 이미지
```

- **WEB**: 지금까지와 동일. 폭에 따라 1단/2단, 세로 스크롤 자유.
- **PDF**: 브라우저 인쇄 파이프라인(`window.print()`). 본문이 벡터 텍스트로 남아 한글이 선명하다.
- **PNG**: `dom-to-png`이 화면 밖에 **A4 폭(794px) 클론**을 세우고 문서 모드를 켠 뒤 굽는다.
  화면에 보이는 시트는 전혀 흔들리지 않는다.

### 밀도 토큰 하나로 세 갈래를 만든다

구조 규칙(열 수·방향·라벨 폭·줄 높이·여백)을 전부 `.sheet`의 CSS 변수로 올렸다.
반응형/인쇄/내보내기는 **규칙을 다시 쓰지 않고 토큰만 덮어쓴다.**

```css
.sheet { --r-stack: 22px; --r-cols: 1.25fr 1fr; --r-dl-key: 132px; --r-fs: 1; ... }

@media (max-width: 860px) { .sheet { --r-stack: 22px; --r-cols: 1fr; ... } }
.sheet[data-export-mode='a4'] { --r-stack: 10px; --r-cols: 1.1fr 1fr; --r-fs: 0.92; ... }
@media print            { .sheet { --r-stack:  8px; --r-cols: 1.1fr 1fr; --r-fs: 0.88; ... } }
```

이 방식이 중요한 이유가 두 가지 있다.

1. **특이도 싸움이 없다.** 공유 PNG 클론은 화면 밖이어도 뷰포트 기준 media query
   (`max-width: 860px`)의 지배를 받는다. 예전 방식대로 구조 규칙을 덮어쓰려면
   셀렉터 경쟁이 필요했지만, 토큰은 `.sheet` 한 곳에서 결정된다.
2. **두 벌이 갈라지지 않는다.** 컴포넌트/문구/데이터는 하나뿐이고 밀도만 다르다.

> CSS는 클래스를 `@media print` 안으로 합성해 줄 수 없어, 밀도 값 자체는
> `.sheet[data-export-mode='a4']`와 `@media print` 두 곳에 나뉘어 있다.
> 인쇄 쪽이 여백(10mm)만큼 자리가 좁아 값도 조금 더 촘촘하다.
> **한쪽만 고치면 안 된다.** 두 블록에 서로를 가리키는 주석을 달아 두었다.

## 3. A4 치수

| | CSS px (96dpi) | 비고 |
| --- | --- | --- |
| A4 세로 전체 | 794 × 1123 | 210 × 297mm |
| PDF 인쇄 가용 영역 | **718 × 1047** | `@page { margin: 10mm }` |
| 공유 PNG 캔버스 | **794 × 1123** | 여백 없이 꽉 찬 문서 |
| 공유 PNG 래스터 | **1080 × 1528** | 794 → 1080 (배율 1.36), 비율 1 : 1.415 |

`@page` 여백을 12mm → **10mm**로 줄였다.
12mm에서는 가용 영역이 703×1032px이었고, 그 안에 단지 리포트가 들어가지 못했다.
10mm도 문서 여백으로 충분히 자연스럽다.

## 4. 2페이지 PDF의 원인

두 가지가 겹쳐 있었다.

**(1) 큰 섹션을 통째로 보호했다.**

```css
/* 이전 */
.section, .kpi, .tradeRow, .insightBox, .toBox, .vsCard, .footer, .highlight {
  break-inside: avoid;
}
```

`.section`과 `.footer`까지 "쪼개지 말 것"으로 묶여 있었다. 그래서 남은 자리에
들어가지 못하는 섹션(최근 실거래 361px, 이집 점수 289px …)이 **통째로 2페이지로
점프**했고, 1페이지 아래쪽이 그대로 비었다.

**(2) 인쇄 밀도가 화면 밀도였다.**

`.sheet { font-size: 10.5pt }`를 걸어도 자식들이 전부 `rem`(루트 기준)을 쓰고 있어
실제로는 아무것도 줄지 않았다. 여백/줄 높이도 화면 값 그대로였다.
게다가 인쇄 시 페이지 폭이 703px이라 모바일 media query(`max-width: 860px`)가 적용돼
**KPI가 2열 3행**으로 펼쳐졌다.

실측(703px 인쇄 폭, 예산 1032px):

```
header 197 / 가격·거래 168 / 하이라이트 128 / 최근 실거래 361
이집 점수 289 / 생활·입지 210 / 단지 정보 168 / 해석 267 / 푸터 132
합계 1661px  →  1032px 예산의 161%  →  2페이지
```

## 5. 페이지 나눔 전략

**쪼개지면 곤란한 작은 단위만** 보호한다.

```css
@media print {
  /* 보호: 한 덩어리로 읽혀야 하는 작은 것들 */
  .kpi, .tradeRow, .dlRow, .barRow, .matrixRow,
  .highlight, .insightBox, .toBox, .vsCard, .stateBox, .scoreWrap, .signature {
    break-inside: avoid;
  }
  /* 제목만 남고 본문이 넘어가는 고아 제목 방지 */
  .sectionHead, .matrixHead { break-after: avoid; }
}
```

- `.section` / `.footer`의 `break-inside: avoid`는 **제거**했다.
- 그래서 어쩔 수 없이 2페이지가 되는 경우에도 섹션이 내부에서 나뉘고,
  1페이지가 먼저 채워진다. "1페이지 절반 공백 + 2페이지에 전부"는 나오지 않는다.
- 배경색은 `print-color-adjust: exact`를 헤더·KPI·상자·점수 도넛·막대·칩까지 확대 적용했다.

## 6. 압축한 것 (문서 전용)

`transform: scale()`로 페이지를 통째로 줄이지 않았다. 글자도 작게 만들지 않았다.
줄인 것은 **여백·줄 높이·중복**이다.

| 항목 | 웹 | 인쇄 | 공유 PNG |
| --- | --- | --- | --- |
| 바깥 여백 `--r-pad` | 26 / 18px | 14px | 18px |
| 섹션 간격 `--r-stack` | 22px | 8px | 10px |
| KPI 카드 패딩 | 14/14/13px | 8/10px | 9/11px |
| 라벨:값 한 줄 | 9px | 3px | 4px |
| 거래 한 줄 | 10px | 3px | 5px |
| 본문 줄 높이 `--r-lh` | 1.5 | 1.38 | 1.38 |
| 글자 배율 `--r-fs` | 1 | 0.88 | 0.92 |
| KPI 열 | 2열(모바일) | **3열** | **3열** |
| 강점/확인할 점 | 1열(모바일) | **2열** | **2열** |
| 항목별 점수 막대 | 4행 | **2×2** | **2×2** |
| 계약일 표기 | 줄바꿈 | **같은 줄** | **같은 줄** |

- `--r-fs`는 **큰/중간 글자에만** 곱한다. 0.74~0.86rem짜리 캡션은 그대로 둔다 —
  전부 균일하게 줄이면 칩과 각주가 읽히지 않는다.
- 인쇄 본문 기준 크기: 섹션 제목 약 10.3pt, 값 9.5pt, 캡션 8.9pt.
- 라벨 폭은 고정 px이 아니라 **비율(`--r-dl-key: 42%`)** 이다.
  좌우 단 폭이 다르므로(좌 351 / 우 320) 한 고정값이 양쪽에 맞을 수 없다.

## 7. 최근 실거래 행 정책

- 웹: 최대 5건.
- 문서(PDF/PNG): **4건.** `.tradeList[data-export-cap='4'] > *:nth-child(n+5) { display: none }`
- 각 행은 어느 경우에도 **면적 · 층 · 계약일 · 가격**을 모두 유지한다.
- 5건 이상 있을 때만 문서에 문구가 붙는다:

  > 최근 거래 일부 표시 · 자세한 내용은 이집에서 확인

  (`.exportNote` — 웹에서는 `display: none`, 문서에서만 나온다)

envelope은 손대지 않았다. 줄이는 것은 표현이고, **줄였다는 사실을 문서 안에서 밝힌다.**

## 8. 공유 PNG 계약

`captureReportExport()` (`src/lib/report/dom-to-png.ts`):

1. 화면의 시트를 복제한다 (보이는 화면은 건드리지 않는다).
2. 화면 밖 홀더(`left: -100000px`)에 **794px 폭**으로 세운다.
3. 클론에 `data-export-mode="a4"`를 붙인다 → 문서 밀도로 다시 짜인다.
4. 두 프레임 기다린 뒤 내용이 A4를 얼마나 채우는지 잰다.
5. 기존 `captureElementToPng()`으로 굽는다 → 1080 × 1528.

### 채움률에 따른 세로 정책

억지로 A4를 채우면 준비 중 상태 리포트는 화면의 60%가 흰 여백이 된다.
그래서 채움률로 갈래를 나눈다.

| 채움률 | 세로 | 남는 높이 |
| --- | --- | --- |
| ≥ 90% | A4(1123px) | 본문 블록 사이로 분배 (`space-between`) |
| 65 ~ 90% | A4(1123px) | 푸터 위 한 곳에 모음 (`flex-start`) |
| < 65% | 내용 높이 | — |

어느 경우에도 **A4 폭은 유지**되므로 "긴 웹 캡처"로 돌아가지 않는다.
내용이 A4를 넘치면 **자르지 않고** 그만큼 길어진다 — 잘라서 비율을 맞추지 않는다.

실측 채움률: 단지 0.94 · 비교 0.99 · 시 0.92 · 구 0.94 · 동 0.75 · 일별(준비 중) 0.42

## 9. 카카오 공유

`ReportActions`의 이미지 저장 / Web Share 두 경로 모두
`captureElementToPng(보이는 시트)` → **`captureReportExport(시트)`** 로 바꿨다.

- 공유 payload에는 A4 PNG **와 함께 canonical URL/text가 항상 실린다.**
  이미지는 클릭할 수 없으므로 링크가 빠지면 수신자가 리포트로 돌아올 방법이 사라진다.
- 액션바는 `data-export-exclude`로 이미 제외돼 있었다.
  이번에 **PWA 설치 배너**에도 같은 표시를 붙였다 — 인쇄물에 남고 있었다.

## 11. 비교 리포트 정책

- 목표는 한 장이고, 현재 실측(1019 / 1047px, 97%)으로 **한 장에 들어간다.**
- 여유가 30px 남짓이라 단지명이 아주 길거나 trust note가 늘면 2페이지가 될 수 있다.
- 2페이지가 되더라도 §5의 나눔 규칙 때문에 1페이지가 먼저 채워지고
  섹션이 내부에서 나뉜다. "고아 푸터/헤더 조각"은 나오지 않는다.

## 12. 알려진 문제 / 남은 한계

1. **비교 리포트 여유가 얇다** (1047px 예산에 1019px). 위 §11 참고.
2. **하이라이트 값의 날짜가 인쇄에서 갈릴 수 있다.**
   `6억 6,500만원 · 전용 129.7178㎡ · 2026-09-05`가 좁은 단에서 `2026-09-` / `05`로 나뉜다.
   `word-break: keep-all`로도 하이픈 줄바꿈은 막히지 않는다.
   값 문자열을 조각으로 나누려면 envelope 조립을 건드려야 해서 이번 범위에서 제외했다.
3. **동 리포트 공유 이미지는 아래 여백이 넓다** (채움률 0.75 → 약 280px이 푸터 위에 모임).
   A4 형식을 지키기 위한 선택이다.
4. **일별 리포트 준비 중 상태는 A4가 아니다** (1080 × 663).
   A4로 늘리면 60%가 흰 여백이라 내용 높이를 택했다.
5. **밀도 값이 두 블록에 나뉘어 있다** (§2). CSS 한계이며 주석으로 묶어 두었다.
6. PDF는 브라우저 인쇄 대화상자를 거친다. 사용자가 여백/배율을 바꾸면 한 장 보장이 깨진다
   (`@page`는 기본값만 정한다).
