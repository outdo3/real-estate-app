# LOGIN RECENT VIEWED DENSITY UX V1

브랜치: `main` / 기준 커밋: `9f2cf98`

로그인(MY) 화면의 "최근 본 단지" 목록을 기본 5행으로 줄이고 더보기/접기를 붙인다.
표시 밀도만 바꾸는 STEP이다. DB/schema/migration 변경 없음.

## 1. 감사 결과 (구현 전)

| 질문 | 답 |
|---|---|
| 컴포넌트 경로 | `src/app/my/page.tsx` — `/my`가 이 앱의 로그인/계정 화면이다(`proxy.ts`가 비로그인 사용자를 여기로 보내고 `AuthGate`가 로그인 모달을 띄운다) |
| 최근 본 단지 출처 | `GET /api/my/recent` (서버, Prisma). 로그인 상태에서만 조회한다 |
| 정렬 규칙 | 서버가 정한다 — `orderBy: { viewedAt: 'desc' }` |
| 현재 최대 개수 | **20** (`take: 20`). 화면에는 그 전부가 잘림 없이 렌더됐다 |
| 항목이 이미 클라이언트에 있는가 | **있다.** `recentViews` state에 배열로 들어와 있고 렌더는 `.map()`뿐이었다 |
| 순수 UI slice로 가능한가 | **가능하다.** 조회·정렬·중복·식별자에 손댈 필요가 없다 |

### 다른 화면과의 관계

`최근 본 단지`는 두 곳에 있는데 **출처도 표현도 다르다.**

| 화면 | 출처 | 표현 | 이 STEP |
|---|---|---|---|
| `/my` (로그인) | `/api/my/recent` (서버, 최대 20) | **세로 목록** | **대상** |
| `/` (홈) | `localStorage` (`recent-apartments.ts`, `MAX_RECENT = 8`) | 가로 스크롤 | 건드리지 않음 |

홈은 가로 스크롤이라 세로 스크롤 압박이 없다. 지시대로 **로그인 화면만** 바꿨다.

## 2. 변경

| | 전 | 후 |
|---|---|---|
| 기본 표시 행 수 | 최대 **20** (전부) | **5** |
| 더보기 | 없음 | 6건 이상일 때 `더보기 (N개 더 있음)` |
| 펼친 상태 | — | **현재 가진 전부** |
| 접기 | 없음 | `접기` → 5로 복귀 |
| 5건 이하 | 전부 표시 | 전부 표시 (버튼 없음) |

개수 규칙은 `src/lib/my/recent-rows.ts` 순수 모듈이 갖는다.

### 실거래 목록(`trade-rows.ts`)과 왜 따로인가

모양은 비슷하지만 **펼치는 방식이 다르다.**

- 실거래: 15씩 단계적으로 늘린다(한 단지에 거래가 수백 건일 수 있다)
- 최근 본 단지: 한 번에 전부 펼친다(서버가 이미 20건으로 잘라 상한이 정해져 있다)

규칙이 다르므로 억지로 한 모듈로 합치지 않았다.

## 3. 데이터는 하나도 바뀌지 않았다 (§4)

기본 5행은 **예전에 20행을 만들던 바로 그 배열의 앞 5건**이다.

건드리지 않은 것: canonical aptSeq / 단지명 / 위치 라벨 / 클릭 목적지(`aptHref`) /
`viewedAt` 정렬 / 중복 제거 / `localStorage`·세션 동작 / 서버·클라이언트 조회 경로 /
보관 개수(`take: 20`).

새 API도 새 쿼리도 만들지 않았다. `/api/my/recent` 호출은 여전히 **한 번**이고,
펼치고 접는 데 추가 조회가 없다(목록은 이미 클라이언트에 다 있다).

테스트가 정렬 규칙(`viewedAt desc`), 보관 개수(`take: 20`), 호출 횟수(1회),
`aptHref` 시그니처와 링크 형태, `key={r.id}`를 각각 고정한다.

## 4. 로그인 흐름이 여전히 우선 (§5)

페이지 구조를 재설계하지 않았다. 순서는 그대로다:

```
프로필 → (관리자) → 관심단지 → 최근 본 단지 → 관심 목적 → 바로가기 …
```

로그인 컨트롤은 `AuthGate`가 띄우는 **모달**이라 이 목록보다 항상 위에 있다.
목록이 20행에서 5행으로 줄면서 아래 섹션들이 훨씬 가까워졌다.

## 5. 행 밀도 (§6)

행 표현을 바꾸지 않았다 — 이름 + 주소 두 줄 그대로이고, 이미지·배지·가격·통계·제휴
콘텐츠를 추가하지 않았다.

`.aptItem`의 패딩도 **일부러 그대로 뒀다.** 이 클래스는 바로 위 **관심단지** 목록과
공유한다 — 여기를 줄이면 이 STEP 범위 밖 화면이 같이 바뀐다(§12). 밀도 이득은 대부분
행 수에서 나오므로 굳이 공유 클래스를 건드릴 이유가 없다. 테스트로 고정했다.

## 6. 상태 동작 (§9)

- 진입 시 → 접힌 5행 (`useState(false)`)
- 다른 화면에 갔다 돌아옴 → 접힌 5행 (컴포넌트가 다시 마운트된다)
- 펼침 여부를 `localStorage`/세션에 **저장하지 않는다** — 저장하면 다음 방문에 20줄로
  다시 열려 이 STEP이 무의미해진다
- 로그인 성공 동작 변경 없음

## 7. 접근성 (§10)

- `<button type="button">` — Enter/Space 키보드 활성화가 기본 동작
- `aria-expanded={recentExpanded}`
- `aria-label`: `최근 본 단지 더보기` / `최근 본 단지 접기`
- 터치 타깃 `min-height: 44px`
