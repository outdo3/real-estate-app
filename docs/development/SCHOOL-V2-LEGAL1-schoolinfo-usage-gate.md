## 0. 핵심 요약 (먼저 결론)

이번 조사에서 **이전에 몰랐던 결정적 1차 자료를 새로 찾았다**: schoolinfo.go.kr의 OpenAPI "API 제공목록" 안의 **개별 공시항목(오퍼레이션)별 메타정보 페이지**에 명시된 "이용허락조건"이다. 3개 오퍼레이션(학교기본정보=apiType0, 학년별·학급별 학생수=apiType09, 직위별 교원현황=apiType22)에서 **동일한 문구**를 직접 확인했다:

이는 data.go.kr 카탈로그 등록(`15098092`, "공공누리 제3유형: 출처표시+변경금지")과 **문면상 다르다** — 카탈로그는 변경을 금지하는데, schoolinfo.go.kr 자신의 오퍼레이션별 명세는 변경(가공)까지 명시적으로 허용한다. 두 공식 출처가 서로 다른 말을 하고 있다는 사실 자체를 그대로 보고한다(§2/§4에서 상세).

**두 개의 서로 다른 공식 출처가 다른 결론을 준다 — 이 사실 자체가 결론이다.**

| schoolinfo.go.kr 오퍼레이션별 메타정보(3개 표본 확인) | 유형 라벨 없음, 평문 서술 | 가능(명시) | **가능(명시)** |

**판정**: `KOGL TYPE` 질문에 대해 **UNKNOWN(단일 유형으로 확정 불가)** — data.go.kr은 제3유형이라 하고, 데이터를 실제로 서비스하는 schoolinfo.go.kr 자신의 API 명세는 그보다 관대한 조건(변경 허용)을 명시한다. 어느 쪽이 우선하는지 판단할 공식 근거(예: "data.go.kr 등록 정보와 원 제공기관 정보가 다르면 어느 쪽을 따른다"는 규정)를 찾지 못했다.

**실무적 판단(법률 자문 대체 아님, 이번 STEP의 잠정 결론)**: schoolinfo.go.kr 오퍼레이션별 페이지가 (a) 실제 API를 호출하는 그 도메인 자신의 문서이고, (b) 3개 서로 다른 카테고리(기본정보/학생수/교원현황)에서 일관되게 같은 문구였으며, (c) 더 최근에/더 구체적으로 이 특정 오퍼레이션에 대해 작성된 문서로 보인다는 점에서 **schoolinfo.go.kr 쪽 조건을 더 신뢰할 수 있는 근거로 채택**한다. 다만 data.go.kr 등록과의 불일치가 해소되지 않은 채로 남으므로, 최종 게이트는 아래 §10에서 **CLEARED가 아니라 CONDITIONAL**로 판정한다.

## 3. 상업적 이용

## 4. 변경/가공의 의미 — 항목별 판정

기준: schoolinfo.go.kr 오퍼레이션 메타정보(변경·2차저작물 작성까지 명시적으로 허용)를 1차 근거로 삼되, data.go.kr 제3유형(변경금지, "형식의 변경"까지 포함하는 넓은 정의)과의 불일치가 있다는 점을 모든 항목에 동일하게 적용되는 배경 리스크로 깔고 판단한다. "법률가처럼 단정" 대신 확실한 범위와 REVIEW_REQUIRED 범위를 구분한다.

|---|---|---|---|

| I | 좌표를 거리 계산 input으로 사용 | **REVIEW_REQUIRED(단, E~H보다 낮은 위험)** | 좌표 그 자체(위도·경도 숫자 하나)는 창작성이 인정되기 어려운 단순 사실값이라 저작권 보호 대상 여부 자체가 불확실 — 다만 이는 이번 조사가 판단할 수 없는 저작권법 일반론(창작성 요건)이라 REVIEW_REQUIRED로 남긴다 |
| J | 좌표로 직선거리 Nm 계산해 표시 | **REVIEW_REQUIRED** | I와 동일 근거 + 계산 결과가 원본 데이터셋에 없는 새 수치라는 점에서 G와 유사한 성격도 있음 |

**중요**: 위 REVIEW_REQUIRED 항목들 중 상당수가 schoolinfo.go.kr의 실제 오퍼레이션 조건("변경 및 2차적저작물 작성 포함 자유이용")만 놓고 보면 SAFE에 가깝다. REVIEW_REQUIRED로 유지하는 이유는 **data.go.kr 제3유형과의 미해소된 불일치** 때문이지, schoolinfo.go.kr 자체 문서에 금지 문구가 있어서가 아니다.

> 본 저작물은 '교육부'에서 'OO년' 작성하여 공공누리 제O유형으로 개방한 '저작물명(작성자:OOO)'을 이용하였으며, 해당 저작물은 '학교알리미 홈페이지(https://www.schoolinfo.go.kr/)'에서 무료로 다운받으실 수 있습니다.

필수 요소: 기관명(교육부) + 작성연도 + 공공누리 유형(단, §2에서 확인했듯 이 API의 정확한 유형 자체가 불확실 — 표기 시 이 문제를 어떻게 다룰지도 REVIEW_REQUIRED) + 저작물명 + (표시돼 있다면) 작성자명 + 출처 URL.

**이집 UI 초안 제안**:
- **화면 내 짧은 표기**(카드/섹션 하단, 공간 제약 고려): `"자료: 교육부 학교알리미(schoolinfo.go.kr), 2026년"` — 기관명+연도+URL은 포함하나 공식 예시의 "공공누리 제O유형", "저작물명", "작성자명"은 생략됨.
- **판정**: 화면 내 짧은 표기만으로는 **공식 예시 형식의 전 요소를 충족하지 못한다.** 별도의 "데이터 출처" 또는 "이용약관" 상세 페이지에서 공식 예시 형식 그대로(기관명/연도/유형/저작물명/작성자/URL)를 완전하게 표기하고, 화면 내 짧은 표기는 그 상세 페이지로 링크하는 2단 구조를 권장한다. (§2의 유형 불확실성이 해소되기 전에는 "공공누리 제O유형" 자리를 어떻게 채울지 결정할 수 없어 — 이 부분도 REVIEW_REQUIRED.)

## 8. 최근 3년 제한의 의미 — HISTORICAL_RETENTION

공식 근거(재확인): 「교육관련기관의 정보공개에 관한 특례법 시행령」 제3조 3항 — "최근 3년 동안의 자료만 공시" — API 제공목록 페이지 상단에 이 조항이 그대로 인용돼 있다.

**질문**: 2024년에 합법적으로 받은 데이터가 2027년에 API에서 내려간 뒤에도 이집 DB에 계속 보관/표시할 수 있는가?

이 조항과 위에서 확인한 "이용허락조건"(출처표시하면 자유이용) 어디에도 "받은 데이터를 몇 년 뒤에는 폐기해야 한다"는 문구는 없다 — 3년 제한은 **API/공시 사이트가 그 시점 이후 자료를 계속 제공(access)하는가**에 대한 규정으로 읽히지, **이미 적법하게 취득한 사본의 보관 기간**을 규율하는 조항으로 보이지는 않는다. 다만 이 특례법의 입법 취지가 "오래된 학교 정보를 무한정 공개하지 않는다"는 프라이버시/정보최신성 보호 목적일 가능성도 배제할 수 없어(추정, 확인 안 됨), 취득 후 보관까지 자유롭다고 단정하기는 이르다.

**판정: `HISTORICAL_RETENTION = REVIEW_REQUIRED`**(지시사항의 기본값 그대로 유지 — 이번 조사로 명확히 해소되지 않음).

## 10. 최종 Gate 판정

### A. `SCHOOLINFO_COORDINATE_USE_GATE` = **CONDITIONAL**

허용 범위: schoolinfo.go.kr 학교기본정보(apiType=0) 오퍼레이션의 좌표(LTTUD/LGTUD)를 (1) **원본값 그대로** DB에 저장, (2) 지도에 **가공 없이** 마커로 표시, (3) 아파트 좌표와의 **distance sort**(정렬)에 사용하는 것 — REVIEW_REQUIRED 요소가 있어도 실무적으로 가장 안전한 사용 형태.

REVIEW_REQUIRED로 남는 범위: 직선거리 Nm 계산(새 수치 생성), 좌표 기반 "주변 학교 순위"처럼 해석적 라벨을 부여하는 사용.

BLOCKED: 없음(이번 STEP에서 명시적으로 금지된다고 확인된 좌표 관련 사용형태는 없음).

### B. `SCHOOLINFO_STATISTICS_USE_GATE` = **CONDITIONAL**

허용 범위: 학생수/학급수/교원수(§4 A~D) 원본값을 **그대로** 표시 — 이 범위는 두 출처(data.go.kr, schoolinfo.go.kr) 어느 쪽 기준으로도 안전.

REVIEW_REQUIRED로 남는 범위: 시계열 차트(F), 증감률 계산(G), 이집 자체 점수 생성(H) — 특히 H는 SchoolStat 기반 점수화 착수 전 반드시 법률 자문 또는 원 제공기관(KERIS/학교알리미 고객센터, 1544-0079)에 직접 서면 확인 권고.

BLOCKED: 없음(재배포만 제외, §7 — 이집은 재배포를 계획하지 않으므로 실무 영향 없음).

## 11. 다음 작업 조건 판정

- `SCHOOLINFO_COORDINATE_USE_GATE = CONDITIONAL` (CLEARED 아님) → **C5-B1 School coordinate ingestion을 무조건 진행할 수는 없다.** 다만 "원본값 그대로 저장 + 가공 없는 표시 + 정렬"이라는 CONDITIONAL 허용 범위 안에서는 진행 가능하다고 판단할 여지가 있다 — 이 판단을 사용자/ChatGPT가 최종 승인하면 그 범위 내에서 C5-B1 착수를 권고. 직선거리 계산·순위화는 REVIEW_REQUIRED로 별도 재검토 후 결정.
- `SCHOOLINFO_STATISTICS_USE_GATE = CONDITIONAL` → **SchoolStat ingestion 준비를 시작하려면 "원본값 그대로 표시"라는 좁은 범위로 한정**해야 하고, 점수화(H)는 별도 명시적 확인 전까지 금지. 이번 STEP은 어떤 경우든 ingestion 자체를 하지 않는다(지시사항).
- 위 두 게이트 모두 CLEARED가 아니므로, `EducationSource`에 실제로 CLEARED 상태로 등록하는 것은 이번 STEP 이후로도 보류 권고 — REVIEW_REQUIRED 상태로 등록하거나(§9 제안값), 아예 등록을 유보하고 다음 STEP에서 재논의.
