## 1. 여백 감사 — 가장 큰 문제

`.panel { padding: 2rem }` 에 **모바일 재정의가 아예 없었다.**

360px 화면에서 카드마다 좌우 32px씩(합 64px = 화면 폭의 **18%**)과 위아래 32px씩을 그대로 쓰고 있었다. 여기에 다른 여백이 겹쳐 쌓였다:

```
sectionBlock margin-top   32px
+ panel padding-top       32px
+ zoneTitle margin-bottom 16px
────────────────────────────────
섹션 하나 시작에만        80px
```

거기에 섹션 끝의 `panel padding-bottom` 32px이 또 붙는다. 화면 하나가 800px 남짓인 폰에서 섹션 전환마다 **112px**이 내용 없이 소비됐다.

두 번째 offender는 **이미 쓸모가 없어진 여백**이었다. `quickButtons`는 버튼을 두 줄 담던 시절의 `marginTop 1.5rem + paddingTop 1.25rem + borderTop`을 그대로 갖고 있었는데, 직전 STEP에서 [지도][로드뷰] 버튼이 빠져 한 줄만 남은 뒤에도 여백만 남아 있었다.

세 번째는 **항상 떠 있던 하단 액션바**다. `.main`이 `padding-bottom: calc(60px + 4rem)`으로 그 높이를 상시 예약하고 있었다.

## 2. 밀도 시스템 — 전면 축소가 아니다

전부 30% 줄이는 CSS 스케일다운이 아니라, **쌓이는 지점만** 줄였다. 글자 크기·줄간격·터치 타깃은 건드리지 않았다(§3/§17).

| 항목 | before | after | 변화 |
|---|---|---|---|
| `.panel` 상하 패딩(카드당) | 64px | 32px | −50% |
| `.panel` 좌우 패딩 | 32px씩 | 16px씩 | −50% |
| `.sectionBlock` 섹션 간격 | 32px | 20px | −38% |
| `.zoneTitle` 제목→내용 | 16px | 9.6px | −40% |
| `.briefCard` 상하 패딩 + 상단 margin | 64px | 44.8px | −30% |
| `quickButtons` 잔여 여백 | 44px | 16px | −64% |
| 실거래 행 상하 패딩 | 27.2px | 17.6px | −35% |
| 액션바 예약 여백(숨김 시) | 64px | 24px | −63% |
| 위치 카드 지도 높이 @390px | 400px | 290px | −28% |

전부 `@media (max-width: 768px)` 안이다 — **데스크톱 레이아웃은 1px도 바뀌지 않았다.**

### 실거래 행 (§7)

데이터는 하나도 빼지 않았다(가격 / 증감 배지 / 날짜 / 평형 / 층 / 거래유형 전부 유지). 줄인 것은 여백뿐이다:

- 상하 패딩 13.6px씩 → 8.8px씩 (**−35%**)
- 줄 사이 간격 4px → 2.4px
- `line-height`를 명시해 브라우저 기본값이 만들던 슬랙 제거

**행 전체로는 약 −16%** 다. 20~25%에 못 미치는 이유를 분명히 적어둔다: 행 높이의 약 70%가 **글자 자체**(가격 21px + 메타 18px)라, 그 이상 줄이려면 가격 글자를 줄이거나 메타 한 줄을 없애야 한다. 둘 다 §7("데이터를 빼서 행을 줄이지 말 것")과 §17("가격 위계 유지")이 금지한다. **목표 수치보다 규칙을 지켰다.**

## 3. 지도 배치 — 예전 버튼 자리로

### OLD BUTTON POSITION → NEW INLINE MAP POSITION

```
2구역 TIER 2 (맥락과 자금)
  PriceTrendChart
  InvestmentMetrics
  quickButtons
    [ 이 집 사려면 얼마 필요할까? ]
    [ 지도 ] [ 로드뷰 ]           ← ★ 예전 버튼 자리
```

직전 STEP은 위치 카드를 **실거래 타임라인 뒤**에 뒀다. 문맥상으로는 말이 됐지만, 사용자가 지도를 찾던 자리는 원래 여기였다. 그래서 **그 자리에 버튼 대신 실제 지도**를 놓는다.

```
2구역 TIER 2
  PriceTrendChart
  InvestmentMetrics
  [ 이 집 사려면 얼마 필요할까? ]
  ★ 위치 카드 (지도 ↔ 로드뷰) ★   ← 새 위치
3구역 TIER 3 (실거래 타임라인 / 단지 상세 제원)
3구역 단지 주변 생활정보
```

실측(렌더 HTML 오프셋): 위치 카드 11320 < 실거래 타임라인 12547 < 단지 상세 제원 14101 < 생활정보 15661. **중복 렌더 없음(카드 1개), 옛 위치에 빈 래퍼나 잔여 여백 없음.**

## 4. 지도 높이 (§5) — 공용 컴포넌트를 안 건드리고

`KakaoMapEmbed`는 아파트와 오피스텔이 **함께 쓴다**. 거기 박힌 `minHeight: 400px`을 그냥 바꾸면 모든 소비자가 같이 바뀐다.

그래서 CSS 변수로 열었다:

```
KakaoMapEmbed:  minHeight: var(--map-embed-min-height, 400px)   ← 기본값은 예전 그대로
AptLocationCard .mapFrame:  --map-embed-min-height 를 미디어쿼리로 재정의
```

변수를 설정하지 않는 화면(**오피스텔 상세**)은 400px 그대로다 — 실제로 오피스텔 쪽 소스에는 이 변수가 없음을 확인했다.

| 폭 | 지도 높이 |
|---|---|
| ≤375px (360급) | **280px** |
| ≤400px (390급) | **290px** |
| ≤440px (430급) | **300px** |
| ≤1024px (태블릿) | **340px** |
| 그 외(데스크톱) | **380px** |

지도와 로드뷰는 같은 프레임(`inset: 0`)에 깔리므로 **높이가 항상 같다.** 프레임 높이를 CSS에서 확정하므로 SDK가 붙기 전후로 레이아웃 시프트가 없다.

## 5. 스마트 하단 액션바 (§10~§14)

### before → after

| | before | after |
|---|---|---|
| 초기 진입 | 보임 | **숨김** |
| 상·중단 읽는 중 | 보임 | **숨김** |
| 하단 도달 | 보임 | 슬라이드 업 |
| `.main` 하단 예약 | 항상 `60px + 4rem` | 기본 `60px + 1.5rem`, **보일 때만** `+4rem` |

### 임계값과 히스테리시스

```
나타남:  진행률 >= 78%
사라짐:  진행률 <= 60%
```

임계값이 하나면 그 경계에서 손가락이 몇 픽셀만 흔들려도 바가 깜빡인다. 18%포인트를 벌려 두면 한 번 뜬 뒤에는 **사용자가 의도적으로 위로 되돌아갈 때만** 사라진다.

판정은 `src/lib/apt-detail/action-bar-visibility.ts` 순수 함수에 있다. 스크롤 핸들러 안에 묻어두면 검증할 방법이 없고, 특히 히스테리시스는 **이전 상태에 따라 답이 달라지는** 규칙이라 눈으로 확인하기 어렵다.

### 진동 방지

바가 뜨면 `.mainWithActionBar`가 약 40px을 더한다 → 문서가 길어짐 → 진행률 하락 → 다시 숨음 → 문서가 짧아짐 → 다시 뜸. 이 진동이 가능한지 확인했다: 수천 px 문서에서 40px은 약 1%이고 임계 간격은 18%포인트라 **뒤집히지 않는다.** 테스트로 고정했다.

### 애니메이션

`translateY(115%)` + `opacity 0` + `pointer-events: none` → `translateY(0)` + `opacity 1`, **200ms ease-out**. 바운스 없음. `prefers-reduced-motion: reduce`에서는 전환을 끄되 나타나고 사라지는 것 자체는 유지한다.

숨김 상태에서도 **DOM에는 남는다** — 마운트/언마운트를 반복하면 슬라이드를 줄 수 없고 `FavoriteButton`이 자기 상태를 다시 읽어야 한다. `pointer-events: none` + `aria-hidden`이라 숨어 있는 동안 탭도 스크린리더도 가로채지 않는다.

### 성능 (§20)

- 리스너는 `passive`
- 실제 계산은 `requestAnimationFrame`으로 **프레임당 한 번**으로 묶는다(스크롤 이벤트는 프레임보다 훨씬 자주 온다)
- 상태는 **값이 실제로 바뀔 때만** 갱신 → 스크롤하는 내내 리렌더 없음
- 새 API 요청 0건, ResizeObserver 0개, 지도 재초기화 없음
- `resize` / `orientationchange`도 같은 핸들러를 탄다

### 기능 (§13)

관심단지 / 공유 / 글쓰기의 **동작은 하나도 바뀌지 않았다.** `visible` prop 하나만 추가했고, 즐겨찾기 상태·공유 동작·analytics·글쓰기 라우팅·인증 가드 전부 그대로다.

## 6. 측정 (§19)

### CSS에서 확정되는 값 (실측)

§2 표와 §4 표가 전부 빌드 산출 CSS에서 확인한 값이다.

### 대표 단지 합산 (계산값 — 렌더 측정 아님)

패널 6개 / 섹션 5개 / 제목 4개 / 거래행 15개 노출 기준, 390px:

```
패널 상하      6 × 32px = 192px
섹션 간격      5 × 12px =  60px
제목 간격      4 × 6.4px =  26px
briefCard              =  19px
quickButtons 잔여      =  28px
지도 높이              = 110px
실거래 행     15 × 9.6px = 144px
액션바 예약(숨김)       =  40px
────────────────────────────────
합계                   ≈ 619px
```

**약 619px = 390px 폰 화면(약 800px 가용) 기준 0.8화면 분량**을 내용으로 돌려준다.

**이 합계는 CSS 델타 × 등장 횟수로 계산한 추정치이지 브라우저에서 잰 문서 높이가 아니다.** 실제 `document.scrollHeight` 비교는 브라우저 계측이 필요해 하지 못했다(§8 한계).

## 8. 남은 한계

1. **모바일 QA가 렌더링 기반이 아니다.** 밀도는 "얼마나 답답한가"가 최종 판단 기준인데 그건 눈으로만 알 수 있다.
2. **총 문서 높이 before/after를 브라우저에서 재지 못했다** — §6의 619px은 계산값이다.
3. **실거래 행은 −16%로 목표(20~25%)에 못 미친다.** 더 줄이려면 가격 글자를 줄이거나 데이터를 빼야 해서 멈췄다(§2).
4. 액션바 임계값 78%/60%는 **실사용 관찰 없이 정한 값**이다. 실기기에서 "너무 늦게/일찍 뜬다"는 피드백이 나오면 순수 함수의 상수 두 개만 고치면 된다.
5. 데스크톱 밀도는 손대지 않았다(이번 피드백이 모바일 화면이었다).
6. 위치 카드 컴포넌트는 아파트/오피스텔 두 벌 그대로다(직전 STEP 한계 유지).
