# APT DETAIL PARTNER + TRADE DENSITY UX V1

브랜치: `main` / 기준 커밋: `b752e49`

단지 상세의 밀도 문제 두 가지를 함께 다룬다: 제휴 카드가 데이터보다 눈에 띄는 문제와,
실거래 15행이 만드는 스크롤 압박. DB/schema/migration 변경 없음.

## 1. 감사 결과 (구현 전)

| 질문 | 답 |
|---|---|
| 법무사 카드 렌더 경로 | `apt-client.tsx` → `<PartnerCtaCard placement="apt_detail">` → `getPartnerForPlacement()` |
| 전화번호 표시 경로 | `PartnerCtaCard`의 `<span className={styles.phoneNumber}>{partner.displayPhone}</span>` |
| 파트너 이벤트 경로 | `PartnerCtaCard` 내부 `IntersectionObserver`(노출) + `onClick`(클릭) → `trackEvent` |
| 실거래 행 수 동작 | `visibleCount` state 초기값 **15**, "더보기" → `+15`, 필터 변경 시 15로 리셋 |
| 거래가 클라이언트에 다 있는가 | **있다.** `TradeTimelineList`는 받은 배열을 `slice`만 한다 |
| 15는 UI slice인가 API limit인가 | **UI slice.** API/조회 범위와 무관하다 |

추가로 확인한 것: 필터 변경 시 리셋 effect가 **이미 존재**했다(`[selectedTradeArea,
tradeTypeFilter, periodFilter, saleFilter]`). 이번에는 그 리셋 값만 15 → 5로 바뀐다.

## 2. 사용자에게 보이는 제휴 문구

`광고·제휴` 배지를 뺐다. 대신 섹션 제목이 그 자리를 대신한다.

```
부동산 등기 상담              ← 법무사
이 단지 상담 가능한 중개사      ← 중개사
```

**파트너 메타데이터는 하나도 지우지 않았다.** `partner.id` / `partner.type` /
`placement` / `channel` 전부 그대로이고 집계 의미도 동일하다 — 표시 변경이다.

이집이 제공하는 서비스가 아니라는 사실은 카드 하단 면책 문구가 계속 말한다:

```
이집이 제공하는 서비스가 아니며, 상담 내용과 비용은 해당 사무실에서 확인해 주세요.
```

> **주의 사항으로 남겨둠:** 광고 표시 문구를 빼는 것은 표시광고 규제 관점에서
> 검토가 필요할 수 있다. 사용자 지시에 따라 배지는 제거했고, 비-이집 서비스임을
> 알리는 면책 문구는 유지했다.

버튼 한 줄(약 50px)을 되찾는다.

CSS 박스 계산 기준 추정 높이: **약 290px(390px 뷰포트) / 346px(360px, 버튼 쌓임)

44px 버튼이며, 둘 다 줄이면 고지 의무나 접근성이 나빠져 §3의 "접근성을 해치면서까지
높이를 강제하지 않는다"에 따라 유지했다.

## 4. 전화번호 비노출

법무사 `010-8026-4778`, 중개사 `051-714-2225` 모두 **화면에 쓰지 않는다.**

- 보이는 것: `전화 상담` / `전화 문의`
- `tel:01080264778` / `tel:0517142225` 는 그대로 — 기능은 동일하다
- 본문·버튼 라벨·**aria-label**·보조 문구 어디에도 숫자가 없다

이유: 번호가 보이면 사용자가 손으로 걸 수 있고, 그 통화는 어떤 집계에도 남지 않아
파트너에게 실제로 무슨 일이 일어났는지 말해줄 수 없다.

## 6. 영업 구역 — canonical 위치로만 판정

### 실측 (읽기 전용 조회)

Production `ApartmentMaster` 에서 `sgg_cd = '26140'`(부산 서구)의 `umd_name`을 직접
조회했다. 서구 전체 법정동은 **19종**이며, 파트너 영업 구역에 해당하는 값은 아래 **9개**다.

| 법정동 | 단지 수 |
|---|---|
| 서대신동1가 | 18 |
| 서대신동2가 | 19 |
| 서대신동3가 | 29 |
| 동대신동1가 | 6 |
| 동대신동2가 | 6 |
| 동대신동3가 | 8 |
| 부민동1가 | 4 |
| 부민동3가 | 1 |
| 부용동1가 | 7 |
| **합계** | **98** |

### 실측이 바꾼 것

- **부민동2가 · 부용동2가에는 ApartmentMaster 행이 하나도 없다.** 파트너가 말한 구역에
  속하지만 대상 단지가 존재하지 않으므로 목록에 넣지 않았다 — 없는 동을 적어두면
  있는 것처럼 읽힌다. (지시문의 "예상 목록"에는 들어 있었지만 추정하지 않고 확인했다.)
- **남부민동(단지 10곳)은 영업 구역이 아니다.** `contains('부민동')`로 매칭하면
  남부민동까지 잡힌다 — 부분 문자열 매칭을 쓰면 안 되는 실제 사례다.

### 자격 규칙

```
lawdCd === '26140'  AND  검증된 9개 법정동과 정확히 일치
```

- 단지명은 **보지 않는다.** `getBrokerForLocation({ lawdCd, dong })`의 인자에 이름을
  넘길 자리 자체가 없다.
- `'서구'`라는 **이름**으로 판정하지 않는다 — 대구·인천·광주·대전에도 서구가 있다.
  lawdCd로 구를 확정한다.
- `lawdCd`나 `dong` 중 하나라도 비면 자격 없음이다. 모르는 상태를 통과시키지 않는다.
- 자격이 없으면 카드가 렌더되지 않고, 따라서 **노출 집계도 발생하지 않는다**(§21).

## 8. 배치

```
핵심 요약 → 가격/실거래 → 지도/학군 → 리포트/자금 → [중개사] → [법무사] → StickyActionBar
```

기존 섹션 순서는 건드리지 않았다. 두 상담 카드만 데이터 구역을 전부 지난 뒤에 온다
(DATA FIRST → ACTION SECOND). 중개사를 법무사보다 앞에 둔 이유: 단지를 보던 사용자에게
더 가까운 다음 행동이 "이 단지 상담"이고, 등기는 매매가 정해진 뒤의 일이다.

Finance Fit(`/finance-fit`)과 `/tools`의 법무사 카드는 **같은 압축 스타일을 자동으로
물려받는다**(공용 스타일시트). 중개사 카드는 넣지 않았다 — 파일럿 범위는 단지 상세뿐이다(§23).

## 9. 실거래 밀도

| | 전 | 후 |
|---|---|---|
| 기본 행 수 | 15 | **5** |
| 더보기 | `+15` | 5 → **15**(예전 기본값까지), 그 뒤 `+15` |
| 접기 | 없음 | **있음** → 5로 복귀 |
| 필터 변경 | 15로 리셋 | **5로 리셋** |

개수 규칙은 `src/lib/apt-detail/trade-rows.ts` 순수 모듈이 갖는다. 예전에는 JSX 안에
흩어져 있어 테스트할 방법이 없었다.

### 데이터는 하나도 바뀌지 않았다 (§15)

기본 5행은 **예전에 15행을 만들던 바로 그 신뢰된 배열의 앞 5건**이다.
`queryTrades()` / canonical aptSeq / 취소 거래 제외 / 평형 매칭 / 정렬 / 가격 계산 /
차트 시리즈 / 면적 라벨 — 전부 그대로다. 이 모듈은 `trades.slice(0, n)`만 한다.

15건보다 많은 단지에서는 예전처럼 15씩 계속 더 볼 수 있다 — 밀도를 줄이면서 볼 수
있던 행을 잠가버리지 않는다.

### 로딩 (§17)

목록은 이미 전부 클라이언트에 있다. 펼치기/접기에 조회가 끼지 않으므로 즉시 반응하고,
거짓 "데이터가 없습니다"가 스칠 수 없다. `STATS LOADING STATE UX FIX V1`은 이 STEP에서
건드리지 않았다.

## 10. 분석

| 이벤트 | 파라미터 |
|---|---|
| `partner_cta_impression` | `partner_type`, `partner_id`, `placement` |
| `partner_cta_click` | `partner_type`, `partner_id`, `placement`, `channel` |

- 법무사: `partner_type=legal_office`, `channel=phone|kakao`
- 중개사: `partner_type=brokerage`, `channel=phone`
- `placement=apt_detail`

두 카드가 같은 훅(`usePartnerCta`)을 쓴다. 스키마 변경 없음, PII 없음 — 상호·번호·
대표자·주소는 집계에 나가지 않는다(테스트로 고정).

### 클릭은 lead가 아니다 (§22)

번호를 감추면 CTA 클릭 관측률은 올라간다. 하지만 그 클릭이 뜻하는 것은 **버튼을 눌렀다**
까지다.

```
전화 클릭 ≠ 통화 연결
전화 클릭 ≠ 상담 진행
전화 클릭 ≠ 계약
```

이벤트 이름을 `partner_cta_click`으로 유지하고 `lead` / `conversion` 같은 이름을 쓰지
않는 이유다. 성과처럼 들리는 이름을 붙이면 나중에 그 숫자가 성과로 읽힌다.

## 12. 데스크톱

모바일과 **같은 5행 기본값**을 쓴다. 화면 크기에 따라 개수를 다르게 하면 같은 화면을
