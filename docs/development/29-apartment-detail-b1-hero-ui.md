## 2. Hero 구조 (최종 구현)

```
[Header] ← 이집 (로고+메뉴+로그인, 아파트명 표시 제거)  ...  로그인

[Hero]
  {단지명}                                          [↗ 공유]
  📍 {지역}
  {준공년도}년 준공 · {세대수}   ← 실제 값 있는 항목만, 동수는 데이터 없어 생략

[가격 핵심]
  최근 실거래가                              [매매] [전월세]  ← 선택된 쪽 초록 채움
  {가격 큰 숫자}   {면적} · {층}층 · {거래일}
  최고가/최저가: 최고 {}/최저 {}

[평형 선택]  ← AreaSelector, 기존 컴포넌트 그대로 재배치

[매매/전세 시세 추이]  ← PriceTrendChart, 위치만 이동

[핵심 가격 지표]  ← InvestmentMetrics(매매가/전세가/전세가율/필요갭금액), 위치만 이동

[단지 스펙 그리드]  ← AptSpecGrid(세대수/준공년월/용적률/건폐율/주차대수), 삭제하지
                      않고 Hero 핵심 다음으로 이동. address는 Hero에서 이미 보여줬으므로
                      중복 방지를 위해 컴포넌트에 빈 문자열 전달(컴포넌트 자체는 무수정)

[퀵버튼]  지도 · 로드뷰 · 단지정보 · 대출한도 · 커뮤니티시설  (건축물대장 제외, §7 참고)
[커뮤니티 유도 카드]
```

## 3. 로그인 유지

`apt-client.tsx`의 `<Header>` 호출을 `<Header hideLogo pageTitle={...} pageTitleLarge
pageTitleAlign="left" />`에서 `<Header />`로 변경했다. `Header.tsx` 자체는 한 글자도
수정하지 않았다(공통 컴포넌트 무수정). `HeaderAuthButton`(로그인 진입점)은 `hideLogo`/
`pageTitle` prop과 무관하게 항상 렌더되는 위치라 로그인은 그대로 유지된다(코드 재확인,
`Header.tsx` line 103, `!hideLogo`/`pageTitle` 조건 밖에 위치).

**부수 효과(의도된 것)**: 아파트명이 더 이상 Header의 `<h1>`로 표시되지 않고, 대신 Hero의
`<h1 className={styles.heroTitle}>`로 이동했다. 승인된 구조 목업(§0의 `[Header] ← 이집 ...
로그인` / `[Hero] 단지명 ...`)이 이 배치를 명시하고 있어 그대로 구현했다.

## 4. 공유 위치/재사용

- **위치**: Hero 우측 상단(단지명과 같은 줄), 너무 강한 primary CTA로 보이지 않도록
  중립 색(흰 배경 + 회색 테두리) 아이콘+텍스트("↗ 공유")로 배치.
- **재사용 여부**: `KakaoShareButton`을 그대로 재사용한다. 새 공유 API/로직을 만들지
  않았다 — `handleShare`(navigator.share → 카카오 SDK → 클립보드 3단 폴백) 함수는 단
  한 글자도 바꾸지 않았다. 추가한 것은 선택적 `compact` prop 하나뿐이고, 이 prop이
  true일 때 반환하는 `<button>`의 스타일/라벨만 다르며 `onClick={handleShare}`는
  동일하다. `KakaoShareButton`을 쓰는 곳은 이 파일 전체에서 `apt-client.tsx` 하나뿐임을
  grep으로 재확인했고(다른 화면에 영향 없음), 기존 위치(`quickButtons` 패널 아래
  `.shareRow`)는 Hero로 옮겼으므로 제거했다(같은 기능을 두 곳에 중복 배치하지 않음).

## 5. 단지명 Hero

단지명(`displayName || aptName`, 기존 로직 그대로) · 지역(`regionName || firstTrade?.dong`,
새 변수 `heroRegionLabel`로 분리 계산 — 지오코딩에 쓰이는 `primaryAddress` 자체는 건드리지
않음) · "{준공년도}년 준공 · {세대수}" 요약 줄로 구성했다.

**동수는 표시하지 않는다.** 코드 전체(`aptInfo`, `Apartment` 테이블, `apt-building-info.ts`
응답)를 확인한 결과 이 페이지가 쓰는 데이터 파이프라인 어디에도 "동수"(건물 동 개수) 값이
없다(`ApartmentMaster.mainBuildingCount` 필드가 스키마에는 있으나 이 페이지와 연결돼
있지 않음 — 문서26/28이 이미 확인한 대로 `ApartmentMaster`는 이 페이지에서 미사용). 가짜
값을 만들지 않고 자연스럽게 생략했다.

**정밀도 버그 방지**: 준공년도를 문자열로 그대로 이어붙이면 소스에 따라 `aptInfo['사용승인일']`
가 이미 "년" 접미사를 포함해 "2022년년 준공"처럼 중복될 위험이 있어, `parseInt`로 정수화한
뒤 직접 "{연도}년 준공"으로 조립하도록 했다(`AptSpecGrid.tsx`가 같은 문제를 `parseInt`로
피하는 방식과 동일).

## 6. 최근 실거래가

기존 `latestPrice`(`filteredTrades[0].priceStr` 우선, 없으면 `trades[0].priceStr`) 계산
로직을 그대로 사용했다. 새 대표가격 계산·평균·median을 추가하지 않았고 API도 바꾸지
않았다. Hero 가격 핵심 블록에서 `.price` 클래스(font-size 2rem, 기존 값 그대로) 큰 숫자로
표시된다.

## 7. 매매/전세 토글

로직 무변경(`setTradeTypeFilter('매매'|'전월세')`, 기존 state/effect 그대로) — 시각적으로만
선택된 쪽 배경을 `white`에서 `var(--primary-color)`(+ 흰 글자)로 바꿔, AreaSelector가 이미
쓰던 "선택 시 초록 채움" 언어와 통일했다. 실측(로컬 프로덕션 빌드, 브라우저 실클릭)으로
전월세 클릭 시 가격("보 2억 9,000만")·라벨("최고 보증금/최저 보증금")·최고/최저값이 모두
정상 전환됨을 확인했다(§13-3 실측 참고).

## 8. 거래 메타정보 (면적·층·거래일)

기존 로직(`trades.length > 0`일 때만 렌더) 그대로 유지, 구분자만 "•"에서 지침 예시
("84.96㎡ · 12층 · 2026.08.03")와 통일하기 위해 "·"로 바꿨다(순수 문자 변경, 로직
영향 없음). `area`/`floor`/`tradeDate`는 `Trade` 타입상 항상 존재하는 필드라 개별 null
가드는 기존과 동일하게 두지 않았다(기존 코드와 동일한 전제).

## 9. 최고가/최저가

기존 계산·문구 그대로, 색상 추가 없음(원래도 빨강/파랑 등 가치판단 색이 없었다 — 확인
결과 수정 불필요). 가격 핵심 블록 안에서 `.price`보다 작은 폰트(0.95rem)로 한 단계 낮은
위계를 그대로 유지.

## 10. 평형 선택 위치

`AreaSelector`를 기존 "2구역 실거래 타임라인" 패널 상단에서 제거하고, 가격 핵심 블록
바로 다음(차트 직전)으로 옮겼다. `trades`/`selectedArea`/`onSelect` props는 동일 — 상태가
이미 부모(`apt-client.tsx`)에 있어 컴포넌트 자체는 수정하지 않고 렌더 위치만 옮겼다.
문서26이 지적한 평형 칩 라벨 중복 문제(§4-B-1)는 이번 STEP에서 그대로 재현되며(별도
STEP 대상), 손대지 않았다.

## 11. PriceTrendChart / 핵심 가격 지표

두 컴포넌트 모두 props·내부 로직 무변경, 렌더 위치만 평형 선택 다음으로 이동했다.
`InvestmentMetrics`는 원래도 4칸 컴팩트 grid(라벨 0.78rem, 값 0.95rem)라 추가 압축 없이
그대로 재사용했다.

## 14. 모바일 검증(도구 제약 재확인)

문서26/27/28과 동일하게, 이번 세션의 브라우저 자동화 창도 1536×864에 고정돼 있어

1. 실제 컴파일된 CSS 클래스에 `@media(max-width:768px)`/`(max-width:900px)` 블록의
   실제 속성값을 그대로 주입해(B0 STEP과 동일 기법) `Header` 하단탭바(`position:fixed;
   bottom:0; height:60px`)와 `StickyPriceBar`(`position:fixed; bottom:60px`)의 겹침
   여부를 기하학적으로 재검증 — **여전히 겹치지 않음**(`overlap:false`, `bar.bottom`
   ===`nav.top` 정확히 일치) — B1이 B0의 수정을 되돌리지 않았음을 확인.
2. `AptSpecGrid.module.css`의 `@media(max-width:640px)` 3열 그리드, `.heroTitle`에
   추가한 `@media(max-width:900px)` 폰트 축소(1.35rem→1.15rem) 등 코드상 존재하는
   반응형 규칙을 그대로 인용해 서술한다(실측은 아님).
3. 데스크톱(1536px 네이티브) 스크린샷으로는 3개 표본 모두 Hero/가격/평형/차트/지표/
   스펙그리드/퀵버튼까지 레이아웃이 깨지지 않음을 확인했다(§13).

매매/전월세 토글 → 가격이었다. 같은 Header 높이를 기준으로 역산하면 가격 도달 거리는
약 324px 안팎으로 추정된다(AptSpecGrid를 실제로 되돌려 재측정한 것이 아니라, 현재도
그대로 남아있는 AptSpecGrid 자체의 실측 높이 68px + 기존 wrapper padding/margin 값을
더한 계산 추정치임을 명시한다).

**결론**: 가격 도달 거리가 추정치 기준 약 130px가량 앞당겨졌고, 무엇보다 가격 앞에
나열되던 5칸 스펙 그리드(용적률·건폐율 등 전문 지표 포함)가 사라지고 단지명·지역·
준공/세대수 요약만 남아 "첫인상"의 정보 밀도 자체가 낮아졌다 — 문서26 §12 재설계
원칙 1("빠른 이해")과 부합하는 방향으로 개선됐다고 판단한다.
