# COMMUNITY EDITOR V2.1 — SIMPLE INLINE COMPOSER

- 기준 HEAD: `728029b` (main)
- 범위: **편집 화면 UX만**. DB schema·migration·`PostContentBlock`/`PostImage`·업로드/영수증·저장 API·권한·Storage 정책 변경 없음.

## 1. 왜 바꿨나

V2 편집기는 저장 구조(블록)를 그대로 화면에 드러냈다 — 블록마다 테두리, 블록 사이 "+ 내용 추가", 항상 보이는 ↑ ↓ 삭제,
"블록 1/25". 안전했지만 "블록을 조립하는 개발 도구"처럼 보였다. V2.1은 사용자에게 **일반 게시판 글쓰기**로 보이게 한다:
하나의 본문을 쓰다가 **커서 위치에서 [사진 추가]** 를 누르면 그 자리에 사진이 들어가고, 사진 아래에서 계속 쓴다.

## 2. 무엇이 같은가 (의도적으로 유지)

| 항목 | 상태 |

| 서버·DB | `post-write-handlers`·`post-write-db`·`content-blocks`·API route·schema 무변경 |

| 사진 파이프라인 | V1 압축·방향·EXIF 제거·1.5MB 그대로 |

## 3. 화면

```
제목
[📷 사진 추가 0/5]
┌───────────────────────────────┐
│ 오늘 광복동에 다녀왔어요.        │   ← 글 입력칸(테두리 없음)
│ 사람이 생각보다 많았습니다.      │
│ [사진]                          │   ← 게시글과 같은 모습의 사진 카드
│ 애슐리 내부는 이런 분위기였어요.  │   ← 사진 아래 이어 쓰기
└───────────────────────────────┘
```

- 본문 전체가 하나의 입력 상자처럼 보인다(바깥 테두리 1개, 포커스 시 테두리 색만 변경). 안의 글 입력칸은 테두리·배경 없음, 16px.
- 제거한 것: "+ 내용 추가", 항상 보이는 ↑ ↓ 삭제, "블록 n/25", 블록 라벨.
- 사진을 탭하면 사진 위에 작은 버튼(**이미지 위로 이동 / 이미지 아래로 이동 / 이미지 삭제**, 각 44px)이 나타나고, 사진 밖을 누르면 사라진다.
- 블록 25개 상한은 내부 검사로 유지하고, 닿았을 때만 "내용을 더 추가할 수 없어요."를 보인다.
- 빈 본문 placeholder "내용을 입력해주세요", 사진 바로 아래 빈 칸은 "이어서 작성해주세요".

## 4. 커서 위치 삽입

순수 함수 `insertImagesAtCursor` (`src/lib/community/block-editor-state.ts`).

| 상황 | 결과 |
|---|---|
| 글 중간 커서 | 그 위치에서 글을 나눠 `글 → 사진 → 글` |
| 커서가 맨 앞 | `사진 → 글` |
| 커서가 맨 끝 | `글 → 사진 → (빈 이어 쓰기 칸)` |
| 본문이 비었음 / 커서 없음 | `사진 → (빈 이어 쓰기 칸)` (사진부터 시작) |
| 여러 장 선택 | 커서 위치에 선택 순서대로 `사진 → 사진 → 사진`, 그 뒤 이어 쓰기 칸 |
| 사진을 선택한 상태 | 그 사진 바로 뒤에 삽입 |
| 5장 초과 | 남은 장수만 넣고 "사진은 최대 5장까지 올릴 수 있어요." |

- **선택 영역 정책**: 글자를 선택한 채 사진 추가 → 선택 글자는 지우지 않고 **selectionEnd 뒤**에 삽입.
- **줄바꿈**: 나누는 자리의 줄바꿈 **1개만** 사진이 대신한다(줄 끝이면 뒤쪽 첫 줄바꿈, 줄 맨 앞이면 앞쪽 끝 줄바꿈).
  그 밖의 줄바꿈·빈 줄·공백은 그대로다. 사진을 지우면 줄바꿈 1개로 다시 합쳐져 **원래 글과 같아진다**(테스트로 확인).
  단, 저장할 때 서버 규칙대로 각 글 블록의 앞뒤 공백은 정리된다(V2와 동일).
- 삽입 후 커서는 사진 바로 아래 글 입력칸의 맨 앞으로 옮긴다.

### 커서 보존

- 각 글 입력칸에서 `select / keyup / click / focus / blur / change` 때마다 (입력칸, selectionStart, selectionEnd)를 기억한다.
  모바일에서 버튼을 탭해 입력칸이 blur돼도 마지막 커서가 남는다.
- 데스크톱은 버튼 `mousedown`을 막아 입력칸 포커스를 유지한다.
- 버튼을 누르는 순간 커서를 확정해 두고, 사진 선택창에서 돌아오면 그 입력칸이 남아 있을 때 **현재 선택 위치를 다시 읽어** 삽입한다.

## 5. 합치기

`normalizeComposerBlocks` — 모든 구조 변경(삽입·사진 삭제·사진 이동·수정 화면 불러오기) 뒤에 적용:

1. 인접한 글 블록은 하나로 합친다(한쪽이 비면 그대로, 둘 다 있으면 줄바꿈 1개로 연결).
2. 마지막이 사진이면 이어 쓰기용 빈 글 입력칸을 둔다.

빈 글 블록은 저장 시 버려지므로 이 규칙은 저장 결과를 바꾸지 않는다. 이탈 경고용 스냅샷도 빈 칸을 무시해, 수정 화면을 열기만 해서는 "수정됨"이 되지 않는다.

사진 이동은 V2 `moveBlock`을 그대로 쓰고 이동 후 합치기를 적용한다(사진이 글 블록 하나를 건너뛰는 단위).

Backspace로 앞 블록과 합치기는 **넣지 않았다** — 모바일 IME에서 keydown이 조합 중 229로 오는 등 오동작 위험이 크고, 핵심은 커서 위치 삽입이다.

## 6. 한글 IME

- 입력 중에는 블록 구조를 바꾸지 않는다(onChange는 해당 입력칸 값만 교체).
- `compositionstart`~`compositionend` 사이에 사진 선택이 끝나면 삽입을 미뤘다가 조합이 끝난 뒤 실행한다.
- 나누기는 사진 선택창에서 돌아온 시점(조합이 확정된 뒤)에만 일어난다.
- 실제 삼성·구글 키보드 동작은 기기 QA 필수.

## 11. 알려진 한계

- Backspace 블록 합치기 없음(사진은 탭 → 삭제).
- 사진 이동은 글 블록 한 개 단위다. 문장 가운데로 정확히 옮기려면 삭제 후 커서 위치에 다시 넣는다.
- 사진을 지운 직후 글을 누르지 않고 바로 [사진 추가]하면 본문 끝에 들어갈 수 있다. 마지막 커서가 사진 아래 칸에 있었다면 그 칸이 앞 글에 합쳐져
  없어졌기 때문이다(커서가 가리키는 칸이 없으면 끝에 넣는 규칙). 글을 한 번 누르면 그 위치에 들어간다. → **V2.1A에서 수정**(`COMMUNITY_EDITOR_V2_1A_PHOTO_REPLACE_INSERTION_FIX.md`).
- 드래그 정렬·자동 임시저장 없음(V2와 동일).
- 한글 IME·갤러리 복귀 후 커서·키보드 위 버튼 접근성은 실제 Android 기기 확인이 필요하다.
