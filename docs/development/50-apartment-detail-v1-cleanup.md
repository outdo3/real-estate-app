## APT DETAIL V1 = LOCKED (2026-08-18)

이 STEP의 배포와 production 4개 표본단지(대신푸르지오1차/명륜아이파크
1단지/엘지메트로시티3/고원3단지아파트) 최종 확인을 끝으로 아파트
상세페이지 V1을 LOCK한다.

**LOCK의 의미**:
1. 신규 기능을 임의로 추가하지 않는다.
2. BLOCKER, 실제 데이터 오류, 심각한 UX 버그가 아닌 이상 추가 개발을
   하지 않는다.
3. 단순 아이디어/개선사항은 V2 backlog로 보낸다(§V2 보류 항목 참고).
4. 메인 UI/홈 UX 등 다른 화면의 V1 완성을 우선한다.
5. 실사용 중 발견되는 BLOCKER는 예외적으로 즉시 수정할 수 있다.

**알려진 V1 한계(LOCK을 막지 않음, 기록만 유지)**:
- 고원3단지 등 거래 0건 단지에서 Hero "최근 실거래가"가 "조회 중..."에
  멈추는 기존 동작(이번 STEP에서 발견, 미수정)
- 평면도 데이터 없음(FloorPlanPanel 컴포넌트는 보존, 노출만 제거)
- 커뮤니티시설 데이터 없음(coverage 0/31, 관련 코드는 보존)
- 일부 TAGO 정류장의 노선 미등록(STEP47에서 확인된 한계)
- 부산진화물역 등 비여객역 필터 한계(STEP47에서 확인, 안전한 일반
  규칙 없어 미조치)
- 금호어울림 등 모호한 단지명 검색 한계(과거 STEP에서 부분 해결)
- 빠른검색 뒤로가기 1회 무효 소비(과거 STEP에서 확인된 한계)
- 출퇴근 접근성/점수체계/이집 브리핑 고도화/공항 접근성/실시간 버스

**다음 큰 개발 단계**: MAIN UI / HOME UX. 다음 세션은 상세페이지가
아니라 메인 UI 전수점검부터 시작한다.

## 단지 브리핑 판단 (§5)

**A. 유지 — 수정 없음.** `apt-brief.ts`를 코드로 다시 읽었다:
- 실제 사용 데이터: `filteredTrades`(화면에 적용된 필터 기준),
  `aptInfo['세대수']`, `trades[0].buildYear`.
- 규칙 기반(하드코딩된 if/else 임계값)이며 LLM/외부 API 호출이 전혀
  없다.
- 소표본 왜곡 이미 방지돼 있음: 최신/최고 단일 거래 비교가 아니라
  N-샘플(최대 3건) 평균으로 상승/하락률 계산(주석에 실측 사례로
  문서화됨 — 21건 중 단일 이상치로 57% 상승이 잘못 계산됐던 것을
  고친 기록), 거래 활발도도 세대수 대비 비율로 정규화(절대 건수만
  쓰면 대단지/소단지 왜곡 — 이미 문서화된 과거 버그 수정).
- Chart(원시 시계열)/Metrics(갭 금액·전세가율)를 그대로 반복하지 않고,
  "약 14.2% 상승 추세", "1,609세대 규모의 준신축 단지", "22건 거래되어
  활발한 편" 같은 **합성된 해석 문장**을 만들어 새로운 정보를 준다.
- 데이터 부족 시(고원3단지아파트 실측: 거래 0건) 억지로 문장을 만들지
  않고 "총 163세대 규모의 단지입니다" 하나만 정직하게 보여준다.

AI 브리핑을 새로 만들지 않았고, OpenAI/Gemini 호출을 추가하지
않았으며, 버스/생활편의 데이터를 브리핑에 새로 연결하지도 않았다(§5
지시 그대로 준수).

충분하다."
