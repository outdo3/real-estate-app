## 1. 목적

이집에 **실제 외부 파트너 CTA**를 처음 붙인다. 파일럿 파트너는 한 곳이다.

핵심 흐름:

```
이집에서 의사결정 → 등기/법무 질문 발생 → 카카오 또는 전화로 파트너에게 직접 연결
```

**click-out 모델이다.** 이집은 이 흐름에서 고객 정보를 하나도 받지 않는다.

---

## 2. 클릭은 상담이 아니다 (§13)

이 STEP의 가장 중요한 제품 의미다.

우리가 실제로 알 수 있는 것은 **"사용자가 버튼을 눌렀다"** 까지다. 그 뒤에 상담이 이뤄졌는지, 수임으로 이어졌는지는 **확인할 수단이 없다.**

그래서:

| 쓰는 이름 | 쓰지 않는 이름 |
|---|---|
| `partner_cta_impression` | `partner_lead` |
| `partner_cta_click` | `partner_conversion` |
| | `consultation_complete` |
| | `call_connected` |

성과처럼 들리는 이름을 붙이면 **언젠가 그 숫자가 성과로 읽힌다.** 성사 귀속은 확인 수단이 생긴 뒤의 별도 STEP이다. 이 규칙은 주석이 아니라 테스트로 고정돼 있다(`partners.test.ts`).

## 3. 파트너 모델

`src/lib/partners/types.ts` / `config.ts` — **타입이 붙은 설정 모듈 하나.** DB를 쓰지 않는다.

한 행짜리 테이블을 위해 스키마와 migration을 만들 이유가 없고, 파트너가 늘어도 배열에 객체를 추가하면 된다. 파트너 정보가 여러 컴포넌트에 흩어지면 번호가 바뀌었을 때 어디를 고쳐야 하는지 아무도 모르게 되므로 **단일 출처**로 둔다.

```
PartnerConfig { id, type, displayName, phone, displayPhone, kakaoUrl, enabled, placements }
```

확인되지 않은 내용을 광고 문구로 쓰면 **그건 우리가 지어낸 약속**이 된다. 추가 정보는 파트너가 확인해 준 뒤에만 들어온다. 이 규칙도 테스트로 고정돼 있다(설정 JSON에 금지 문구가 있으면 실패).

## 5. 리포트 내보내기 (§8)

**현재 리포트에는 파트너 CTA가 없다.** 따라서 PNG/PDF 내보내기에도 없다(실측: `/report/apt/...`, `/report/city/busan`, `/report` HTML에서 0건).

그래도 카드는 **이중으로** 내보내기에서 빠지도록 만들어 두었다:

1. 루트에 `data-export-exclude` — `dom-to-png.ts`의 기존 제외 메커니즘(PNG 캡처)
2. `@media print { display: none }` — `globals.css`의 `[data-export-exclude]` 규칙과 중복 보장(PDF 인쇄)

즉 나중에 리포트에 얹더라도 **기본값이 "내보내기에서 제외"** 다. 리포트 신뢰 레이어는 깨끗하게 유지된다.

기존 내보내기 시스템에 **전용 광고 슬롯은 없다**(`AdContainer`는 AdSense 자리이고 리포트 시트에 쓰이지 않는다). 리포트에 파트너 영역을 두려면 별도 설계 판단이 필요하다.

## 6. 분석 (§9~§12)

### 이벤트

| 이벤트 | 언제 |
|---|---|
| `partner_cta_impression` | 카드가 **실제로 화면 절반 이상 보였을 때**, 마운트당 1회 |
| `partner_cta_click` | 카카오/전화 버튼을 눌렀을 때 |

### 파라미터 (GA4)

| 키 | 값 | 성격 |
|---|---|---|
| `partner_type` | `legal_office` | 고정 enum |
| `partner_id` | `hwangbo-jaeho-legal` | 고정 slug |
| `placement` | `finance` / `apt_detail` | 고정 enum |
| `channel` | `kakao` / `phone` | 고정 enum (click 전용) |

`partner_id`와 `channel`을 `GA_PARAM_ALLOWLIST`에 추가했다. 나머지 둘은 이미 있었다.

**절대 나가지 않는 것**: 전화번호 · 카카오 오픈채팅 주소 · 상호 · 주소 · 이용자 입력 · 자유 텍스트. allowlist에 키가 없어 구조적으로 막히고, 값이 전화번호처럼 보이면 `PHONE_LIKE` 검사가 한 번 더 버린다(테스트로 확인).

### 두 시스템 — 그리고 알려진 비대칭

| 레이어 | 무엇이 남나 |
|---|---|
| 1st-party (`/api/log/event` → `PageView`) | **이벤트 이름만.** 이 라우트는 `complexId`/`aptName` 외에 저장할 컬럼이 없다 |
| GA4 | 이름 + 위 4개 파라미터 전부 |

즉 **"몇 번 눌렸나"는 양쪽에서 보이지만, "카카오냐 전화냐 / 어느 자리에서냐"는 GA4에서만 보인다.**

이건 스키마를 바꾸지 않기 위한 의도적 선택이다. 컬럼을 새로 만들거나 `actionType`을 억지로 재활용하지 않았다(서버가 `NEXT_ACTION_TYPES`로 검증하므로 후자는 조용히 버려진다). 전체 분해가 1st-party에도 필요해지면 Analytics V2의 전용 Event 저장소로 옮길 때 자연스럽게 해결된다.

### 중복 방지 (§10)

- 노출은 `IntersectionObserver`(threshold 0.5) + `useRef` 가드로 **마운트당 1회**. 리렌더나 화면을 들락날락해도 늘지 않는다. 첫 노출 후 `observer.disconnect()`.
- `IntersectionObserver`가 없으면 **아무것도 보내지 않는다.** 노출은 "실제로 보였다"는 뜻이어야 하므로, 확인할 수 없을 때 일단 세는 쪽이 더 나쁘다.

### 클릭 처리 (§11/§15)

```
onClick → trackEvent(...) → 기본 동작 그대로 진행(막지 않음)
```

`preventDefault`를 쓰지 않는다. `gaEvent`는 `dataLayer`에 동기적으로 쌓이고 1st-party `fetch`는 `keepalive`라 페이지를 떠나도 살아남는다. 사용자를 한 프레임도 붙잡지 않는다.

**추적 리다이렉트를 끼우지 않았다.** 링크는 파트너에게 곧장 간다.

## 7. 개인정보 경계 (§14)

### 판정: **개인정보처리방침 수정 불필요**

이 STEP은 **새로운 개인정보 수집 항목을 만들지 않는다.**

| 확인 항목 | 결과 |
|---|---|
| 고객 입력 폼 | 없음. 이름·전화·이메일·상담 내용 전부 받지 않는다 |
| 이집이 파트너에게 넘기는 정보 | **없음.** 사용자가 직접 카카오/전화로 연결한다 |
| 새로 수집되는 개인정보 항목 | 없음 |
| 클릭/노출 분석 | 기존 "서비스 이용 기록" 범위. 방침 1-나와 7항(Google Analytics 고지)이 이미 포함 |
| 새 쿠키 | 없음 |
| 새 수탁업체 | 없음(위탁하는 정보가 없다) |

방침 7-나는 이미 "이집이 GA로 보내는 값에서 이용자 입력은 제거한다"고 적고 있고, 파트너 파라미터는 전부 고정 enum/slug라 그 서술과 충돌하지 않는다.

→ §14의 "새 개인정보 항목이 없으면 방침을 다시 쓰지 않는다"에 해당. **수정하지 않았다.**

### LEGAL_REVIEW_RECOMMENDED

법적 결론을 지어내지 않는다. 아래는 운영자/법률 검토 사항이다.

1. **광고 표시.** 카드 최상단에 `광고·제휴` 배지를 항상 먼저 노출하고, 하단에 "이집이 제공하는 서비스가 아니며, 상담 내용과 비용은 해당 사무실에 직접 확인해 주세요"를 명시했다. 표시 의무를 충족하는지의 최종 판단은 운영자 몫이다.
2. **법무사 광고 규정.** 법무사 업종에는 직역별 광고 규정이 있을 수 있다. 문구·형식이 그 규정에 맞는지는 **파트너와 운영자가 확인**해야 한다. 이집이 임의로 판단하지 않는다.
3. **제휴 관계 성격.** 수수료/대가 구조가 생기면 표시 문구를 다시 검토해야 한다. 현재 설정에는 대가 관련 내용이 없다.

## 11. 알려진 한계

1. **channel/placement는 GA4에서만 보인다** — 1st-party 라우트에 저장할 컬럼이 없다(§6 비대칭).
2. **클릭 이후는 측정할 수 없다.** 카카오 오픈채팅에 들어갔는지, 전화가 연결됐는지, 상담이 성사됐는지 이집은 알 수 없다. 이게 click-out 모델의 본질적 한계이고, 그래서 이벤트 이름이 `click`이다.
3. **모바일 QA가 렌더링 기반이 아니다**(§9).
4. **파트너 회전/가중치 없음.** 자리마다 첫 번째 일치 파트너 한 곳만 나온다. 파트너가 늘면 `getPartnerForPlacement` 하나만 고치면 된다.
5. **광고 차단기가 GA4를 막으면** 그 사용자의 파트너 이벤트는 GA4에 안 잡힌다(1st-party는 영향 없음).
6. **관리자 대시보드에 파트너 전용 화면이 없다**(§20에 따라 만들지 않았다). 현재는 GA4에서 본다.
