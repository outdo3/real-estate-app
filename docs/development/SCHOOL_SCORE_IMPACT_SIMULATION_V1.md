## 1. 방법론

**프로덕션 점수 로직을 복제하지 않았다.** 실제 운영 함수를 그대로 import해 돌렸다:

- `rankFeature` / `computeSchoolAccessCategory` / `resolvePeerPoolLevels` / `absoluteSchoolDistanceBand`
- 바꾼 것은 **입력 한 필드뿐** — `nearestElementaryDistanceM`
- 가중치·임계값·peer 정의·다른 feature는 전혀 건드리지 않음

스크립트: `scripts/apartment-score/school-distance-impact-simulation.ts` (SELECT만, DB 쓰기 0건)

### 현재 점수 경로 (§1 — 실제 코드 기준)

```
ApartmentLocationFeature.nearestElementaryDistanceM   (Kakao SC4, 반경 1km, size=15 단일 페이지)
  → rankFeature(direction='lowerIsBetter', treatCompleteNullAsWorst=true)
     · 선형(로그 변환 대상 아님)
     · tie-aware 평균순위 percentile
     · peer pool = LOCAL(umdName) → SIGUNGU → REGION_WIDE(현재 SIGUNGU와 동일)
  → scoreFromPercentile: 5 + percentile/100 × 90
  → schoolAccess 카테고리 = nearestElementaryDistanceM 60 : elementaryCount1000m 40
  → 총점 = Σ(baseWeight/usedWeightSum × categoryScore),  schoolAccess baseWeight = 15
```

**즉 이 한 필드가 총점에서 갖는 몫은 15% × 60% = 9%다.** 아래 총점 델타는 5개 카테고리가 모두 채점되는 경우(usedWeightSum=100)를 가정한 값이며, 일부만 채점되는 단지는 분모가 작아져 **영향이 더 커진다**.

점수는 **테이블에 저장되지 않고 요청 시 계산된다**(`ApartmentScore` 모델 없음). 출처를 바꾸려면 점수를 재계산하는 게 아니라 **feature를 다시 수집**해야 한다.

- 200/400/650은 유지 가능 — 분포가 그대로다
- **933(FAR 상한)은 무효** — 인공적 상한을 실측값처럼 쓴 값이고, NEIS에서는 그 위에 36건이 실재한다

## 7. null 의미 감사 (§11)

현재 동작(`percentile.ts` + `school-access.ts`):

```
qualityFlag='complete' + nearestElementaryDistanceM=null
  → treatCompleteNullAsWorst=true
  → sentinel = 관측 최댓값 + span×0.5 + 1  (순위에 "가장 나쁨"으로 포함)
```

코드 주석은 이 상태를 **"확인된 부재"**(실제로 반경 내 대상이 없음)라고 설명한다.

**그런데 실제 의미는 "1km 안에서 못 찾았다"이다.** 20건 전부 NEIS로는 학교가 실재한다(1,052~1,422m).

| 질문 | 답 |
|---|---|
| null이 "학교 없음"인가? | **아니다** — 20건 전부 학교가 실재한다 |
| "검색 실패"인가? | **그렇다** — 반경 밖이라 못 찾은 것 |
| "최악 점수"로 쓰이는가? | **그렇다** — sentinel로 순위 최하위에 들어간다 |
| 중립인가? | 아니다 |

→ **데이터 신뢰 문제로 플래그한다.** 방향은 우연히 맞다(멀다 = 나쁨). 그러나 **크기가 임의적**이다 — sentinel은 실제 1,359m가 아니라 "관측 최댓값보다 span의 절반만큼 더 나쁜 값"이라는 계산상의 자리표시자다. 이 STEP에서는 고치지 않는다(지시 §11).
