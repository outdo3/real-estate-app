# MAP_UX_V2 — 모바일 마커 밀도 / 매물 종류 구분 / 검색 핸드오프

작성일: 2026-09-07
시작 HEAD: `c2e0e09` (branch `main`, OFFICETEL_MAP_LAYER_V1 직후)

## 문제

OFFICETEL MAP LAYER V1 배포 후 실제 모바일에서 지도가 읽히지 않았다. 추측이 아니라
Production 실측으로 먼저 숫자를 남겼다.

| 케이스 | 마커 수 | 마커가 덮은 화면 면적 |
| --- | --- | --- |
| 부산 서구 / 레벨 4 / 360px / 두 레이어 ON | 36 (아파트 19 + 오피스텔 17) | **35.7%** |
| **부산진구 서면 / 레벨 3 / 360px / 두 레이어 ON** | **67** (아파트 9 + 오피스텔 58) | **80.0%** |
| 같은 조건 375px | 67 | 76.7% |
| 같은 조건 390px | 67 | 73.8% |

§11의 기준(40~50% 초과 = UX FAIL)을 크게 넘겼다. 원인은 셋이었다:

1. 아파트와 오피스텔이 **동시에** 켜질 수 있었다(독립 토글).
2. 축소해도 **낱개 마커를 전부** 그렸다(아파트는 묶음 개념 자체가 없었음).
3. 낱개 오피스텔 칩에 **이름표**를 붙여 칩 하나가 ~112px를 차지했다.

부수적으로 오피스텔의 teal(#0f766e)이 이집 Green과 너무 가까워 작은 화면에서 종류가
구분되지 않았고, 우측 라벨 "단지"는 무엇을 뜻하는지 모호했다.

## 결정과 구현

### §2 라벨

`단지` → `아파트`. 화면 라벨만 바꾸고 내부 state 키(`apt`)는 그대로 뒀다.
향후 용어 체계는 아파트 / 오피스텔 / 생활형숙박시설 / 전체이며, 뒤의 둘은 이 STEP 범위가 아니다.

### §3 매물 종류 시각 체계

| | 아파트 | 오피스텔 |
| --- | --- | --- |
| 색 | 이집 Green(기존 유지) | **파랑** `#1d4ed8` / 선택 `#1e3a8a` |
| 아이콘 | `Home` | `Building2` |
| 모양 | 둥근 말풍선(꼬리 있음) | 각진 사각 |
| 내용 | 가격 + 면적 | 이름(확대 시) — **가격 없음** |

색만으로 구분하지 않는다: 아이콘·모양·가격 유무가 함께 다르다.

### §4 포커스 모드

아파트와 오피스텔은 **동시에 켜지지 않는다**. 이미 활성인 쪽을 다시 눌러도 끄지 않는다
(끄면 어느 매물도 없는 빈 지도가 남는다) — 항상 정확히 하나가 켜져 있다. 기본은 아파트.
학교/재개발/경공매/생숙은 기존 독립 토글 그대로다.

우측 칩은 아파트/오피스텔만 `role="radio"` + `aria-checked`로 노출해 배타 관계를
보조기술에도 전달한다. 나머지는 기존대로 `aria-pressed`다.

### §6/§9 확대 단계별 밀도

카카오맵 레벨은 **숫자가 작을수록 확대**이며 기본 진입 레벨은 4다. 임계값은 실측으로 정했다.

| 레벨 | 아파트 | 오피스텔 |
| --- | --- | --- |
| ≤ 2 | 낱개 가격 칩(단지명 포함) | 낱개 칩 + **이름** |
| 3 | 낱개 가격 칩 | 낱개 **아이콘 칩**(이름 없음) |
| 4 ~ 6 | **묶음 개수 배지**(누르면 확대) | **묶음 개수 배지**(누르면 확대) |
| > 6 | 묶음 개수 배지 | 그리지 않음 + 확대 안내 |

"낱개로 그린다"와 "이름을 쓴다"를 **다른 결정**으로 분리한 것이 핵심이다. 레벨 3에서
낱개 63개를 그리는 것 자체는 감당되지만(25.4%), 같은 63개에 이름을 붙이면 71.3%가 된다.
위치는 다 보여주고 이름만 한 단계 더 확대해야 나온다 — 정보가 사라지지 않는다.

오피스텔만 레벨 7 이상에서 사라지는 이유: 마커 데이터가 **시군구 단위**라 그보다 넓은
화면에서는 "이 지역에만 오피스텔이 있다"는 잘못된 인상을 준다. 지어내는 대신 안내한다.

### §8 동일 좌표 다중 master

부산 실측 32그룹 / 79건 / 최대 5개. **픽셀 클러스터링 이전에** 좌표가 완전히 같은
master들을 하나의 표시 그룹으로 접는다(`groupByExactCoordinate`). 확대해도 절대 갈라지지
않는 겹침이므로 부채꼴로 펼쳐봐야 서로를 가릴 뿐이다.

- 화면에 그려지는 것: 겹친 카드 모양의 개수 배지 하나(확대로 풀리는 클러스터 배지와
  그림자 모양으로 구분 — 색만으로 구분하지 않는다)
- 누르면: **선택 목록 카드**. 각 항목이 표시명 / 동 / 규모(호)를 보여주고 자기
  `officetelId`로 이동한다
- 좌표 키는 원본 숫자 그대로다. 반올림해서 묶으면 "가까운 다른 건물"까지 한 위치로
  만들어버린다(테스트로 고정)

**데이터는 합치지 않는다.** 그룹은 순전히 표시 단위이며 멤버는 각자 identity를 유지한다.

### §12 오피스텔 검색 핸드오프

핸드오프가 미완이었던 **직접 원인 두 가지**를 찾아 고쳤다.

1. `/map`의 `ApartmentAutocomplete`에 `includeOfficetel` 프롭이 빠져 있었다. 기본값이
   `false`라 **오피스텔 결과가 목록에 아예 나오지 않았다** — placeholder는
   "아파트, 오피스텔 단지명 검색"이라고 약속하면서.
2. 오피스텔 결과는 `lat: 0, lng: 0`으로 내려왔다. 검색 read 계층이 좌표를 select하지
   않았기 때문이다. 지도는 이동할 좌표 자체가 없었다.

수정: `searchOfficetels`가 저장 좌표(`latitude`/`longitude`)를 함께 반환하고,
autocomplete가 그대로 전달하며, 지도는 다음 순서로 처리한다.

```
검색 결과(OFFICETEL)
→ 오피스텔 포커스 ON / 아파트 OFF (진행 중이던 아파트 응답은 순번 무효화)
→ 저장 좌표 확인(없으면 이동하지 않고 안내)
→ panTo + 낱개 마커가 보이는 레벨까지 확대
→ 해당 구 마커 조회
→ 도착 후 **officetelId가 정확히 일치하는** 마커만 선택
```

이름/부분주소/최근접 좌표/첫 마커로 대체하지 않는다. 못 찾으면 아무것도 선택하지 않는다
(`findExactOfficetelMarker`가 강제, 테스트 고정). 좌표가 없는 master(부산 8건)를 고르면
`"{이름}은(는) 위치 정보가 없어 지도에 표시할 수 없습니다."`를 띄우고 이동하지 않는다.

### §14 stale / race 안전성

레이어 전환과 검색 핸드오프가 **반대편 레이어의 진행 중 요청을 순번으로 무효화**한다
(`requestSeqRef` / `officetelSeqRef`를 각각 증가). 기존 응답 가드
(`isStaleMarkerResponse`)가 그 순번을 보고 늦게 도착한 응답을 버린다.

`refreshActiveLayers`는 이제 `focus`를 인자로 받는다. 검색 핸드오프처럼 **같은 커밋 안에서
포커스를 막 바꾼** 호출부가 아직 갱신되지 않은 `layers` 클로저를 읽어 엉뚱한 레이어를
조회하는 것을 구조적으로 막는다.

### §17 터치 타깃

우측 레이어 칩 높이 33px → **44px**(실측). 칩이 커진 만큼 세로 간격을 0.5rem → 0.35rem로
줄여 컨트롤 열 전체 높이 증가를 최소화했다. 오피스텔 카드의 상세보기/닫기는 V1에서 이미
44px다.

### §18 향후 composite 대비

`전체` 모드와 GREEN+BLUE 합성 마커는 **구현하지 않았다**(범위 밖). 다만 구조는 준비됐다:
색은 상수 하나(`OFFI`)로 모여 있고, 표시 그룹(`groupByExactCoordinate`)이 identity를
합치지 않은 채 묶음을 만드는 방식이 이미 자리잡았다. 원칙은 그대로다 —
**DATA: separate / MAP PRESENTATION: may group.**

## 알려진 제한

- `전체`(아파트+오피스텔 동시) 모드와 합성 마커는 미구현(의도적 범위 밖).
- 오피스텔은 레벨 7 이상에서 표시되지 않는다(데이터가 시군구 단위이기 때문).
- 오피스텔 마커에는 가격이 없다(원천에 마커용 대표가가 없음 — 지어내지 않는다).
- 생숙/재개발/경공매 레이어는 여전히 데이터 미연동 안내만 뜬다.
