# COMPETITOR REVERSE ENGINEERING V1

## 1. Executive Summary
현재 이집(e-jip)은 기능적으로 호갱노노, 아실, 부동산지인이 제공하는 대부분의 데이터를 확보하고 있으며, 커뮤니티, 통계, AI 검색 등 차별화된 인프라를 갖추고 있습니다(AUTH/MY V1까지 완료). 그러나 현재의 정보 나열식 구조로는 사용자가 "그래서 이 집을 사야 하는가?"라는 최종 의사결정을 내리기 위해 여전히 다른 앱을 교차 검증해야 하는 한계가 있습니다. 본 문서는 주요 경쟁사의 의사결정 흐름을 역설계하여, 이집이 "해석과 결론을 제공하는 유일한 세 번째 서비스"로 도약하기 위한 UI/UX V2 및 HOME V2의 설계 근거를 제시합니다.

## 2. Product Thesis
- **이집은 단순 부동산 정보 나열 서비스가 아니다.**
- **핵심 흐름**: 데이터 → 해석 → 비교 → 추천 → 행동
- **단기 목표**: 사용자가 아실/호갱노노와 함께 반드시 여는 "세 번째 서비스" (해석을 위해 여는 앱).
- **장기 목표**: "이집 하나만 열어도 아실/호갱노노를 더 열 필요가 없다" (데이터 수집부터 결론까지 완결되는 앱).
- **원칙**: 경쟁사의 기능을 단순 복제하지 않는다. 그들이 사용자에게 떠넘기는 '해석의 부담'을 이집이 대신 처리한다.

## 3. User Decision Journey
부동산 탐색 사용자의 이상적/실제 여정은 다음과 같습니다.
1. **발견 (Discovery)**: 예산과 지역을 바탕으로 후보군 탐색 (지도, 조건 검색)
2. **검증 (Validation)**: 후보 단지의 실거래가 흐름, 학군, 교통, 호재 확인
3. **비교 (Comparison)**: 최종 후보 2~3개 단지를 놓고 우위 평가
4. **자금 (Financing)**: 해당 단지를 매수/전세하기 위한 실제 필요 자금 계산
5. **결정 (Decision)**: 시장 상황(거시)과 단지 가치(미시)를 종합하여 결론 도출

## 4. Hogangnono Analysis
- **첫 화면 구조**: 현재 위치 기반의 지도로 즉시 진입하여 시각적 직관성 극대화.
- **검색 UX**: 단순하고 빠르며, 검색어 자동완성과 최근 검색어 접근이 용이함.
- **단지 상세 IA**: 실거래가 차트가 최상단에 위치하며, 하단으로 갈수록 학군, 일조량, 리뷰 등 생활 밀착형 정보 배치.
- **강점**: 훌륭한 시각화(일조량, 경사도 등), 강력한 알림 기능, 활성화된 거주민 리뷰.
- **약점**: 거시적 시장 흐름(공급량 등) 파악이 어렵고, 리뷰의 객관성이 떨어짐(편향된 정보).
- **사용자에게 떠넘기는 부분**: 쏟아지는 리뷰와 필터링된 호재 속에서 '진짜 가치'를 가려내는 것은 사용자의 몫.

## 5. Asil Analysis
- **데이터 밀도**: 공급물량, 갭투자 증감, 미분양, 외지인 거래 등 투자 목적의 데이터 밀도가 매우 높음.
- **강점**: 복수 단지 가격 비교 차트, 학업성취도 기반 학군 정보 등 '분석'에 최적화.
- **약점**: UI가 모바일 환경에서 지나치게 빽빽하고 표 중심으로 구성되어 초보자에게 위압감을 줌 (Steeper learning curve).
- **왜 어렵게 느껴지는가**: 데이터를 '가공하지 않고 원형(Table/Chart) 그대로' 던져주기 때문.

## 8. UX Friction Audit
사용자가 집을 판단할 때 겪는 15가지 마찰(Friction):
1. **맥락 단절**: A아파트 보다가 B아파트 비교 시 탭 이동/뒤로가기로 인한 맥락 상실.
2. **해석 강요**: 공급물량 차트를 보여주고 "이게 가격에 미치는 영향"은 설명해주지 않음.
3. **자금 계산 분리**: 아파트 가격 확인 후, 별도의 계산기 앱(또는 부동산도구 탭)을 열어 DSR과 LTV를 계산해야 함.
4. **평형 전환의 피로도**: 84㎡를 보다가 59㎡로 바꿀 때 차트/데이터가 초기화되거나 딜레이 발생.
5. **정보 과적재**: 지도 위에 가격, 학구도, 상권, 호재 아이콘이 겹쳐서 가독성 훼손.
6. **편향된 정보**: 커뮤니티/리뷰의 "우리 아파트 최고" 글로 인해 객관적 단지 평가 방해.
7. **비교의 한계**: 차트 선 겹치기 외에, 생활/교통/학군의 다면적 비교가 불가능함.
8. **표 중심의 모바일 UI**: 아실 등에서 모바일에 억지로 구겨 넣은 표를 가로로 스크롤해야 하는 피로감.
9. **반복 정보**: 다른 탭/메뉴를 눌러도 결국 실거래가 리스트가 중복으로 나옴.
10. **모호한 학군 지표**: "서울대 몇 명" 데이터는 있지만, 초등학생 자녀를 둔 부모에게 실질적인 통학로 안전도 정보 부족.
11. **목적 불일치**: 실거주 매수자와 갭투자자가 동일한 화면과 동일한 지표를 강제로 봐야 함.
12. **지역 거시 데이터 접근성**: 특정 단지를 보다가 "근데 이 동네 전체 분위기는?"을 알기 위해 완전히 다른 메뉴로 나가야 함.
13. **뒤로가기 늪**: 꼬리에 꼬리를 무는 단지 클릭 후 메인으로 돌아가기 위해 뒤로가기를 10번 눌러야 함.
14. **부동산 용어 장벽**: 건폐율, 용적률, 전세가율 등의 용어가 초보자에게 직관적이지 않음.
15. **의사결정 보류**: 데이터를 다 보고도 "그래서 사야 되나?"에 대한 답이 없어 결국 결정을 보류함.

## 9. Why Users Reopen Competitors
현재 이집을 본 뒤에도 사용자가 경쟁사를 다시 열 가능성이 있는 이유와 해결책:
- **실거래 신뢰도 / 빠른 확인**: 호갱노노의 압도적인 실시간 조회 감각. -> **이집 해결**: 단지 상세 최상단에 핵심 실거래 요약과 변동 브리핑(텍스트) 즉시 노출.
- **입주물량/공급 파악**: 아실의 직관적인 입주물량 차트. -> **이집 해결**: 단지 상세 내에서 '해당 단지 반경 3km 이내 향후 3년 입주물량'을 이집점수와 엮어 해석된 문장으로 제공.
- **다중 단지 비교**: 아실의 여러 아파트 차트 겹치기. -> **이집 해결**: 단순 차트 겹치기를 넘어, 육각형 방사형 차트(Score 기반)와 필요 자금 기반의 "조건 매칭 비교" 제공.

## 10. Current E-jip Audit
- **홈 (/)**: 검색과 메뉴 나열 중심. 의사결정을 리드하지 않고 '원하는 걸 찾아보라'는 형태.
- **지도 (/map)**: 기능적이나 경쟁사 대비 오버레이 레이어가 분산되어 있음.
- **단지 상세 (/apt/[name])**: 정보는 많으나 병렬로 나열되어 있음. 브리핑과 Score V2가 있으나 더 돋보여야 함.
- **부동산도구 (/tools)**: 유용한 계산기들이 모여 있으나, 단지 상세와 분리되어 있어 "A 단지를 살 때 필요한 돈"을 계산하려면 맥락이 끊김 (Dead-end 존재).
- **통계 (/stats)**: 훌륭한 데이터를 가지고 있으나 BottomNav에 있을 만큼 매일 들어가는 메뉴인지 재고 필요.
- **마이 (/my)**: AUTH V1을 통해 잘 정돈됨. 향후 개인화의 훌륭한 기반.

## 11. E-jip Strengths (현재 이집의 강점)
- **E-jip Score V2 & 단지 브리핑**: 경쟁사가 하지 못하는 "데이터의 해석(Interpretation)".
- **개인화 기반 (AUTH/MY V1 완료)**: 관심목적(Preferences), 최근 본 단지 자동 동기화(Sync) 등 유저 상태 유지.
- **분양/재건축 통합**: 흩어져 있는 정비사업 데이터를 한 앱 내에 구조화.

## 12. E-jip Weaknesses (현재 이집의 약점)
1. **Decision-making 연결 부족**: 단지를 보고도 "계산"과 "비교"로 부드럽게 이어지지 않음.
2. **부동산 도구의 고립**: 계산기가 단지 데이터와 연동되지 않는 단절된 유틸리티로 존재.
3. **홈 화면의 수동성**: 유저가 직접 무엇을 할지 선택해야 하는 관문 역할에 그침.
4. **정보의 병렬 나열**: 단지 상세에서 1순위 정보(가격/점수)와 3순위 정보가 동일한 위계로 나열됨.
5. **비교 경험의 부재**: 아실처럼 단지 간 우위를 한눈에 보는 기능이 부족.
6. **모바일 텍스트 밀도**: 브리핑 등 훌륭한 텍스트가 모바일에서 읽기에 다소 길거나 빽빽할 수 있음.
7. **필터링의 복잡성**: AI 검색이 강력하나, 초보자가 즉각적으로 슬라이더를 당겨 찾는 직관적 필터가 부족.
8. **지역 통계와 단지의 괴리**: 단지와 통계 메뉴가 완전히 분리됨.
9. **행동 CTA의 부족**: "매물 보기", "계산하기" 등 다음 행동(Action) 버튼이 약함.
10. **시각적 계층(Hierarchy)**: 중요 숫자가 화면에서 충분히 강조되지 않음.

## 13. Real Estate Tools Strategy
**전제 검증**: 현재 부동산 도구가 고립되어 효용이 떨어진다는 판단은 **사실**입니다.
**전략 변경**: 
- 독립된 메뉴(`/tools`)로도 존재하되, **핵심은 단지 상세 페이지 내로의 이식(Embedding)**입니다.
- **흐름**: 단지 상세 진입 → 현재가 확인 → `[이 집을 사려면 얼마가 필요할까?]` 버튼 탭 → 현재 보고 있는 아파트의 시세가 자동 입력된 상태로 '대출/취득세/중개보수' 통합 계산기 바텀시트 전개.
- **효과**: 계산 도구가 유틸리티가 아닌 **의사결정의 핵심 무기**로 승격됨.

## 14. Ideal Decision Journey
이집만의 최적화된 사용자 여정:
1. **Home**: 개인화된 내 목적(MY-4에서 설정한 매수/투자 등)에 맞는 시장 요약 및 추천 단지 노출.
2. **Search/Map**: 1~2개 탭으로 내 예산/평형 필터 적용 후 지도에서 탐색.
3. **Detail (The Core)**: 
   - 10초: 이집점수, 단지브리핑(결론), 현재가.
   - 30초: 실거래 차트, 향후 입주물량/지역분위기 요약.
   - 2분: 생활/학군/교통 상세 지표 확인.
4. **Finance Action**: 단지 상세 내에서 즉시 `[내 자금으로 계산하기]` 실행.
5. **Compare**: 고민되는 다른 단지 추가 후 `[VS 비교하기]`로 다면 평가.
6. **Save**: 관심단지 추가.

## 15. Detail Page Ideal IA
단지 상세 페이지의 정보 계층(Hierarchy):
- **Tier 1 (진입 후 10초 이내)**: 
  - 단지명, 평형 선택, **단지 브리핑 (한 줄 요약)**, **E-jip Score V2 (방사형 차트)**, 최근 실거래가 및 호가 요약.
- **Tier 2 (스크롤 시 30초 이내)**: 
  - 실거래가/전세가 트렌드 차트, **[자금 계산기 CTA]**, 해당 지역 공급물량/시장강도 한 줄 코멘트.
- **Tier 3 (딥 다이브 2분 이내)**: 
  - 학군(초/중/고 맵핑), 대중교통 노선, 편의시설 분포, 재건축/분양 호재, 커뮤니티 리뷰.

## 16. HOME V2 Inputs

## 20. Do Not Copy (가져오지 말아야 할 경쟁사 UX)
1. 깨알 같은 글씨로 채워진 테이블 중심의 모바일 UI (아실).
2. 너무 많은 옵션으로 인해 진입 장벽이 높은 지도 필터 메뉴.
3. 데이터를 설명해주지 않고 사용자에게 해석을 강요하는 차트 위주의 배치.
4. 모든 부동산 도구를 한 페이지에 모아놓은 유틸리티형 폴더 구조.
5. 단지 상세 화면 상단 공간을 낭비하는 거대한 아파트 외관 사진.
6. 목적(매수 vs 전월세)과 상관없이 고정된 정보 배치.
7. 무분별하게 겹쳐진 지도 위의 혼란스러운 핀/레이어.
8. 편향된 호가 중심의 커뮤니티 게시판 메인 노출.
9. 복잡한 탭 구조(아파트 내부에서 실거래 탭, 호가 탭, 커뮤니티 탭 등 끝없는 탭 이동).
10. 맥락 없이 제공되는 거시 지표(M2 통화량 등 실질 결정과 거리가 먼 데이터).

## 21. Differentiators (이집이 반드시 가져야 할 차별화)
1. **Interpretation Engine** 
   - *WHY*: 초보자는 데이터를 봐도 모름. 
   - *HOW*: Score V2와 브리핑 텍스트를 최우선 배치. 
   - *PRIORITY*: P0
2. **Contextual Calculators** 
   - *WHY*: 계산은 독립적인 행위가 아님. 
   - *HOW*: 단지 상세에서 현재 시세가 주입된 계산기 팝업/바텀시트 제공. 
   - *PRIORITY*: P0
3. **Score-based Comparison** 
   - *WHY*: 표 비교는 모바일에서 끔찍함. 
   - *HOW*: 2개 단지 선택 시 방사형 차트와 강약점 요약 텍스트로 우위 판단. 
   - *PRIORITY*: P1
4. **Decision-led HOME** 
   - *WHY*: 사용자의 다음 행동을 유도해야 함. 
   - *HOW*: 찜한 단지 변동, 관심 지역 리포트를 피드 형태로 제공. 
   - *PRIORITY*: P1
5. **Unified Market & Micro Data** 
   - *WHY*: 지역 분석 따로, 단지 분석 따로 함. 
   - *HOW*: 단지 상세 스크롤 중 자연스럽게 해당 '구'의 입주물량/시장강도 노출. 
   - *PRIORITY*: P2
6. **Intent-driven UI** 
   - *WHY*: 실거주와 투자의 관점은 180도 다름. 
   - *HOW*: Preferences에 따라 단지 상세 정보의 정렬 순서(학군 vs 갭투자) 자동 스왑. 
   - *PRIORITY*: P2
7. **Cross-Domain Integration** 
   - *WHY*: 재건축/분양과 기존 아파트는 대체재 관계임. 
   - *HOW*: 아파트 상세 주변 추천에 인근 분양/재건축 단지를 점수로 묶어 추천. 
   - *PRIORITY*: P1

## 22. Moat 후보 (경쟁 해자)
- **단기 차별화**: Contextual Calculators (단지 연동형 자금 계산기), E-jip Score 방사형 비교.

## 25. One-Line Verdicts
- **호갱노노** = 직관적이고 커뮤니티가 강하지만, 단지 간 객관적 비교와 깊은 해석이 부재한 감정적 지도.
- **아실** = 데이터 밀도가 압도적이지만, 모바일에 부적합한 표 중심 UI로 초보자에게 불친절한 전문가용 대시보드.
- **부동산지인** = 거시적 흐름을 보기에 좋지만, 개인의 '내 집 마련' 의사결정에 직결되기 어려운 거시 지표 모음.
- **이집 현재** = 데이터와 인프라는 모두 갖추었으나, 메뉴가 파편화되어 사용자가 직접 정보를 조립해야 하는 도서관.
- **이집 V2 목표** = 데이터 수집부터 계산, 비교, 최종 판단까지 한 흐름에 끝내주는 '부동산 의사결정 내비게이션'.

## 26. Decision Principles (UI/UX V2 개발 원칙)
1. **해석 없는 데이터는 없다**: 숫자를 던질 때는 반드시 그 의미(좋은지/나쁜지)를 병기한다.
2. **계산은 그 자리에서**: 단지 정보와 자금 계산을 분리하지 않는다.
3. **가장 중요한 것은 10초 내로**: 점수와 브리핑은 첫 화면 스크롤 없이 보여야 한다.
4. **동일 정보 중복 노출 금지**: 다른 탭을 눌러도 똑같은 표가 반복되지 않게 한다.
5. **엄지손가락 법칙**: 핵심 비교/계산 버튼은 모바일 하단 플로팅 또는 접근하기 쉬운 위치에 둔다.
6. **표(Table) 최소화**: 모바일 가로 스크롤 표를 극력 배제하고 게이지/차트/카드 형태로 변환한다.
7. **맥락 유지**: A단지에서 B단지로 넘어갈 때 이전 상태나 비교 맥락을 유실하지 않게 한다.
8. **목적 기반 정렬**: 투자자와 실거주자의 정보 우선순위는 달라야 한다 (점진적 도입).
9. **거시와 미시의 융합**: 단지 데이터를 볼 때 해당 지역의 거시 지표를 자연스럽게 한 스푼 얹어준다.
10. **행동 유도(CTA)**: "잘 봤다"로 끝나지 않고 "비교하기", "저장하기", "계산하기"로 끝나야 한다.
