## 로고/심볼/이집이 역할 분리

| 자산 | 역할 | 노출 성격 |
|---|---|---|
| 로고(워드마크 `이집`) | 브랜드 정체성 표지판 — "여기가 이집이다"를 알림 | 상시, 정적, 작게 |
| 심볼(단독 마크) | compact branding — 공간이 좁은 곳(파비콘, 앱 아이콘, 로딩 스피너 중심)에서 로고를 대신함 | 상시/반복, 정적~미세 애니메이션 |
| 이집이(캐릭터) | 서비스 안내자 — "지금 무슨 일이 일어나고 있는지"를 사용자 대신 말해주는 역할(로딩/분석 대기/empty/온보딩) | **상태 기반**로만 등장, 상시 노출 아님 |

이 구분이 10번 "디자인 원칙"의 "화면마다 캐릭터를 다 띄우지 않기"를
구조적으로 지킨다 — 로고/심볼은 상시 자리에 고정, 이집이는 "지금
이집이 일하고 있다"는 특정 순간에만 등장.

## Brand Voice — 이집 언어 시스템

D안 설계 직후 사용자·ChatGPT가 추가로 확정한 UX copy 전략이다. 자산
(로고/심볼/캐릭터 일러스트)만으로 끝나는 브랜드가 아니라, **문구
자체가 브랜드를 반복 각인시키는 장치**가 되도록 한다.

### 핵심 개념

브랜드명 `이집`은 일상어 `이 집`(지시대명사 "이" + 명사 "집")과 발음이
자연스럽게 겹친다. 이 중의성을 억지 말장난이 아니라 **UX copy를 통한
브랜드 기억 장치**로 쓴다:

```text
이집 = 브랜드명
+
이 집 = 사용자가 지금 찾고 있는/보고 있는 실제 집
```

사용자가 검색·추천·최근 본 단지·커뮤니티 등을 이용하는 과정에서
자연스럽게 "이집"이라는 단어를 반복해서 마주치게 하는 것이 목표다 —
로고를 한 번 보여주는 것보다, 문장 속에서 여러 번 자연스럽게 스치게
하는 쪽이 각인 효과가 크다는 전제.

### 적용 원칙 — 적극 사용 영역 vs 절제 영역

**적극적으로 사용하기 좋은 영역**: 홈, 검색 시작/완료, 추천, AI
조건검색, 관심단지, 최근 본 단지, 비교, 커뮤니티, 글쓰기, loading,
empty state, onboarding, 이집 브리핑.

**절제해야 하는 영역**: 실거래 숫자, 시세, 대출, 세금, 정책, 법률,
중요한 데이터 오류, 시스템 장애. 이 영역은 **정확성·신뢰·정보 전달이
브랜드 언어유희보다 항상 우선한다** — 위 "현재 loading/empty/error
상태 구조" 조사에서 이미 확인한 "에러 문구는 캐릭터 톤을 배제하고
담백하게 유지" 결론과 정확히 같은 방향이다.

### UI Copy 3단계 체계

향후 UI 문구를 3개 타입으로 구분해서 쓴다.

**A. 정보형** — 정확하고 직접적인 문구. 사용처: 가격/거래/대출/정책/
데이터 설명.

```text
최근 실거래가를 확인하세요.
```

**B. 브랜드형** — `이집`과 `이 집`의 중의성을 자연스럽게 활용. 사용처:
탐색/검색/추천/커뮤니티/관심단지/비교.

```text
이집, 가격 흐름은 어땠을까요?
이집 어때?
찾던 이집, 여기 있어요.
어떤 이집을 찾고 계세요?
최근에 본 이집
마음에 둔 이집
어느 이집이 더 나을까요?
```

**C. 캐릭터형** — `이집이`가 서비스 안내자로 말하는 문구. 사용처:
loading/AI 분석/empty/준비 중/안내/onboarding. **정보형보다 더 자주
쓰지 않는다** — 위 "로고/심볼/이집이 역할 분리"의 "상태 기반으로만
등장" 원칙과 동일선상.

```text
이집이가 좋은 이집을 찾고 있어요.
이집이가 데이터를 정리하고 있어요.
이집이가 조건에 맞는 집을 찾는 중이에요.
```

### 커뮤니티 특화 활용

커뮤니티에서는 단지명 + `이집` 언어 시스템을 적극 검토한다.

```text
대신롯데캐슬, 이집 어때요?

대신롯데캐슬, 이집이 궁금하면?
실거주자에게 물어보세요.

이집에 대해 궁금한 점을 남겨보세요.

이집에서 살아본 이야기를 들려주세요.

이집, 실제로 어떤가요?
```

주의: 단지명을 실제 아파트명으로 동적 치환할 경우 문장이 부자연스러워
지지 않는지 STEP 57 적용 시 케이스별로 확인해야 한다(예: 단지명이
"이집"이라는 단어와 겹치는 발음/표기일 경우 등 예외 케이스). 브랜드
각인을 위해 커뮤니티 문구 전부에 억지로 "이집"을 넣지 않는다.

### Search / Recommendation 활용

```text
어떤 이집을 찾고 계세요?

조건에 맞는 이집을 찾고 있어요.

이 조건이면, 이런 이집은 어때요?

찾던 이집, 여기 있어요.
```

검색 결과의 정확성을 흐리는 카피는 금지 — `ai-search-client.tsx`의
조건검색처럼 실제 매물 정보를 보여주는 화면에서는 브랜드형 문구가
헤드라인/안내 문구에만 쓰이고, 결과 데이터 자체(가격/평형/거래일 등)
표기 방식에는 영향을 주지 않는다.

### Recent / Favorite 활용

```text
최근에 본 이집

마음에 둔 이집

다시 보고 싶은 이집
```

단, 홈의 "최근 본 단지"처럼 이미 정착된 메뉴/기능명이 있다면 무조건
바꾸지 않는다 — STEP 57 실제 적용 시 UX 적합성을 보고 개별 판단한다
(이미 "남은 결정사항" 1번에 같은 취지로 기록돼 있음).

### Loading 활용

`FullPageLoader`가 이미 존재하므로(위 "현재 브랜드 노출 위치" 참고)
D안 자산 적용 시 이 컴포넌트의 메시지 후보로 가장 먼저 활용한다.

```text
이집이가 단지를 살펴보고 있어요.

이집이가 정보를 찾고 있어요.

이집이가 데이터를 정리하고 있어요.

조건에 맞는 이집을 찾고 있어요.
```

매번 랜덤 문구를 과도하게 보여주지 않는다 — 상태(어떤 화면의 어떤
로딩인지)에 맞는 고정 문구를 사용한다(위 "상태별 문구 초안" 표와
같은 방식, Brand Voice의 B/C 유형 구분을 그 표에도 그대로 적용).

### Empty 활용

```text
아직 본 이집이 없어요.
관심 가는 단지를 둘러보세요.

찾는 이집이 아직 없어요.
검색 조건을 조금 바꿔보세요.
```

단, 어색한 언어유희가 되는 경우는 일반 정보형(A) 문구로 대체한다 —
"6-4. Empty State"에서 이미 정한 "이집이는 왜 비어있는지를 말해줄 뿐
정보 자체를 대신하지 않는다"는 원칙과 함께 적용한다.

### 사용 금지 원칙

- 모든 제목에 `이집` 강제 삽입
- 가격/대출/법률 문구에 장난스러운 표현
- 실제 단지와 브랜드를 혼동하게 만드는 표현
- `이집이`와 `이집`을 한 문장에 과도하게 반복
- 유아용 서비스처럼 보이는 과한 캐릭터 말투
- 느낌표 남발
- 이모지 남발

이 항목들은 위 "디자인 원칙"(10번, "신뢰감 > 귀여움", "실제 정보보다
캐릭터가 더 눈에 띄면 안 됨")을 문구 차원에서 구체화한 것이다.

## 현재 loading/empty/error 상태 구조 (전수조사 결과)

전역 패턴이 이미 하나로 수렴돼 있다 — **의미 있는 문장 하나만 보여주고
과장하지 않는다**(약 20개 파일에서 동일 톤 확인, 예:
`ApartmentQuickSearch.tsx`, `CommunityPreview.tsx`, `BusAccessCard.tsx`,
`map/page.tsx`, `presales-client.tsx`, `stats/[type]/type-client.tsx`
등). 유형별로 정리:

1. **Global loading**(페이지 최초 진입): `FullPageLoader` — 이미
   브랜드 적용됨(위 참고). 3곳에서만 쓰이고, 다른 페이지(홈/통계/
   커뮤니티/분양 목록 등)는 각자 로컬 로딩 문구만 쓴다 — 통일 안 됨.
2. **Section loading**(페이지 안 특정 영역만): 대부분 회색 스켈레톤
   바(`skeletonBar`, `ChartSkeleton`) 또는 반투명 오버레이 + 평문
   텍스트(예: `apt-client.tsx:501` "데이터를 수집 중입니다..."). 브랜드
   요소 없음.
3. **AI/분석 대기**: `ai-search-client.tsx`가 유일하게 브랜드
   로딩(`FullPageLoader message="AI가 데이터를 분석하고 있어요..."`)을
   쓰는 실질적 "분석 대기" 화면.
4. **Empty state**: 전부 텍스트 한 줄, 아이콘/캐릭터 없음. 톤은
   일관되게 정직하고 담백함(예: "아직 이 단지 관련 글이 없습니다.
   첫 글을 남겨보세요!" — CTA 포함, "표시할 데이터가 없습니다." — CTA
   없음). 홈의 "최근 본 단지" empty는 STEP 52에서 **섹션 자체를
   숨기는** 방식을 택해 문구조차 없다.
5. **Error/retry**: 대부분 문구만 있고 재시도 버튼은 일부만
   (`map/page.tsx:651`, `nearby-market-section.tsx:239`). 톤은
   차분하고 신뢰감 있음, 이모지 남용 없음(`⚠️` 정도만 가끔).
6. **"준비 중"(미구현) 상태**: `redevelopment-client.tsx`,
   `map/page.tsx`(오피스텔/생숙/재개발/경매), `FloorPlanPanel.tsx`,
   `SchoolDistrictPanel.tsx` 등 — 이미 CLAUDE.md 13번 원칙("미구현을
   오류로 단정하지 않는다")대로 별도 카테고리로 정직하게 분리돼 있다.
   이 상태는 "이집이가 열심히 만들고 있어요" 같은 캐릭터 톤을 입히기
   좋은 후보다(신뢰를 깨지 않으면서 친근함을 더할 수 있는 지점).

**결론**: 브랜드 시스템을 얹을 구조적 기반(FullPageLoader, 일관된 empty
문구 톤, 이미 분리된 준비중 상태)은 이미 갖춰져 있다. 새로 만들어야
하는 것은 (1) 이 조각들을 하나의 브랜드 언어로 통일하는 것과 (2)
이집이 캐릭터를 얹을 자리를 정하는 것이지, 로딩/empty 처리 로직 자체를
새로 설계하는 게 아니다.

## 로딩 상태 전략

### 6-1. Global Loading

기존 `FullPageLoader`를 브랜드 시스템의 표준 global loading으로
승격한다(신규 컴포넌트를 만들지 않는다 — 이미 3곳에서 검증된
컴포넌트를 확장하는 것이 STEP 53에서 확립한 "재사용 우선" 원칙과
일치). 방향:

- 현재: 텍스트 "🏢 이집" pulse + spinner
- 목표(STEP 57 적용안): 텍스트를 심볼(또는 심볼+워드마크 조합) 이미지로
  교체. 이집이 일러스트는 **global loading에는 넣지 않는다** — 여기는
  "이집이 일한다"가 아니라 "이집이 로드된다"는 순간이라 로고/심볼이
  더 맞는다(캐릭터는 6-2/6-3에서 등장).
- FullPageLoader가 쓰이지 않는 다른 초기 진입 지점(홈/통계/커뮤니티/
  분양 목록)에도 동일 컴포넌트를 적용할지는 각 페이지 로딩 패턴이
  달라(SWR/직접 fetch 등) STEP 57에서 페이지별로 개별 판단.

### 6-2. Section Loading

예: 상세 실거래 로딩(스켈레톤), 교통정보 로딩, 커뮤니티 정보 로딩,
분양 정보 로딩.

방향: 기존 회색 스켈레톤 바를 걷어내지 않는다(레이아웃 시프트 방지
목적이 크고 이미 잘 작동함). 대신 스켈레톤과 **별개로** 작은 심볼
아이콘 + 1줄 메시지를 필요한 곳에만 보조적으로 추가하는 방식을
제안한다("skeleton과 함께 소형 브랜드 메시지" — 사용자 6-2 요청 반영).
예: `apt-client.tsx:501`의 "데이터를 수집 중입니다..." 오버레이에
작은 이집이 아이콘 추가.

### 6-3. AI/분석 대기

가장 이집이가 자연스럽게 들어갈 자리. 현재 `ai-search-client.tsx`의
`FullPageLoader`가 이미 이 역할의 뼈대다 — 메시지를 캐릭터 톤으로
교체하고, 심볼 대신 이집이 일러스트(돋보기/차트 포즈)로 바꾸는 것을
STEP 57의 최우선 후보로 제안한다.

### 6-4. Empty State

현재 전부 텍스트 한 줄 + 종종 CTA. 이집이 기본 포즈 + 짧은 문장 +
CTA 조합으로 업그레이드할 후보 지점(우선순위 순):

1. `ApartmentQuickSearch.tsx`/`HomeApartmentSearch.tsx`의 "검색 결과가
   없습니다" — 검색 실패는 사용자가 자주 마주치는 지점이라 우선순위
   높음.
2. `ai-search-client.tsx`의 조건검색 결과 없음 emptyBox.
3. 홈 최근 본 단지 empty(현재 숨김 방식 — 노출 방식으로 바꿀지는
   별도 판단).
4. 커뮤니티/분양 목록 empty.

### 6-5. Error / Retry

10번 원칙대로 여기는 **캐릭터를 자제**한다. 신뢰감이 귀여움보다
우선이라는 원칙을 코드 문구 톤에서도 이미 확인했다(현재 에러 문구는
전부 담백하고 침착함, 과장 없음) — 이 기존 톤을 그대로 유지하고,
브랜드는 로고 정도의 최소 수준으로만(예: 에러 박스 안에 작은 심볼
아이콘 정도, 이집이 캐릭터는 넣지 않음).

## Empty 상태 전략

(6-4와 통합 설계, 위 참고) 핵심 원칙: 이집이는 "왜 비어있는지"를
말해주는 안내자 역할만 하고, 정보 자체를 대신하지 않는다 — 데이터
없음을 캐릭터로 가리거나 과장하지 않는다(CLAUDE.md 4번/13번 원칙과
직결).

## Error 상태 전략

(6-5 참고) 신뢰감 우선. 캐릭터 최소화, 재시도 버튼은 있는 곳(map,
nearby-market)의 스타일을 표준화해 없는 곳(예: 커뮤니티, 학교 정보)

## AI/분석 대기 전략

(6-3 참고) 최우선 적용 후보.
