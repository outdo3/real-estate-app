### 독립 교차검증 — 세대당 주차 비율

세대수를 주거 합계로 바꾸면 세대당 주차가 **비현실적 → 현실적**으로 일제히 수렴한다:

| 단지 | 현재 화면 | 합계 기준 |
|---|---|---|
| 엘지(좌동) | 48세대 / 1,984대 = **세대당 41.33대** | 1,848세대 → **1.07대** |
| 벽산2 | 40세대 / 1,152대 = **28.80대** | 1,070세대 → **1.08대** |
| 두산1차 | 80세대 / 1,477대 = **18.46대** | 1,422세대 → **1.04대** |
| 대림 | 104세대 / 1,541대 = **14.82대** | 1,424세대 → **1.08대** |
| 경동 | 72세대 / 962대 = **13.36대** | 892세대 → **1.08대** |

전부 **1.02~1.15대**로 떨어진다. 이것은 세 가지를 동시에 뒷받침한다: ① 저장 세대수가 틀렸다 ② **저장 주차는 옳았다**(단지 총량) ③ 주거 합계가 맞는 세대수다.

## 4. 주차 정책 — 자동 규칙 없음

214건의 주차 패턴:

| 패턴 | 건 | 뜻 |
|---|---|---|
| SINGLE | 85 | 레코드 1개 |
| **SAME_REPEATED_TOTAL** | **79** | 0 아닌 값이 전부 동일 = 단지 총량 반복 → **합산 금지** |

**단일 자동 규칙이 없다.** 그리고 중요한 사실: SAME_REPEATED_TOTAL 79건 중 **75건은 저장값이 이미 그 반복 총량과 일치**한다 — 주차 필드는 애초에 대체로 망가지지 않았다.

**결론: 주차는 자동 정정 대상에서 제외한다.** 값이 틀린 것이 아니라, 틀린 세대수와 짝지어져 파생값(세대당 주차)이 틀렸을 뿐이다.

## 11. 상세 페이지 데이터 우선순위 (실측 증명)

```
tier1  prisma.apartment 캐시 (byJibun)   — parking·FAR·BCR·승인일이 전부 있을 때만 채택
  ↓ 비어 있으면
tier2  apartment_masters (lawdCd+dong+jibun)  — 빈 필드만 보충
  ↓ 그래도 비어 있으면
tier3  live 건축물대장                     — 빈 필드만 보충 + prisma.apartment에 upsert
```

**`26350-15`가 수정 배포 후에도 90/743을 보이는 경로 증명:**

1. tier1 — 이 지번에 캐시 row **없음** → null
2. tier2 — `apartment_masters` 26350-15의 `total_households=90`, `parking_count=743` **채택** ← 여기가 출처
3. tier3 — FAR/BCR이 여전히 비어 `isFullyPopulated=false`라 live를 부르지만, 고친 helper가 14건 지번이라 **null 반환** → 아무것도 더해지지 않음
4. `사용승인일 1986년`은 대장이 아니라 **네이버 스크랩 fallback**(`naverApprovalYear`) — master의 `use_approval_date`는 null이다

즉 **런타임 수정은 정상 동작했고**(live가 틀린 값을 더 이상 만들지 않는다), 화면 값은 **이미 저장된 master 값**이다. 코드 수정으로는 고쳐지지 않는다.
