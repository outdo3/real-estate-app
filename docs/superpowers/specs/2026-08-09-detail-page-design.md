# 단지 상세페이지 개선 — 설계 문서

날짜: 2026-08-09

## 배경

"프로젝트 명칭 변경 및 UX/성능 최적화 종합 작업" 요청의 3번째 하위 프로젝트. 대상 파일은
`src/app/apt/[name]/apt-client.tsx`. 요구사항 5가지:

1. 공급면적(공급평형)/전용면적 함께 표기
2. 주차대수(세대당 포함) 표시 복구
3. 하단 스크롤 섹션(학군/교통/편의시설/단지상세) 데이터 불일치 수정
4. 실거래 내역을 유형 아래 한 줄 정렬 + 15개씩 페이징 + [더보기]
5. 로그인 버튼을 우측 상단으로 이동

## 진단

- **공급면적**: MOLIT 실거래 API는 전용면적(`excluUseAr`)만 제공한다. 공급면적 데이터 소스가 코드베이스
  어디에도 없다. 현재 UI는 전용면적을 3.3058로 나눈 값을 그냥 "평"이라고 표시하고 있어, 사용자가 흔히
  아는 "공급평형"(예: 84㎡→34평형)과 값이 달라 혼동을 준다.
- **주차대수**: `src/app/api/apt/[name]/info/route.ts`에 세대당 계산 로직(K-APT 건축물대장 조회 분기)이
  이미 존재하지만, 네이버 스크래핑이 먼저 `총주차대수`를 채우면 `if (!info['총주차대수'])` 조건에 막혀
  세대당 계산 분기가 스킵되는 우선순위 버그가 원인이다.
- **하단 4개 패널**: `apt-client.tsx` 667~690행이 지역과 무관하게 완전히 하드코딩된 텍스트다
  (송도초등학교, 자갈치역, 고신대학교복음병원, 용적률 868% 등 — 어느 단지를 보든 항상 동일).
- **로그인 버튼 위치**: `Header.module.css`의 `.nav`는 `searchSlot`/`pageTitle` 중 하나가 있어야만
  `flex:1` 요소가 생겨 우측 메뉴/로그인 버튼을 오른쪽 끝으로 밀어낸다. 단지 상세페이지는 `<Header />`를
  두 prop 없이 호출하므로 로그인 버튼이 우측 끝이 아니라 메뉴 바로 옆에 붙는 CSS 버그다.
- **실거래 내역 표**: 페이징 없이 `filteredTrades` 전체를 4컬럼 `<table>`로 렌더링한다.

## 결정 사항 (사용자 확인 완료)

1. 공급면적은 국민평형 매핑표 + 공식 폴백으로 근사 표기(정확한 API 신규 연동은 이번 범위 제외).
2. 하단 4개 패널 모두 실데이터로 교체(학군/교통/편의시설은 카카오 장소검색, 단지상세는 건축물대장 API).
3. 실거래 내역은 카드형 리스트로 전환.
4. 이번 작업도 별도 브랜치/워크트리 없이 `main`에서 바로 진행.

## 설계

### A. 면적 표기 헬퍼 — `src/lib/area-utils.ts` (신규)

```ts
export function getAreaInfo(exclusiveM2: number): {
  exclusivePyung: number;
  supplyPyung: number;
  label: string; // "전용 84.99㎡(25.7평) · 공급 약 34평형"
}
```

- 전용 평형: `exclusiveM2 / 3.3058` (기존과 동일한 계산, 반올림)
- 공급 평형(근사): 자주 나오는 전용면적 구간(39.6/49.5/59.4/72.6/84.9/101.9/114.9/134.9㎡ 등)은
  국민평형 매핑표를 우선 사용. 표에 없는 값은 `exclusiveM2 / 0.77`(아파트 평균 전용률 근사치) 공식으로
  계산한 뒤 반올림.
- `label`은 항상 "약"을 붙여 근사치임을 명시.
- 적용 위치: 평형 필터 버튼, 최근 실거래가 상단 정보, 타임라인 아이템, 하단 실거래 카드 리스트. 기존에
  각 위치마다 따로 있던 `Math.round(parseFloat(area) / 3.3058)` 계산을 전부 이 헬퍼 호출로 교체한다.

### B. 주차대수 우선순위 수정 + 단지상세 실데이터 — `src/app/api/apt/[name]/info/route.ts`

- 기존 `if (!info['총주차대수'] && API_KEY && lawdCd && dong)` 게이트를 제거하고,
  `API_KEY && lawdCd && dong`이면 K-APT 건축물대장 조회를 항상 실행한다.
- K-APT 응답(`target`)에서 기존에 쓰던 `totPkngCnt` 외에 `vlRat`(용적률), `bcRat`(건폐율),
  `mainPurpsCdNm`(주용도)도 함께 `info`에 채운다.
- K-APT 조회가 성공하면 그 결과(세대당 주차 포함)로 네이버 스크래핑 값을 덮어쓰고, K-APT가 실패하거나
  값이 없을 때만 네이버 값을 폴백으로 유지한다.
- "난방 방식"은 신뢰할 수 있는 데이터 소스가 없으므로 표시 항목에서 제거한다(가짜 데이터를 유지하는
  대신 항목 자체를 뺀다).

### C. 하단 4개 패널 실데이터 연동 — `apt-client.tsx` + `KakaoPlaces.tsx`

- `KakaoPlaces`(현재 모달 전용, `category: 'SC4' | 'SW8'` 단일값)를 다음과 같이 확장:
  - `categories: string[]` 배열을 받아 카테고리별로 병렬 `categorySearch` 실행 후 거리순으로 병합
  - `limit` prop 추가(기본 5, 패널 임베드 시 2~3으로 축소)
  - 기존 모달 호출부(`openModal('학군')`, `openModal('교통')`)는 `categories={['SC4']}` /
    `categories={['SW8']}`로 마이그레이션(단일 카테고리는 배열의 특수 케이스일 뿐이므로 인터페이스를
    분기하지 않고 하나로 통일)
- **학군/교통 패널**: 각각 `<KakaoPlaces address={primaryAddress} categories={['SC4']} limit={2} />` /
  `categories={['SW8']}`로 실제 최근접 결과 표시
- **편의시설 패널**: `categories={['HP8', 'MT1']}`(병원+대형마트) 병합 후 상위 3개
- **단지상세 패널**: B에서 확보한 `aptInfo['용적률']`/`aptInfo['건폐율']`/`aptInfo['주용도']`를 표시,
  값이 없으면 "정보 없음"
- 모든 패널은 데이터 조회 실패/빈 결과 시 기존 `KakaoPlaces`의 에러 문구를 그대로 노출(별도 처리 불필요)

### D. 실거래 내역 카드형 리스트 + 페이징 — `apt-client.tsx`

- 기존 692~718행의 `<table>`을 제거하고 카드 리스트로 교체:
  ```
  [매매]  2026.07.15
  전용 84.99㎡(25.7평) · 공급 약 34평형 · 12.5억 · 15층
  ```
- `visibleCount` state(초기값 15) 추가, `filteredTrades.slice(0, visibleCount)`만 렌더링
- 하단에 `filteredTrades.length > visibleCount`일 때만 `[더보기]` 버튼 노출, 클릭 시 `visibleCount + 15`
- `selectedArea`/`tradeTypeFilter`/`periodFilter`/`onlySales` 중 하나라도 바뀌면 `visibleCount`를 15로
  리셋(기존 필터링 `useEffect`/파생 로직에 리셋 추가)

### E. 로그인 버튼 우측 고정 — `Header.module.css`

- `.menuList`에 `margin-left: auto` 추가. `searchSlot`/`pageTitle`이 있는 페이지는 이미 그쪽이
  `flex:1`로 공간을 채우므로 시각적 변화 없음. 없는 페이지(단지 상세 등)에서는 메뉴+로그인 버튼 그룹
  전체가 우측 끝에 붙는다.
- 모바일(`max-width: 900px`)은 `.menuList`가 `position: fixed` 하단 탭바로 전환되므로 이 변경의 영향을
  받지 않는다(데스크톱 전용 수정).

## 검증 계획

- `npm run build` 클린 빌드
- 로컬 브라우저에서 실제 단지 상세페이지 진입해 5개 항목 육안 확인:
  - 평형 필터/실거래가 정보/타임라인/카드 리스트에 전용·공급 평형이 함께 표기되는지
  - 단지정보 모달·상단 태그에 "세대당 X대"가 뜨는지
  - 학군/교통/편의시설/단지상세 4개 패널이 실제 지역에 맞는 데이터로 뜨는지(다른 지역 단지 2곳 비교)
  - 실거래 내역이 15개 단위로 페이징되고 [더보기]가 정상 동작하는지, 필터 변경 시 15개로 리셋되는지
  - 데스크톱 폭에서 로그인 버튼이 우측 상단 끝에 붙는지(단지 상세페이지 기준, 다른 페이지 회귀 없는지도 확인)
- 거래 내역이 없는 단지(신규 분양 등 엣지케이스)로 한 번 더 확인해 각 패널의 "정보 없음"/에러 처리가
  깨지지 않는지 점검
