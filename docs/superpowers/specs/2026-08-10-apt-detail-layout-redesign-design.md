# 단지 상세페이지 UI/UX 및 레이아웃 구조 개편 — 설계 문서 (A. 레이아웃/UI 개편)

날짜: 2026-08-10

## 배경

단지 상세페이지(`src/app/apt/[name]/apt-client.tsx`, 757줄)의 UI/UX·레이아웃 구조 개편 요청.
큰 작업이라 2개로 분리:

- **A. 레이아웃/UI 개편** (이 문서) — 평형 선택 UI, 3구역 재배치, 핵심 투자지표, 단지 브리핑,
  카카오톡 공유, 모바일 반응형. 전부 `apt-client.tsx`와 그 하위 컴포넌트 중심.
- **B. 커뮤니티 단지 태그 연동** (별도 진행) — `Post` 모델에 `aptName` 필드를 추가하는 실제
  DB 마이그레이션이 필요해 리스크 성격이 달라 분리.

## 사용자 확인 완료 사항

1. **스타일링**: Tailwind 신규 도입 없이 기존 CSS Modules(`detail.module.css`) 방식 유지.
2. **공시가/보유세**: 이번 범위에서 완전히 제외. 1구역 핵심 투자 지표는 **전세가율·갭 금액만**
   (둘 다 실거래가 기반, 임의 추정치 아님).
3. **단지 브리핑/현장 팁**: 실제 LLM 호출이 아니라, 이미 보유한 데이터(시세 추이, 세대수,
   준공연도, 거래 빈도 등)를 조합한 규칙 기반 템플릿 텍스트.
4. **실거주민 후기/커뮤니티**: (B에서 실제 DB 필터링 구현 예정) 이번 A에서는 커뮤니티로
   연결되는 CTA만 배치, B 완료 전까지는 필터링 없는 일반 커뮤니티 링크로 동작.

## 진단 (현재 구조)

- 평형 필터: 전체 평형이 버튼으로 전부 나열됨(줄바꿈 다발, 세로 공간 많이 차지) — 요구사항 1의
  "카드/박스 형태로 나열되어 스크롤 과도" 지적과 일치.
- 실거래 내역이 **두 군데 중복**으로 존재: `contentGrid` 우측의 "최근 실거래 타임라인"(기간
  필터만 적용, 페이징 없음)과 하단의 "전체 실거래 내역"(카드 리스트, 15개 페이징). 둘 다 같은
  `filteredTrades`를 다른 형태로 보여줄 뿐이라 중복 — 이번 개편에서 하나로 합친다.
- `tradeTypeFilter`(매매/전월세)는 `/api/apt/[name]?type=apt|rent`로 **한 번에 한 타입만**
  조회하므로, `trades` state에는 매매 또는 전월세 중 하나만 들어있다. "갭 금액"(매매가-전세가)
  계산에는 두 타입이 동시에 필요하므로, 기존 `trades`와는 별도로 **투자지표 전용 fetch**가
  필요하다(최근 6개월 매매+전월세를 병렬로 한 번만 조회, 필터 토글과 무관하게 고정).
- 학군/교통 정보는 이미 3구역 격 "단지 입지 분석" 4패널에 실데이터로 들어있는데, 상단 퀵버튼에도
  "학군"/"교통" 모달이 중복으로 있음 — 개편하면서 중복 제거.
- 카카오 관련 기능은 현재 지도(Maps) SDK만 로드되어 있고, 카카오톡 "공유하기"는 별도의 카카오
  JavaScript SDK(`developers.kakao.com/sdk/js/kakao.js` + `Kakao.init()`)가 필요해 신규
  연동이다.

## 설계

### 1. 평형 선택 영역 — 칩 + 드롭다운

- 신규 컴포넌트 `src/components/AreaSelector.tsx`: 상위에서 `trades`, `selectedArea`,
  `onSelect`를 props로 받는 순수 UI 컴포넌트.
- **주요 평형 칩**(상단, 가로 스크롤 가능): "전체" + 거래건수 기준 상위 3~4개 평형을
  `getAreaInfo()` 라벨로 표시.
- **[▼ 전체 평형] 버튼**: 클릭 시 레이어(팝오버)로 전체 평형 목록(면적 오름차순, 기존 방식과
  동일)을 펼쳐서 선택 가능. 칩에 없는 평형을 고르면 그 평형이 칩 자리에 함께 노출(현재 선택된
  평형은 항상 보이도록).
- 선택값은 기존과 동일하게 최상위 `selectedArea` state로 관리 — 차트(1구역)와 실거래
  내역(2구역)이 자동으로 같은 값을 공유해 동적으로 연동된다(별도 배선 불필요, 기존 구조
  재사용).

### 2. 섹션 재배치

**1구역 (상단, 조밀하게)**
- 브레드크럼 + 단지명 + 태그(세대수/준공/주차) — 기존 유지.
- 실거래가 시세 차트(매매/전월세 · 기간 토글 유지) — 기존 유지, 단 우측 타임라인 패널 제거로
  전체 폭 사용.
- **핵심 투자 지표 카드(신규)**: 전세가율, 갭 금액 2개 지표. 최근 6개월 매매+전월세를 같은
  평형 기준으로 매칭해 계산(매칭 실패 시 "데이터 부족"으로 표시, 임의 추정 안 함).
- 퀵버튼: 지도/로드뷰/단지정보/대출한도/건축물대장 (학군·교통은 3구역과 중복이라 제거).

**2구역 (중단)**
- 평형 선택(칩+드롭다운, 위 1항).
- 평형별 실거래 내역 — 기존 "최근 실거래 타임라인" + "전체 실거래 내역" 카드리스트를
  **하나로 통합**(카드리스트+15개 페이징 방식 유지, sub-project 3에서 만든 패턴 그대로).
- **단지 브리핑/현장 팁 카드(신규)**: 규칙 기반 템플릿 텍스트. 아래 3항 참고.

**3구역 (하단)**
- 학군/교통/편의시설/단지상세 4패널 — 기존 유지(sub-project 3에서 실데이터화 완료).
- **실거주민 후기/커뮤니티 카드(신규, A 범위)**: "이 단지 이야기가 궁금하다면?" CTA +
  `/community`로 이동하는 버튼(쿼리파라미터로 단지명 전달, 예: `/community?aptName=...`).
  B가 완료되기 전까지는 커뮤니티 목록이 필터링되지 않고 전체 글이 보임 — B에서 실제 필터링
  붙임.
- **카카오톡 공유 버튼(신규)**: 아래 4항 참고.

### 3. 단지 브리핑/현장 팁 — 데이터 기반 템플릿

`src/lib/apt-brief.ts` 신규: `buildAptBrief({ trades, aptInfo, aptName }): string[]` 형태로
2~4개의 문장(불릿)을 반환.

- 최근 시세 추이: `filteredTrades`(매매, 기간 무관 전체) 중 가장 오래된 거래와 최신 거래의
  평당가를 비교해 "최근 시세는 약 N% {상승/하락/보합} 추세입니다" 생성.
- 단지 규모/연식: `aptInfo['세대수']`/준공연도로 "총 OOO세대 규모의 {신축(5년 이하)/준신축
  (10년 이하)/구축} 단지입니다".
- 거래 활발도: 최근 3개월 거래 건수로 "최근 3개월간 N건 거래되어 {거래가 활발한/거래가 드문}
  편입니다".
- 데이터가 부족한 항목(예: 거래 이력 자체가 없음)은 해당 문장을 생성하지 않고 건너뜀(빈
  카드가 되지 않도록 최소 1개 문장은 항상 나오게 폴백 문구 준비).

### 4. 카카오톡 공유 버튼

- 카카오 JavaScript SDK(`https://developers.kakao.com/sdk/js/kakao.js`)를 신규 로드하고
  `Kakao.init(NEXT_PUBLIC_KAKAO_MAP_API_KEY)`로 초기화(기존 지도 SDK와는 별개 스크립트,
  같은 JS 키 재사용).
- 클릭 시 `Kakao.Share.sendDefault()`로 단지명·최근 실거래가·현재 페이지 URL을 담은 기본
  템플릿 공유.
- **주의사항(코드만으로 해결 불가)**: 카카오 디벨로퍼스 콘솔에서 해당 앱에 "카카오톡 공유"
  제품이 활성화되어 있어야 실제로 동작한다. 활성화되어 있지 않으면 카카오 SDK가 에러를
  반환하는데, 이 경우 사용자에게 "공유 기능을 사용할 수 없습니다"라는 안내와 함께 URL
  복사(클립보드) 폴백을 제공한다(완전히 막히지 않도록).

### 5. 모바일 반응형 점검

- `detail.module.css`에 이미 `@media (max-width: 900px)` 관련 규칙 일부 존재 — 새로 추가되는
  칩/드롭다운/투자지표 카드/브리핑 카드/공유 버튼에 375~430px 기준 패딩·폰트 축소, 줄바꿈
  규칙(`word-break`, `overflow-wrap`)을 일관되게 적용.
- 기존 인라인 style 위주 코드베이스 컨벤션을 유지하되, 모바일 전용 규칙이 필요한 부분만
  `detail.module.css`의 미디어쿼리로 분리(인라인 style은 미디어쿼리를 못 쓰므로).

## 검증 계획

- `npm run build` + `npx tsc --noEmit` 클린
- 실제 거래 이력이 많은 단지로 브라우저 확인: 평형 칩/드롭다운이 정상 동작하고 선택 시 차트와
  실거래 내역이 함께 바뀌는지, 투자지표(전세가율/갭)가 실제 값으로 뜨는지, 단지 브리핑
  문장이 자연스럽게 나오는지, 카카오톡 공유 버튼(콘솔 미설정 시 폴백 포함), 커뮤니티 CTA
  링크 확인.
- 거래 이력이 거의 없는 단지로도 확인해 투자지표/브리핑이 "데이터 부족" 등으로 깨지지 않고
  안내되는지 확인.
- 모바일 폭(375~430px, 라이브 DOM 기반 시뮬레이션 — 이전 세션에서 `resize_window`가 이
  환경에서 뷰포트를 실제로 좁히지 못하는 한계가 확인됨)에서 텍스트 줄바꿈/패딩 확인.
